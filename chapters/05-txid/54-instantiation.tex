\section{Instantiation}\label{sec:txid-instantiation}

We give two instantiations of the generic construction of $\ID$. The first uses
algebraic pseudorandom functions and tailored Sigma protocols, and needs no
trusted setup. The second builds both pseudorandom functions from the MiMC
block cipher and proves the two pseudorandom function relations with a
general-purpose zk-SNARK. Both follow \Cref{prot:txid-generic} step by step,
and \Cref{sec:txid-evaluation} compares the two.

\subsection{Instantiating $\ID$ with algebraic PRFs}\label{sec:txid-alg-instantiation}

Three of the four relations of the construction involve pairing equations,
and proving statements about pairings is expensive. So this instantiation is
more involved than the construction. The derivations of
\Cref{sec:txid-construction}, from the tracing key to epoch keys and from epoch
keys to tags, need every step to be one way. It must be hard to go back from an
epoch key to the tracing key, and from a tag to the epoch key. Every step must
also be provable with a Sigma protocol, so its inputs and outputs must be group
or field elements related by equations of discrete logarithms. A hash function
is one way, but has no such structure. One-way functions alone are not enough
either, since tags and epoch keys must also look random, so both steps are
algebraic pseudorandom functions. Pairing equations are not equations of
discrete logarithms, so we rewrite the relations and blind their values, and the
prover proves equations of discrete logarithms while the verifier checks the
pairings. The hash-based instantiation drops the algebraic structure and pays
with a general-purpose proof system.

The setup is transparent. We derive all group generators by hashing to the
group from a public seed, so no party, including the registration authority,
knows a discrete logarithm relation among them.

\subsubsection{The epoch PRF}\label{sec:txid-fe}

A user's tracing key is a pair of field elements $\utk = (\utk', \utk'')$. The
first component keys the epoch PRF, and the second keys the tag PRF below. The user draws both once at registration, and the
registration authority certifies them together in the same credential.

The epoch key must be an element of $\group{1}$, since the tag PRF pairs it with
an element of $\group{2}$, and its derivation must be provable with a Sigma
protocol. A hash of the epoch raised to a secret exponent is the simplest
pseudorandom function with both properties. For a hash function $\HE$ into
$\group{1}$, the epoch PRF raises the hash of the epoch to the first component
of the tracing key:
%
\begin{equation*}
  \FE(\utk, \epoch) = \HE(\epoch)^{\utk'}.
\end{equation*}
%
The public tracing key $\PTK$ contains a Pedersen commitment $T$ to the pair,
and the vector of group elements that tag evaluation needs, for generators
$\gen_2, \gen_3$ of $\group{1}$ and $\ggen_D$ of $\group{2}$:
%
\begin{equation*}
  T = \gen_2^{\utk'}\cdot\gen_3^{\utk''}, \qquad W_\gamma =
\ggen_D^{1/(\utk''+\gamma)} \ \text{ for } \gamma \in [0,\Max).
\end{equation*}
%
These elements do not change with the epoch, so, as in
\Cref{sec:txid-construction}, they are part of the public tracing key, which is
already sent in the grant message. The registration authority signs only $T$ and the public signing key,
so the elements $\{W_\gamma\}$ are not certified. The user proves them well
formed against the certified $T$ at the first grant to each auditor, in the
epoch key proof.

\begin{lemma}\label{lem:txid-fe-prf}
  %
  Under the DDH assumption in $\group{1}$ and modelling
$\HE$ as a random oracle, $\FE$ is a secure pseudorandom function, and remains
so against a distinguisher given the whole of $\PTK$.
%
\end{lemma}

\subsubsection{The tag PRF}\label{sec:txid-ft}

The tag PRF takes the epoch key as input, and its correct evaluation must be
provable with equations of discrete logarithms. The Dodis-Yampolskiy PRF has
this shape. Its output raised to the key plus the input gives back a fixed
value, which is one equation for a Sigma protocol. It is pseudorandom under the $q$-decisional bilinear Diffie-Hellman inversion
($q$-DBDHI) assumption~\cite{PKC:DodYam05}. \Cref{prim:dy-prf} gives it.

\begin{primitivebox}{The Dodis-Yampolskiy PRF~\cite{PKC:DodYam05}.}{dy-prf}

  \begin{description}

    \item[$(\pp,\key) \sample \PRFgen(\secparam)$ :] On input the security
parameter, sample a generator $\ggen_D \sample \group{2}$ and a group element $P
\sample \group{1}$, and return $\pp = (\ggen_D, P)$ and $\key = k \sample \Zp$.

    \item[$y \leftarrow \PRFeval(\pp, \key, x)$ :] On input public parameters
$\pp = (\ggen_D, P)$, key $\key = k$, and input $x \in \Zp \setminus \{-k\}$,
return the following:
      %
      \begin{equation*}
      %
	y = \pairing\big(P, \ggen_D^{1/(k+x)}\big).
      %
      \end{equation*}

  \end{description}

\end{primitivebox}

Here the secret group element $P$ is the epoch tracing key, and the elements
$\ggen_D^{1/(\utk''+\gamma)}$ are published as $\{W_\gamma\}$. A tag is
keyed by the epoch key and not by $\utk''$:
%
\begin{equation*}
  \FT(\PTK,\ek,\gamma) = \pairing(\ek, W_\gamma).
\end{equation*}
%
Its security rests on \Cref{asm:qmdbdhi-txid}.

\begin{assumptionbox}{The Decisional Bilinear Diffie-Hellman Inversion with
published elements ($q$-mDBDHI) assumption.}{qmdbdhi-txid}

  Let $(\group{1},\group{2},\group{T},\pairing)$ be a type III bilinear group of
prime order $p$ with generators $\gen \in \group{1}$ and $\ggen_D \in
\group{2}$. The $q$-mDBDHI assumption holds if, given $(\gen, \ggen_D,
\{\ggen_D^{1/(k+\gamma)}\}_{\gamma\in[0,q)})$ for uniformly random $k \sample
\Zp$ and $P \sample \group{1}$, no PPT adversary can distinguish
$\{\pairing(P, \ggen_D^{1/(k+\gamma)})\}_{\gamma\in[0,q)}$ from
$\{\Delta_{\gamma}\}_{\gamma \in [0,q)}$ for uniformly random $\Delta_{\gamma}
\sample \group{T}$ with non-negligible advantage. Neither $P$ nor $k$ is given
to the adversary. We use it with $q = \Max$.

\end{assumptionbox}

This is a variant of the $q$-DBDHI assumption, with the base elements shared
and the element of $\group{1}$ withheld~\cite{EC:BonBoy04b,PKC:DodYam05}.
Similar $q$-type assumptions are the norm for constructions of this shape, and
pairing-based constructions of this type are known not to admit both short
proofs and a reduction to a simple assumption~\cite{EC:TCRSTW22,TCC:BHKU22}.

The auditor gets the outputs $\{W_\gamma\}$ and not the key $\utk''$.
Every tag of an epoch has the following form, for the same $Y$:
%
\begin{equation*}
  \Tag_\gamma = Y^{1/(\utk''+\gamma)}, \qquad Y = \pairing(\ek,\ggen_D).
\end{equation*}
%
An auditor holding $\utk''$ could recover $Y$
from any single tag on the ledger and compute every other tag of that user in
that epoch without the epoch key. Since $\utk''$ never changes, one grant would
then let the auditor trace the user in every later epoch. With the elements
$\{W_\gamma\}$ instead, the auditor still computes every tag of a granted epoch
from $\ek$, and the epoch key keeps the other epochs out of reach. The
elements $\{W_\gamma\}$ do not reveal $\utk''$, since recovering $\utk''$
from them would break the $q$-SDH assumption, which the BBS+ signature scheme
already requires.

The elements $\{W_\gamma\}$ are public parameters, not secrets held in trust.
The user hands them to every auditor they authorise. Two colluding auditors who
compare their copies learn only that the same user granted them both, which they already knew.

\begin{lemma}\label{lem:txid-ft-prf} Let $\ek$ be uniform in $\group{1}$ and
unknown to the adversary, and let the public parameters
$\{W_\gamma\}_{\gamma\in[0,\Max)}$ be given to the adversary. Under the
$q$-mDBDHI assumption with $q = \Max$, $\FT$ is a secure pseudorandom
function on domain $[0,\Max)$.  \end{lemma}

\subsubsection{The tracing protocol}\label{sec:txid-protocol-inst}

Credentials use the group-element variant of the BBS+ signature scheme of
\Cref{prim:bbs}, on $(S, T)$, with bases $\gen_1$, $\gen_2$ and $\gen_3$ and
randomness generator $\gen_4$. During registration, the user sends only the group elements $S
= \G(\sk)$ and $T$, together with a proof of knowledge of the underlying
secrets, rather than the secrets themselves. Commitments use the Pedersen commitment scheme of \Cref{prim:pedersen} for
vectors of two field elements, so that one commitment holds both components of
$\utk$. It shares its generators with the BBS+ signature scheme. Range proofs, which show that a committed value lies
in an interval, use Bulletproofs~\cite{SP:BBBPWM18}.

BBS+ signs several values at once, can sign values the signer never sees, and
has a Sigma protocol for proving knowledge of a signature. The variant that signs
group elements is unforgeable only if every signed element comes with a proof of
knowledge of its representation, so the registration proof is required and not
optional~\cite{SCN:AuSusMu06,EC:TesZhu23b}. Pedersen commitments are group
elements, so their openings can be proved in a Sigma protocol, and sharing the
generators with BBS+ lets the same committed key appear in both. Bulletproofs
need no trusted setup and their proofs grow logarithmically with the bit length
of the range, so the setup stays transparent.

\Cref{prot:txid} gives the protocol. Each of its algorithms is the algorithm of
the same name in \Cref{prot:txid-generic}, with the following proofs. The proof
for $\rel_4$ is the Sigma protocol for knowledge of a representation of $S$ and
$T$, with its label in the Fiat-Shamir hash. The proofs for $\rel_5$, $\rel_7$
and $\rel_6$ are the epoch key proof, the tag proof and the transaction
authorisation proof, given after the protocol in
\Cref{prot:txid-ek-proof,prot:txid-tag-proof,prot:txid-tx-proof}. The user
proves the range clause of $\rel_7$ with a Bulletproofs range proof on a
separate commitment to the index.

\begin{protocolbox}{The algebraic tracing protocol}{txid}

  \begin{description}

    \item[$(\crs,\state) \sample \IDgen(\secparam)$ :] On input the security
parameter, do:

      \begin{enumerate}

	\item Fix bilinear groups $(\group{1},\group{2},\group{T},p,\pairing)$
of prime order $p$.

	\item Fix a public seed $\mathsf{sd}$ and derive
$\gen_0,\gen_1,\gen_2,\gen_3,\gen_4 \in \group{1}$ and $\ggen,\ggen_D \in
\group{2}$ by hashing to the group from $\mathsf{sd}$. Fix hash functions $\HE
: \{0,1\}^* \to \group{1}$ and $\hash : \{0,1\}^* \to \Zp$.

	\item The registration authority samples $(\rask,\rapk) \sample
\BBSgen(\secparam,3,(\gen_0,\ldots,\gen_4,\ggen))$, which samples only $z
\sample \Zp$ and sets $\ggen_Z \leftarrow \ggen^z$.

	\item Set $\ck \leftarrow (\gen_2,\gen_3,\gen_4)$ and $\Max \leftarrow
2^{\ell}$.

	\item Return $\crs \leftarrow (\group{1},\group{2},\group{T},\pairing,
\mathsf{sd}, \gen_0,\ldots,\gen_4,\ggen,\ggen_D,\HE,\hash, \rapk,\ck,\Max)$ and
$\state \leftarrow \varnothing$.

      \end{enumerate}

    \item[$(\sk,\utk,\regcred) \sample \IDregister(\crs,\state)$ :] Between the
user and the registration authority, do:

      \begin{enumerate}

	\item The registration authority sends a fresh nonce $\rand$ to the
user.

	\item The user samples $\sk,\utk',\utk'' \sample \Zp$, and computes $S
\leftarrow \gen_1^{\sk}$, $T \leftarrow \gen_2^{\utk'}\cdot\gen_3^{\utk''}$ and
$W_\gamma \leftarrow \ggen_D^{1/(\utk''+\gamma)}$ for each $\gamma \in
[0,\Max)$.

	\item The user computes the proof $\algoproof_4$ of knowledge of
$(\sk,\utk',\utk'')$ with label $\rand$, and sends $(S,T,\algoproof_4)$ to the
registration authority.

	\item The registration authority exits if $S$ has been registered before
or $\algoproof_4$ does not verify.

	\item The registration authority computes $\signature \sample
\BBSsign(\rask,(S,T))$ and records $S$ as registered.

	\item Return $\sk$ and $\utk \leftarrow (\utk',\utk'')$ to the user,
and $\regcred \leftarrow (S,T,\signature)$ as their registration credential.

      \end{enumerate}

    \item[$(\PTK,\ek) \sample \IDgrant(\crs,\sk,\utk,\regcred,\epoch)$ :]
Between the user and an auditor, do:

      \begin{enumerate}

	\item The auditor sends a fresh nonce $\rand$ to the user.

	\item The user exits if the epoch $\epoch$ has started.

	\item The user parses $\regcred = (S,T,\signature)$, and computes $\ek
\leftarrow \HE(\epoch)^{\utk'}$ and the epoch key proof $\algoproof_5$ of
\Cref{prot:txid-ek-proof} with label $\rand$. On the user's first grant to this
auditor, $\algoproof_5$ also covers $\{W_\gamma\}$.

	\item The user computes the proof $\algoproof_4$ of knowledge of
$(\sk,\utk',\utk'')$ with label $\algoproof_5\|\rand$, and sends
$(\regcred,\ek,\algoproof_5,\algoproof_4)$ to the auditor, together with
$\{W_\gamma\}$ on a first grant.

	\item The auditor outputs $\PTK = (T,\{W_\gamma\})$ and $\ek$ if the
epoch $\epoch$ has not started, $\BBSverify(\rapk,(S,T),\signature) = 1$
and both proofs verify, and exits otherwise.

      \end{enumerate}

    \item[$\tx \sample \IDsubmit(\crs,\sk,\utk,\regcred,\epoch,\payload)$ :] On
input from the user, do:

      \begin{enumerate}

	\item Parse $\regcred = (S,T,\signature)$ and compute $\ek \leftarrow
\HE(\epoch)^{\utk'}$.

	\item Take an index $\gamma \in [0,\Max)$ that the user has not used in
this epoch, and compute $\Tag_\gamma \leftarrow
\pairing(\ek,W_\gamma)$.

	\item Sample $\openinfo, r_\gamma \sample \Zp$ and compute the following:
	  %
	  \begin{equation*}
	    \com \leftarrow \gen_2^{\utk'} \cdot \gen_3^{\utk''} \cdot
\gen_4^{\openinfo}.
	  \end{equation*}

	\item Compute the tag proof $\algoproof_7'$ of
\Cref{prot:txid-tag-proof} with the opening $r_\gamma$. It contains the
commitment $\com_\gamma$ to the index. Compute a Bulletproofs range proof
$\algoproof_{\mathsf{rng}}$ that $\com_\gamma$ opens to a value in $[0,\Max)$.

	\item Set $\msg \leftarrow
\payload\|\Tag_\gamma\|\com\|\algoproof_7'\|
\algoproof_{\mathsf{rng}}$, and compute the transaction authorisation proof
$\algoproof_6'$ of \Cref{prot:txid-tx-proof} with label $\msg$.

	\item Return $\tx \leftarrow (\payload,\Tag_\gamma,\com,
\algoproof_7',\algoproof_{\mathsf{rng}},\algoproof_6')$, and submit it to the
ledger.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \algo{Verify}(\crs,\state,\tx)$ :] Run by the
transaction validators. Parse $\tx$, and return $1$ if and only if the
following hold:

      \begin{enumerate}

	\item $\Tag_\gamma \notin \state$.

	\item $\algoproof_7'$ verifies with the tag proof.

	\item $\algoproof_{\mathsf{rng}}$ verifies for the $\com_\gamma$ in
$\algoproof_7'$ and the range $[0,\Max)$.

	\item $\algoproof_6'$ verifies with the transaction authorisation proof
on $\msg$.

      \end{enumerate}

      On returning $1$, the validators set $\state[\Tag_\gamma] \leftarrow
\payload$.

    \item[$\{\payload\} \leftarrow \IDidentify(\crs,\PTK,\ek,\epoch)$ :] For
each $\gamma \in [0,\Max)$, compute $\Tag_\gamma \leftarrow
\pairing(\ek,W_\gamma)$ and retrieve $\state[\Tag_\gamma]$ if present. Return
the set of retrieved payloads.

  \end{description}

\end{protocolbox}

Because the elements $\{W_\gamma\}$ do not
depend on the epoch, each auditor receives them once, at its first grant from a
user, and every later grant is constant size. In the instantiation,
$\rel_5$ has the following instance and witness:
%
\begin{equation*}
  \inst_5 = (\HE, \gen_2, \gen_3, \ggen_D, T, \epoch, \ek,
\{W_\gamma\}_{\gamma\in[0,\Max)}), \qquad \witness_5 = (\utk',\utk'').
\end{equation*}
%
The relation is the following:
%
\begin{equation*} \begin{gathered}
  \rel_5 = \{\ T = \gen_2^{\utk'}\cdot\gen_3^{\utk''} \ \wedge \ \ek =
\HE(\epoch)^{\utk'} \ \wedge \ \forall\, \gamma \in [0,\Max): \
W_\gamma^{\utk''} = \ggen_D \cdot W_\gamma^{-\gamma}\ \}.
\end{gathered} \end{equation*}
%
The last equation is the definition of $W_\gamma$, rearranged into an equality
of discrete logarithms against the committed $\utk''$. Instead of all $\Max$
of these equations, the prover proves one random linear combination of them, with coefficients derived by hashing the elements themselves. Later
grants to the same auditor prove only the first two equations, against the same
certified $T$. \Cref{prot:txid-ek-proof} gives the proof.

\begin{protocolbox}{The epoch key proof}{txid-ek-proof}

  \begin{description}

    \item[$\algoproof_5 \sample \NIZKprove(\crs_5, \inst_5, \witness_5,
\rand)$ :] On input $\inst_5$, $\witness_5$ and label $\rand$, do:

      \begin{enumerate}

	\item On a first grant, compute the following for each $\gamma \in
[0,\Max)$:
	  %
	  \begin{equation*}
	    \lambda_\gamma \leftarrow \hash(\{W_\gamma\},\gamma).
	  \end{equation*}
	  %
	  Then compute the following:
	  %
	  \begin{equation*}
	    \widehat{W} \leftarrow \prod_{\gamma=0}^{\Max-1}
W_\gamma^{\lambda_\gamma}, \qquad \widehat{V} \leftarrow \prod_{\gamma=0}^{\Max-1}
(\ggen_D\cdot W_\gamma^{-\gamma})^{\lambda_\gamma}.
	  \end{equation*}

	\item Sample $\alpha,\beta \sample \Zp$, and compute $A \leftarrow
\gen_2^{\alpha}\cdot\gen_3^{\beta}$, $B \leftarrow \HE(\epoch)^{\alpha}$, and on
a first grant $K \leftarrow \widehat{W}^{\beta}$.

	\item Compute the challenge $c \leftarrow \hash(\inst_5,A,B,K,\rand)$,
leaving out $K$ and $\{W_\gamma\}$ on a later grant.

	\item Compute $\eta \leftarrow \alpha + c\cdot\utk'$ and $\zeta
\leftarrow \beta + c\cdot\utk''$.

	\item Return $\algoproof_5 \leftarrow (A,B,K,\eta,\zeta)$, without $K$
on a later grant.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \NIZKverify(\crs_5, \inst_5, \algoproof_5,
\rand)$ :] Compute $c$ as above, and on a first grant also $\widehat{W}$ and
$\widehat{V}$. Return $1$ if and only if the following hold, the last on a
first grant only:
      %
      \begin{equation*}
	\gen_2^{\eta}\cdot\gen_3^{\zeta} = A\cdot T^{c}, \quad
\HE(\epoch)^{\eta} = B\cdot\ek^{c}, \quad \widehat{W}^{\zeta}
= K\cdot\widehat{V}^{c}.
      \end{equation*}

  \end{description}

\end{protocolbox}

The tag proof must show that the tag is the user's
tag for this epoch at some index in range, without revealing the epoch key or
the index. Proving $\rel_7$ directly would require an argument over the secret
group element $\ek$ paired against a secret-exponent term, which would be
expensive in practice. Instead, the user blinds the epoch key and the tag with a
fresh scalar, publishes the blinded values, and proves only equalities of
discrete logarithms. The index is committed separately, and the tag proof and
a standard range proof both refer to that commitment, so the index shown to
be in range is the one the tag is computed from, as \Cref{lem:txid-rel7}
shows.

A correctly formed tag satisfies the following equation:
%
\begin{equation*}
  \Tag_\gamma^{\utk''+\gamma} = \pairing(\ek,\ggen_D).
\end{equation*}
%
The user samples fresh $s, r_\gamma \sample \Zp$, and publishes the epoch hash
blinded by $s$ as $U$, the tag blinded by $s$ as $X$, the blinded epoch key
paired with $\ggen_D$ as $\Pi$, and the commitment $\com_\gamma$ to the index.
After blinding, the equation above becomes the following:
%
\begin{equation*}
  \Pi = X^{\utk''+\gamma}.
\end{equation*}
%
The user proves the rewritten tag relation $\rel_7'$, with instance and witness as
follows:
%
\begin{equation*}
  \inst_7' = (\inst_7, U, \Pi, X, \com_\gamma), \qquad \witness_7' =
(\utk', \utk'', \openinfo, s, \gamma, r_\gamma),
\end{equation*}
%
\begin{equation*} \begin{gathered}
  \rel_7' = \{\ \com = \gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot\gen_4^{\openinfo}
\ \wedge \ U = \HE(\epoch)^s \ \wedge \ \Pi = \pairing(U,\ggen_D)^{\utk'} \\
\wedge \ X = \Tag_\gamma^s \ \wedge \ \Pi = X^{\utk''}\cdot X^{\gamma} \ \wedge
\ \com_\gamma = \gen_3^{\gamma}\cdot\gen_4^{r_\gamma} \ \wedge \ 0 \leq \gamma <
\Max\ \}.
\end{gathered} \end{equation*}
%
Every equation is now one of discrete logarithms, and the only pairing is
computed by the verifier on public data. The rewriting loses nothing, provided
the verifier rejects $U = 1_{\group{1}}$ and $\Pi = 1_{\group{T}}$. Otherwise a
prover could blind with zero, or pick a key and index that cancel, and any tag
would pass.

\begin{lemma}\label{lem:txid-rel7} Every witness for $\rel_7$ gives a witness
for $\rel_7'$, and every witness for $\rel_7'$ with $U \neq 1_{\group{1}}$ and
$\Pi \neq 1_{\group{T}}$ gives a witness for $\rel_7$ with the same index. The
tag proof of \Cref{prot:txid-tag-proof}, together with a range proof on
$\com_\gamma$, satisfies completeness, special soundness and honest-verifier
zero knowledge for $\rel_7$, the last with a simulator that is also given the
index $\gamma$ and under the DDH assumption in $\group{1}$.
\end{lemma}

\begin{protocolbox}{The tag proof}{txid-tag-proof}

  \begin{description}

    \item[$\algoproof_7' \sample \NIZKprove(\crs_7, \inst_7, \witness_7)$ :]
On input $\inst_7$, $\witness_7$ and the opening $r_\gamma$ of $\com_\gamma$,
do:

      \begin{enumerate}

	\item Parse $\inst_7 = (\HE, \ggen_D, \gen_2, \gen_3, \gen_4, \com,
\epoch, \Max, \Tag_\gamma)$ and $\witness_7 = (\utk', \utk'', \openinfo,
\ek, \gamma)$.

	\item Sample $s \sample \Zp$ and compute the following:
	  %
	  \begin{equation*}
	    U \leftarrow \HE(\epoch)^s, \quad \Pi \leftarrow
\pairing\big(\ek^{\,s},\, \ggen_D\big), \quad X \leftarrow
\Tag_\gamma^{\,s}, \quad \com_\gamma \leftarrow
\gen_3^{\gamma}\cdot\gen_4^{r_\gamma}.
	  \end{equation*}

	\item Set $\inst_7' \leftarrow (\inst_7, U, \Pi, X, \com_\gamma)$.

	\item Sample $\mu_1, \mu_2, \mu_h, \mu_s, \mu_\gamma, \mu_r \sample
\Zp$ for the witness values $\utk', \utk'', \openinfo, s, \gamma, r_\gamma$,
and compute the following:
	  %
	  \begin{gather*}
	    A \leftarrow \gen_2^{\mu_1}\cdot\gen_3^{\mu_2}\cdot\gen_4^{\mu_h},
\quad B \leftarrow \HE(\epoch)^{\mu_s}, \quad M \leftarrow
\pairing(U,\ggen_D)^{\mu_1}, \\
	    C \leftarrow \Tag_\gamma^{\mu_s}, \quad F \leftarrow X^{\mu_2 +
\mu_\gamma}, \quad A_\gamma \leftarrow \gen_3^{\mu_\gamma}\cdot\gen_4^{\mu_r}.
	  \end{gather*}

	\item Compute the challenge $c \leftarrow \hash(\inst_7', A, B, M, C, F,
A_\gamma)$.

	\item Compute $\theta_x \leftarrow \mu_x + c\cdot x$ for each witness
value $x$, writing $\theta_1, \theta_2, \theta_h, \theta_s, \theta_\gamma,
\theta_r$ in the order above.

	\item Return $\algoproof_7' \leftarrow (U, \Pi, X, \com_\gamma, A, B, M,
C, F, A_\gamma, \theta_1, \theta_2, \theta_h, \theta_s, \theta_\gamma,
\theta_r)$.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \NIZKverify(\crs_7, \inst_7, \algoproof_7')$ :]
Compute $c$ as above, and return $1$ if and only if the following hold:
      %
      \begin{gather*} U \neq 1_{\group{1}}, \quad \Pi \neq 1_{\group{T}}, \\
\gen_2^{\theta_1}\cdot\gen_3^{\theta_2}\cdot
\gen_4^{\theta_h} = A \cdot \com^c, \quad \HE(\epoch)^{\theta_s}
= B \cdot U^c, \quad \pairing(U,\ggen_D)^{\theta_1} = M
\cdot \Pi^c, \\ \Tag_\gamma^{\theta_s} = C \cdot X^c, \quad
X^{\theta_2 + \theta_\gamma} = F \cdot \Pi^c, \quad
\gen_3^{\theta_\gamma}\cdot\gen_4^{\theta_r} = A_\gamma \cdot
\com_\gamma^{c}.  \end{gather*}

  \end{description}

\end{protocolbox}

Each transaction comes with a
proof that it originated from a registered user, following relation $\rel_6$.
The registration authority certifies the key committed in $\com$ with a BBS+
signature. As for the tag proof, we rewrite $\rel_6$ as an equivalent relation
$\rel_6'$ that avoids proofs over bilinear
equations~\cite{CDL16,USENIX:HesSinSor23}. The rewriting
randomises the signature, which the verifier checks with one pairing equation on
public data, and every other equation is one of discrete logarithms. The
signature and the commitment share the randomness generator, so the proof
reconciles their two random exponents.

The user writes $b$ for the base of the credential, randomises the signature
with a fresh $r_1 \sample \Zp^*$, and blinds the base with a fresh $r_2 \sample
\Zp$:
%
\begin{equation*}
  b = \gen_0\cdot\gen_1^{\sk}\cdot\gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot
\gen_4^{r}, \qquad E' = E^{r_1}, \qquad d = b^{r_1}\cdot\gen_4^{-r_2}, \qquad
\bar{E} = E'^{-e}\cdot d\cdot\gen_4^{r_2}.
\end{equation*}
%
For a valid signature $\bar{E} = E'^{z}$, which the verifier checks with the
following pairing equation:
%
\begin{equation*}
  \pairing(E',\ggen_Z) = \pairing(\bar{E},\ggen).
\end{equation*}
%
The user also sets the following:
%
\begin{equation*}
  r_3 = 1/r_1, \qquad r'' = r - r_2 r_3 - \openinfo.
\end{equation*}
%
The user proves the rewritten relation $\rel_6'$, with instance and witness as
follows:
%
\begin{equation*}
  \inst_6' = (\rapk, \com, E', \bar{E}, d), \qquad \witness_6' = (\sk, \utk',
\utk'', \openinfo, e, r_2, r_3, r''),
\end{equation*}
%
\begin{equation*} \begin{gathered}
  \rel_6' = \{\ \com = \gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot\gen_4^{\openinfo}\
\wedge \ \pairing(E', \ggen_Z) = \pairing(\bar{E}, \ggen) \\ \wedge \ \bar{E}/d
= E'^{-e}\cdot\gen_4^{r_2} \ \wedge \ (\gen_0\cdot\com)^{-1} =
\gen_1^{\sk}\cdot d^{-r_3}\cdot\gen_4^{r''}\ \}.
\end{gathered} \end{equation*}
%
The third equation ties $\bar{E}$ to the signature's exponent $e$, and the last
ties the blinded base to the committed tracing key, with $r''$ reconciling the
signature's randomness with the commitment's opening. The proof takes the whole
transaction as its label.

\begin{lemma}\label{lem:txid-rel6} Every witness for $\rel_6$ gives a witness
for $\rel_6'$, and every witness for $\rel_6'$ with $E' \neq 1_{\group{1}}$
gives a BBS+ signature on the values committed in $\com$ and on $\sk$. The
transaction authorisation proof of \Cref{prot:txid-tx-proof} satisfies
completeness, special soundness and honest-verifier zero knowledge for
$\rel_6$.
\end{lemma}

\begin{protocolbox}{The transaction authorisation proof}{txid-tx-proof}

  \begin{description}

    \item[$\algoproof_6' \sample \NIZKprove(\crs_6, \inst_6, \witness_6,
\msg)$ :] On input $\inst_6$, $\witness_6$ and label $\msg$, do:

      \begin{enumerate}

	\item Parse $\inst_6 = (\rapk, \com)$ with $\rapk = (\gen_0, \gen_1, \gen_2,
\gen_3, \gen_4, \ggen, \ggen_Z)$, and $\witness_6 = (\sk, \utk', \utk'',
\openinfo, e, r, E)$.

	\item Sample $r_1 \sample \Zp^*$ and $r_2 \sample \Zp$, and compute
$E'$, $d$, $\bar{E}$, $r_3$ and $r''$ as above.

	\item Sample $\mu_x \sample \Zp$ for each witness value $x$ of
$\witness_6'$, writing $\mu_1$, $\mu_2$ and $\mu_h$ for those of $\utk'$,
$\utk''$ and $\openinfo$, and compute the following:
	  %
	  \begin{equation*}
	    t_1 \leftarrow \gen_2^{\mu_1}\cdot\gen_3^{\mu_2}\cdot
\gen_4^{\mu_h}, \quad t_2 \leftarrow E'^{-\mu_e}\cdot\gen_4^{\mu_{r_2}}, \quad
t_3 \leftarrow \gen_1^{\mu_\sk}\cdot d^{-\mu_{r_3}}\cdot \gen_4^{\mu_{r''}}.
	  \end{equation*}

	\item Compute the challenge $c \leftarrow \hash(\inst_6, E', \bar{E}, d,
t_1, t_2, t_3, \msg)$.

	\item Compute $\theta_x \leftarrow \mu_x + c\cdot x$ for each witness
value $x$, with the same subscripts, and let $\vec{\theta}$ be the vector of
all eight responses.

	\item Return $\algoproof_6' \leftarrow (E', \bar{E}, d, t_1, t_2, t_3,
\vec{\theta})$.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \NIZKverify(\crs_6, \inst_6, \algoproof_6',
\msg)$ :] Compute $c$ as above, and return $1$ if and only if the following
hold:
      %
      \begin{gather*}
	E' \neq 1_{\group{1}}, \quad \pairing(E', \ggen_Z) = \pairing(\bar{E},
\ggen), \\
	\gen_2^{\theta_1}\cdot\gen_3^{\theta_2}\cdot\gen_4^{\theta_h} =
t_1\cdot\com^c, \quad E'^{-\theta_e}\cdot\gen_4^{\theta_{r_2}} =
t_2\cdot(\bar{E}/d)^c, \\ \gen_1^{\theta_\sk}\cdot d^{-\theta_{r_3}}\cdot
\gen_4^{\theta_{r''}} = t_3\cdot\big((\gen_0\cdot\com)^{-1}\big)^{c}.
      \end{gather*}

  \end{description}

\end{protocolbox}

\begin{theorem}\label{thm:inst} The algebraic instantiation securely realises
$\idfu{\algo{trace}}$ in the standalone model, in the random oracle model for
$\HE$, $\hash$ and the hash to the group that derives the generators, under the DDH assumption in $\group{1}$, the $q$-mDBDHI
assumption with $q = \Max$, the $q$-SDH assumption, and the DL assumption in
$\group{1}$.
\end{theorem}

Under the DDH assumption in $\group{1}$ the epoch PRF is pseudorandom and the
tag proof is zero knowledge. Under the $q$-mDBDHI assumption the tag PRF is
pseudorandom, under the $q$-SDH assumption the credentials are unforgeable, and
under the DL assumption the commitments are binding and the range proofs sound.

\subsection{Instantiating $\ID$ with hash-based PRFs}\label{sec:txid-hash-instantiation}

The protocol above keeps its proofs algebraic so that they are cheap to compute.
We now give a more straightforward instantiation, in which both pseudorandom
functions are hash functions and the proofs about them use a general-purpose
proof system. We use independent hash functions
$\hashfs$ for Fiat-Shamir challenges, $\HE$ for epoch keys and $\HT$ for tags,
and instantiate the components of \Cref{prot:txid-generic} as follows:
%
\begin{enumerate}

  \item The one-way functions are $\G(\sk) = \gen_1^{\sk}$ and $\G'(\utk) =
\gen_2^{\utk}$, for a tracing key $\utk \in \Zp$ that is now a single scalar.
The public tracing key is one group element.

  \item The pseudorandom functions are $\FE(\utk,\epoch) = \HE(\utk,\epoch)$ and
$\FT(\PTK,\ek,\gamma) = \HT(\ek,\gamma)$. Both are the MiMC block cipher, keyed
by $\utk$ and by $\ek$ respectively and applied to the input. MiMC is designed
to be cheap inside an arithmetic circuit, a statement written as additions and
multiplications over $\Zp$~\cite{AC:AGRRT16}.

  \item $\DS$ is the BBS+ signature scheme of \Cref{prim:bbs} with $n = 2$ and
generators $\gen_0, \ldots, \gen_3$, on the two field elements $\sk$ and
$\utk$. The registration authority signs them in the group-element variant, on
$\G(\sk) = \gen_1^{\sk}$ and $\PTK = \gen_2^{\utk}$, without learning them.

  \item $\Com$ is the Pedersen commitment scheme of \Cref{prim:pedersen}, with
$\ck = (\gen_2, \gen_3)$. Here $\gen_3$ is also the randomness generator of
the BBS+ signature scheme, as $\gen_4$ is in the algebraic instantiation, and we
derive all generators by hashing to the group.

  \item The proofs for $\rel_5$ and $\rel_7$ use the zk-SNARK of Groth,
extended with a commitment to part of the
witness~\cite{EC:Groth16,CCS:BelSolBeg23}. Its proofs are a constant number of
group elements and its statements are arithmetic circuits over $\Zp$. Its
structured reference string is generated for each circuit from secret values,
so this instantiation needs a trusted setup. Each proof comes with a commitment
to the tracing key in the witness, and the linking proof of
\Cref{prot:txid-link}.

  \item The proofs for $\rel_4$ and $\rel_6$ are Sigma protocols compiled with
the Fiat-Shamir transform under $\hashfs$, as in the algebraic instantiation.

\end{enumerate}

The hash-based pseudorandom functions have no Sigma protocol, so their relations
need a general-purpose proof system. A zk-SNARK has small proofs and cheap
verification, which the validators pay for on every transaction. The linking
proof adds only what ties the hidden key of the circuit to the group elements
used elsewhere.

Not every hash function is a pseudorandom function. Collision and preimage
resistance say nothing about outputs looking random, and the random oracle
heuristic does not help, since we prove statements about the concrete function
inside a circuit. So we use the MiMC block cipher keyed with the secret, and
assume that it is a pseudorandom permutation, also against a distinguisher
holding $\PTK = \gen_2^{\utk}$. A pseudorandom permutation is a keyed
permutation that no efficient distinguisher can tell from a uniformly random
one. The switching lemma says that no one making $q$
queries can tell a random permutation on $\Zp$ from a random function, except
with probability about $q^2/p$~\cite{EC:BelRog06}. So a pseudorandom
permutation is also a pseudorandom function, up to this loss. The cryptanalysis of MiMC is of this keyed
permutation~\cite{AC:AGRRT16}. Holding $\PTK$ is outside the standard notion,
so that part of the assumption is ours.

Circuits cannot take $\PTK$ or $\com$ as input. Statements of the zk-SNARK are
over $\Zp$, and the coordinates of these group elements lie in a different
field. Checking them in the circuit costs hundreds of thousands of constraints,
and listing them as public inputs binds nothing.
So each zk-SNARK proof comes with a commitment and a linking proof, in the
commit-and-prove style of LegoSNARK~\cite{CCS:CamFioQue19}. The circuit commits
to the tracing key. A small Sigma protocol then shows that this commitment
contains the same key as the public tracing key, at a grant, or as $\com$, in a
transaction. \Cref{prot:txid-link} gives the linking proof.

\begin{protocolbox}{The linking proof}{txid-link}

  \begin{description}

    \item[Circuits :] The grant circuit proves $\ek = \HE(\utk, \epoch)$, and
the transaction circuit proves $\Tag_\gamma = \HT(\HE(\utk, \epoch), \gamma)$
and $0 \leq \gamma < \Max$. The setup of each circuit also outputs a
commitment key $(K_0, K_1) \in \group{1}^2$. Each proof carries $D =
K_0^{\utk}\cdot K_1^{\mu}$ for a fresh $\mu \sample \Zp$, and the verifier
checks the proof against $D$.

    \item[Prove :] On input $D$, $\com = \gen_2^{\utk}\cdot\gen_3^{\openinfo}$,
the witness $(\utk, \mu, \openinfo)$ and a context $\mathsf{ctx}$, do:

      \begin{enumerate}

	\item Sample $b_u, b_m, b_x \sample \Zp$, and compute $A_1 \leftarrow
K_0^{b_u}\cdot K_1^{b_m}$ and $A_2 \leftarrow \gen_2^{b_u}\cdot\gen_3^{b_x}$.

	\item Compute the challenge $c \leftarrow \hashfs(\crs, K_0, K_1, D,
\com, A_1, A_2, \mathsf{ctx})$.

	\item Compute $s_u \leftarrow b_u + c\cdot\utk$, $s_m \leftarrow b_m +
c\cdot\mu$ and $s_x \leftarrow b_x + c\cdot\openinfo$.

	\item Return $(A_1, A_2, s_u, s_m, s_x)$.

      \end{enumerate}

      The context $\mathsf{ctx}$ is $(\epoch, \Tag_\gamma, \algoproof_7)$ in a
transaction and $(\epoch, \ek, \algoproof_5, \rand)$ at a grant.

    \item[Verify :] Compute $c$ as above, and return $1$ if and only if the
following hold:
      %
      \begin{equation*}
	K_0^{s_u}\cdot K_1^{s_m} = A_1\cdot D^c, \quad
\gen_2^{s_u}\cdot\gen_3^{s_x} = A_2\cdot\com^c.
      \end{equation*}

    \item[Linking to $\PTK$ :] At a grant, the same protocol links $D$ to $\PTK
= \gen_2^{\utk}$, without $\openinfo$, $b_x$ and $s_x$.

  \end{description}

\end{protocolbox}

\begin{theorem}\label{thm:hash-inst} The hash-based instantiation securely
realises $\idfu{\algo{trace}}$ in the standalone model, in the random oracle
model for $\hashfs$ and the hash to the group that derives the generators,
under the $q$-SDH assumption and the DL assumption in
$\group{1}$, if the zk-SNARK of Groth with commitments is zero knowledge and
simulation extractable, and the MiMC block cipher is a pseudorandom permutation
against a distinguisher holding $\gen_2^{\utk}$.  \end{theorem}
