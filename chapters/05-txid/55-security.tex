\section{Security}\label{sec:txid-security}

\subsection{Proof of \Cref{thm:txid-bb}: security of the construction}\label{sec:txid-bb-sec}

We show that the view of a real world adversary $\adv$ during an execution of
$\prot$ is indistinguishable from the view of an ideal world simulator $\simu$
that interacts with system participants through ideal functionality
$\idfu{\algo{trace}}$. We define a sequence of indistinguishable games that
start with Game 0 representing the real world, and end with Game 7 representing
the ideal world.

The games below use five properties, which follow from the hypotheses of
\Cref{thm:txid-bb} and the channels of the model. The proofs of the two
instantiation theorems show that each instantiation has them.

\begin{enumerate}

  \item[(P1)] $\DS$ is EUF-CMA secure, so no PPT adversary produces a valid
signature without querying the registration authority.

  \item[(P2)] $\Com$ is binding and hiding in the sense of
\Cref{sec:prelims-commitments}.

  \item[(P3)] $\FE$ and $\FT$ are pseudorandom, also against a distinguisher
holding the user's public tracing key $\PTK$.

  \item[(P4)] The proofs for $\rel_4$ to $\rel_7$ are zero knowledge and
simulation extractable: a witness can be extracted from any accepted proof, and
simulated proofs are indistinguishable from real ones.

  \item[(P5)] Honest users and honest auditors communicate over a secure,
confidential channel.

\end{enumerate}

The extraction in (P4) relies on binding in (P2). (P3) is what
\Cref{sec:txid-construction} asks for.

\begin{proof}

  $\simu$ maintains three tables, analogous to $\reg$, $\perm$, and $\txns$ in
$\idfu{\algo{trace}}$:

  \begin{enumerate}

    \item $\regsimu[\user] = (\sk, \utk, \signature)$, logging registered users.

    \item $\permsimu[(\auditor,\user,\epoch)] = \ek$, logging tracing
permissions and epoch keys.

    \item $\txnssimu[(\user,\epoch)]$, logging submitted transactions.

  \end{enumerate}

  \paragraph{Game 0.} The real execution of $\prot$.

  \paragraph{Game 1.} As Game 0, except $\simu$ simulates the ledger
operator, the registration authority, and the honest users and auditors, by
following $\prot$'s instructions. Game 1 is indistinguishable
from Game 0 by construction.

  \paragraph{Game 2.} As Game 1, except during registration $\simu$ simulates
the registration authority's output directly from $\idfu{\algo{trace}}$'s
$\IDregister$ calls, rather than executing $\prot$. For each honest user's
$\IDregister$ request, $\simu$ selects random $(\sk, \utk)$, simulates an
execution of $\prot$, and stores $\regsimu[\user] = (\sk, \utk, \signature)$.

  For a valid registration request from a corrupt user, $\simu$ issues
$\IDregister$ to $\idfu{\algo{trace}}$ on the user's behalf and returns its
output.  If $\idfu{\algo{trace}}$ registers the user, $\simu$ extracts $(\sk,
\utk)$ using the extractability of the proof (P4), computes $\signature$
following $\prot$, sends it to $\user$, and records $\regsimu[\user] = (\sk, \utk,
\signature)$.

  The two games diverge only if $\idfu{\algo{trace}}$'s decision on some
$\IDregister$ call differs from $\prot$'s. The correctness of $\prot$ rules out
$\idfu{\algo{trace}}$ accepting where $\prot$ rejects, and the registration
authority's tracking of past requests rules out the reverse, since only a double
registration could cause it, and that never succeeds. So Game 2 is
indistinguishable from Game 1.

  \paragraph{Game 3.} As Game 2, except $\simu$ simulates honest users'
responses to tracing authorisation requests using only $\idfu{\algo{trace}}$'s
output on $\IDgrant$ calls.

  For an $\IDgrant$ call between honest user $\user$ and honest auditor
$\auditor$ in epoch $\epoch$, $\simu$ sets $\permsimu[(\auditor,\user,\epoch)]
\leftarrow \varnothing$ and simulates the transcript with randomly generated
information. By (P5), this is indistinguishable from a real execution.

  For an authorisation request from a corrupt auditor $\auditor$ to honest user
$\user$, $\simu$ forwards it to $\user$, who calls $\IDgrant$. If
$\idfu{\algo{trace}}$ accepts, $\simu$ retrieves $(\sk, \utk, \signature)
\leftarrow \regsimu[\user]$, simulates $\user$'s response following $\prot$, and
sets $\permsimu[(\auditor,\user,\epoch)] \leftarrow \FE(\utk, \epoch)$.

  For an authorisation from a corrupt user $\user$ to honest auditor
$\auditor$ in epoch $\epoch$, $\simu$ runs the auditor's checks of $\prot$. If
they pass, $\simu$ extracts $(\sk, \utk)$ from the proof for $\rel_4$ (P4), calls
$\IDgrant$ on $\user$'s behalf, and sets $\permsimu[(\auditor,\user,\epoch)]
\leftarrow \ek$. By (P1) the credential was issued to $\user$ at registration,
so the extracted key is the one in $\regsimu[\user]$, and by (P4) $\ek =
\FE(\utk, \epoch)$. The checks pass only for an epoch that has not started, so
$\idfu{\algo{trace}}$ accepts exactly when the real auditor does.

  This simulated response is indistinguishable from a real one, so Game 3 is
indistinguishable from Game 2.

  \paragraph{Game 4.} As Game 3, except $\simu$ replaces $\FE(\utk,\cdot)$ of
every honest user by a random function, and uses its values as that user's
epoch keys in every grant and transaction.

  $\simu$ samples each epoch key $\ek$ of an honest user uniformly from the
range of $\FE$, the first time it is needed, and reuses it for that user and
epoch. For a grant to a corrupt auditor, it sets the following:
  %
  \begin{equation*}
    \permsimu[(\auditor,\user,\epoch)] \leftarrow \ek.
  \end{equation*}
  %
  $\simu$ samples the user's public tracing key $\PTK_\user$ once per user, at
registration, and reuses it in every grant for that user. This is required, since
$\PTK$ is certified once and is identical across epochs by construction. A
simulator that drew a fresh one per grant would be trivially distinguishable by a
corrupt auditor holding grants for two epochs.

  When such a user submits a transaction, $\simu$ computes the tag as
$\FT(\PTK_\user,\ek,\gamma)$ under the substituted key, so that a corrupt
auditor's tracing still succeeds.

  Before the substitution, $\simu$ simulates every proof of honest users (P4),
including the proofs for $\rel_4$ at registration and for $\rel_5$ at grants,
and replaces each of their commitments $\com$ by a commitment to a fresh
uniform value (P2). After this step, an honest user's $\utk$ enters the view of
$\adv$ only through $\PTK_\user$ and the outputs of $\FE(\utk,\cdot)$. We then
replace these functions one honest user at a time. Two neighbouring hybrids
differ in one user's function, and a distinguisher between them breaks
pseudorandomness of $\FE$ (P3) against a distinguisher given $\PTK_\user$,
since the reduction can compute every other user's keys itself. So this game is
indistinguishable from Game 3, with a loss of the number of honest
users.\rebekah{check: Game 4 now replaces all of $\FE(\utk,\cdot)$ per honest
user, with a hybrid over users, not only the keys granted to corrupt auditors}

  \paragraph{Game 5.} As Game 4, except $\simu$ also simulates transaction
submission using $\idfu{\algo{trace}}$'s output on $\IDsubmit$ requests from
honest users.

  For each honest user's $\IDsubmit$ call in epoch $\epoch$, $\simu$ checks
whether any corrupt auditor can trace the transaction back to its origin. It
does this by issuing $\IDidentify$ queries on behalf of every corrupt auditor
holding a permission for that user, until it finds a match:

  \begin{enumerate}

    \item For each pair of honest user and corrupt auditor $(\user, \auditor)$
with $\permsimu[(\auditor,\user,\epoch)]\neq \bot$, \linebreak call $\IDidentify$ and
receive $\txns[(\user,\epoch)]$.

    \item If $\txns[(\user,\epoch)] \neq \txnssimu[(\user, \epoch)]$, let
$\algo{TX} = \txns[(\user,\epoch)] \setminus \txnssimu[(\user, \epoch)]$, update
$\txnssimu[(\user, \epoch)] \leftarrow \txns[(\user, \epoch)]$, and output the
pair $(\user, \algo{TX})$.

  \end{enumerate}

  These two steps run on every $\IDsubmit$ call, so after each call
$\txnssimu[(\user,\epoch)] = \txns[(\user,\epoch)]$ for every user that some
corrupt auditor can trace. So at most one entry can have grown since the
previous call, and if one has, it belongs to the user who just called
$\IDsubmit$ and identifies them. This leaves exactly two cases. If no entry
grew, no corrupt auditor holds a permission for the calling user this epoch, so
$\simu$ never learns who called. If one grew, say $\txns[(\user^\star,\epoch)] =
\txnssimu[(\user^\star,\epoch)] \cup \{\payload\}$, then a corrupt auditor is
authorised to trace $\user^\star$ and $\simu$ learns both the caller and the
payload.

  \begin{description}

    \item[No corrupt auditor holds a permission for this user and epoch.]
$\simu$ places the payload it receives from $\idfu{\algo{trace}}$ in the
transaction. Instead of computing the tag as $\Tag_\gamma =
\FT(\PTK,\ek,\gamma)$, it samples a tag $\Tag_{\gamma}^\star$ uniformly at
random. The commitment and both proofs are simulated as from Game 4. After Game 4 the epoch keys released to corrupt auditors
are uniform and independent across epochs, so the keys released for preceding
and succeeding epochs give no information about the key in use here, and
$\adv$ does not hold it. Pseudorandomness of $\FT$ allows the substitution,
since the tags of an epoch are pseudorandom to an adversary holding $\PTK$ but
not $\ek$, and every corrupt auditor here holds $\PTK$ but not $\ek$. No
corrupt auditor obtains a permission for this epoch later, since
$\idfu{\algo{trace}}$ accepts grants only for epochs that have not started. By
(P3) and (P4), this is indistinguishable from submitting transactions in an
execution of $\prot$.

    \item[A corrupt auditor holds a valid tracing permission for the honest
user.] $\simu$ obtains the pair $(\user, \algo{TX})$, where $\user$ identifies
the honest user and $\algo{TX}$ consists of the payload that $\user$ sent with
their $\IDsubmit$ query. $\simu$ retrieves $(\sk, \utk,\signature) \leftarrow
\regsimu[\user]$ and the substituted epoch key $\ek \leftarrow
\permsimu[(\auditor,\user,\epoch)]$, places that payload in the transaction,
computes the tag as $\FT(\PTK_\user,\ek,\gamma)$ so that the corrupt auditor's
tracing succeeds, and simulates the rest of the transaction as in
Game 4.

  \end{description}

  Both cases are indistinguishable from a real execution, so Game 5 is
indistinguishable from Game 4.

  \paragraph{Game 6.} As Game 5, except $\simu$ also simulates transaction
submission for corrupt users, using the output of $\idfu{\algo{trace}}$'s
$\IDsubmit$ interface.

  When a corrupt user $\user$ submits a transaction with a valid tag, one with
valid proofs that does not appear in the ledger, $\simu$ uses (P4) to extract
$\user$'s witness, and (P1) to identify $\user$ using $\regsimu$.  $\simu$ then
sends an $\IDsubmit$ request on $\user$'s behalf to $\idfu{\algo{trace}}$ and
returns its output. The extracted $\sk$ is that of an honest user only with
negligible probability, since otherwise a reduction that sets that user's $\PSK$ to a
challenge for $\G$ and simulates that user's proofs (P4) would invert $\G$,
which contradicts one-wayness of $\G$. If $\idfu{\algo{trace}}$ accepts, $\simu$ records the
transaction in $\txns[(\user,\epoch)]$.

  This game is indistinguishable from Game 5 unless $\idfu{\algo{trace}}$
rejects a transaction that $\prot$ deems valid, which happens only in one of two
cases:

  \begin{description}

    \item[$\user$ is not registered.] This cannot be the case given that each
entry in $\regsimu$ corresponds to a successful $\IDregister$ call to
$\idfu{\algo{trace}}$.

    \item[$\user$ already submitted $\Max$ transactions in the current epoch.]
By (P4) and the determinism of $\FT$, $\prot$ will not accept a transaction from
$\user$ in this case as the tag will already appear in the ledger.

  \end{description}

  \paragraph{Game 7.} As Game 6, except $\simu$ stops the game if the output of
the $\IDidentify$ interface differs from that of $\prot$'s tracing
functionality.

  $\simu$ stops if one of two events occurs. Event $E_1$ is a coalition of
corrupt auditors and users tracing a transaction submitted by an honest user
during an epoch even though the user did not grant permissions to any corrupt
auditor for that epoch. Event $E_2$ is an honest auditor failing to trace a
transaction of a corrupt user submitted during an epoch despite holding the
granted authorisation. We show each event is negligible.

  Event $E_1$ does not occur, since $\simu$ generates at random the transactions
of honest users during an epoch for which they did not grant tracing
permissions to any corrupt auditor.

  Event $E_2$ occurs only with negligible probability, and this is the
argument for non-repudiation. A transaction $\tx$ from a
corrupt user is recorded in $\txnssimu$ and forwarded to $\idfu{\algo{trace}}$
only if it has a valid tag $\Tag_{\gamma}$, meaning the proof for relation
$\rel_6$ and the proof for relation $\rel_7$ are both valid. By (P4) we extract
a witness from each. From $\rel_6$ we obtain a credential $\signature$ on
$(\G(\sk), \G'(\utk))$ verifying under the transaction authorisation relation,
together with an opening of $\com$ to $\utk$. By (P1) the credential was issued
by the registration authority, so $\utk$ is the tracing key of a registered
user, and by the binding of $\com$ (P2) it is the same $\utk$ as in
$\rel_7$. From $\rel_7$ we obtain the following, which is the tag relation:
  %
  \begin{equation*}
    \Tag_{\gamma} = \FT(\PTK, \ek, \gamma), \quad \PTK = \G'(\utk), \quad \ek
= \FE(\utk, \epoch), \quad 0 \leq \gamma < \Max.
  \end{equation*}
  %
  Chaining these, every transaction the validators accept from a corrupt user
has a tag in the following set, for that user's own certified $\utk$:
  %
  \begin{equation*}
    \{\FT(\G'(\utk),\FE(\utk,\epoch),\gamma)\}_{\gamma \in [0,\Max)}.
  \end{equation*}
  %
  An authorised auditor enumerates exactly this set, so a corrupt user cannot
place a transaction on the ledger that a permitted auditor will miss. It remains
possible that an honest auditor with the right permission might have
accepted a bogus epoch key $\ek^\star$ at grant time, which by (P4) and (P1)
occurs only with negligible probability. So Game 7, which is the ideal world, is
indistinguishable from Game 6. This concludes the proof of~\Cref{thm:txid-bb}.

\end{proof}

\subsection{Proof of \Cref{lem:txid-fe-prf}: pseudorandomness of the epoch PRF}

Recall that the epoch PRF of the algebraic instantiation is the following, for
a hash function $\HE : \{0,1\}^* \to \group{1}$ modelled as a random oracle:
%
\begin{equation*}
  \FE(\utk, \epoch) = \HE(\epoch)^{\utk'}.
\end{equation*}
%
We show that no PPT adversary, given $\PTK$, can distinguish $\FE(\utk, \cdot)$
for a uniform key from a random function $R : \{0,1\}^* \to \group{1}$ with
non-negligible advantage.

\begin{proof}

  Let $\adv$ be a PPT adversary in the experiment of \Cref{exp:prf} for $\FE$,
with advantage $\Adv^{\mathsf{prf}}_{\FE,\adv}(\secparam)$. We construct an
adversary $\simu$ against DDH in $\group{1}$.

  $\simu$ receives a DDH challenge $(\gen, \gen^a, \gen^b, Q)$, where either $Q =
\gen^{ab}$ or $Q$ is uniform in $\group{1}$. It does the following:

  \begin{enumerate}

    \item Set the key implicitly to $\utk'^\star = b$.

    \item On the first random oracle query on $\epoch_i$, draw $r_i, t_i \sample
\Zp$, store them, and set $\HE(\epoch_{i}) = (\gen^a)^{r_i}\cdot\gen^{t_i} =
\gen^{a r_i + t_i}$.

    \item On a PRF query on $\epoch_i$, return $Q^{r_i}\cdot(\gen^{b})^{t_i}$,
for the pair $(r_i, t_i)$ stored for $\epoch_i$.

    \item Output the bit $\adv$ outputs.

  \end{enumerate}

  Since $(r_i, t_i)$ is drawn once per epoch and reused, both oracles answer
repeated queries consistently. We consider the two cases of the challenge.

  If $Q = \gen^{ab}$, the response on $\epoch_i$ is the following, so $\simu$
answers exactly as $\FE$ with key $b$:
  %
  \begin{equation*}
    Q^{r_i}\cdot(\gen^{b})^{t_i} = \gen^{a b r_i + b t_i} = \HE(\epoch_i)^{b}.
  \end{equation*}

  If $Q = \gen^{\omega}$ for uniform $\omega$, the random oracle answer and the response
on $\epoch_i$ are the following pair:
  %
  \begin{equation*}
    (\gen^{a r_i + t_i}, \ \gen^{\omega r_i + b t_i}).
  \end{equation*}
  %
  Its exponents are the image of the uniform vector $(r_i,t_i)$ under the
matrix $\left(\begin{smallmatrix} a & 1 \\ \omega & b\end{smallmatrix}\right)$, which
is invertible whenever $ab \neq \omega$. So each pair is uniform in $\group{1}^2$,
and, as the $(r_i,t_i)$ are drawn independently, the pairs are mutually
independent. The view of $\adv$ is that of a random function, except on the
event $ab = \omega$, which has probability $1/p$.

  The term $\gen^{t_i}$ is needed. Re-randomising with $r_i$ alone would give
the response $\gen^{\omega r_i} = \HE(\epoch_i)^{\omega/a}$, which is again $\FE$, under
key $\omega/a$ rather than $b$, so the two cases would be identically distributed.

  It remains to give $\adv$ the public tracing key. $\simu$ draws $\utk''$
itself and computes $\{W_\gamma\}$ from it. It sets $\gen_2 = \gen^{x}$ for $x
\sample \Zp$, which is distributed as a generator derived by hashing, and
computes the first component as follows:
  %
  \begin{equation*}
    T = (\gen^{b})^{x}\cdot\gen_3^{\utk''} = \gen_2^{b}\cdot\gen_3^{\utk''}.
  \end{equation*}
  %
  So $T$ matches the key $b$ in both cases of the challenge. As $\simu$ also
plays the registration authority, it chooses the remaining BBS+ generators and the issuing key, and
produces every other public value of the protocol.

  So $\simu$ wins the DDH experiment whenever $\adv$ wins, up to the event $ab =
\omega$, which gives the following bound:
  %
  \begin{equation*}
    \Adv^{\mathsf{prf}}_{\FE,\adv}(\secparam) \leq
\Adv^{\mathsf{ddh}}_{\simu}(\secparam) + \frac{1}{p}.
  \end{equation*}
  %
  The bound does not depend on the number of random oracle queries, since a
fresh pair $(r_i, t_i)$ is drawn for each new epoch and reused from then on.

\end{proof}

\subsection{Proof of \Cref{lem:txid-ft-prf}: pseudorandomness of the tag PRF}

Recall that the tag PRF of the algebraic instantiation is the following, for
public parameters $W_\gamma = \ggen_D^{1/(\utk''+\gamma)}$ and a uniform epoch
key $\ek \in \group{1}$:
%
\begin{equation*}
  \FT(\PTK, \ek, \gamma) = \pairing(\ek, W_\gamma), \quad \gamma \in
[0,\Max).
\end{equation*}

\begin{proof}

  Let $\adv$ be a PPT adversary in the experiment of \Cref{exp:prf} for $\FT$,
given $\{W_\gamma\}$ as public parameters. We construct an adversary $\simu$
against $q$-mDBDHI with $q = \Max$.

  $\simu$ receives the following $q$-mDBDHI challenge:
  %
  \begin{equation*}
    \Big(\gen, \ \ggen_D, \ \{\ggen_D^{1/(k+\gamma)}\}_{\gamma\in[0,\Max)}, \
\{\Delta_{\gamma}\}_{\gamma\in[0,\Max)}\Big).
  \end{equation*}
  %
  Either $\Delta_{\gamma} = \pairing(P, \ggen_D^{1/(k+\gamma)})$ for every
$\gamma$ and a hidden $P \sample \group{1}$, or every $\Delta_{\gamma} \sample
\group{T}$ is uniform and independent. $\simu$ does the following:

  \begin{enumerate}

    \item Give $\adv$ the elements $\ggen_D^{1/(k+\gamma)}$ as the public
parameters $W_\gamma$, implicitly setting $\utk''^\star = k$ and $\ek^\star =
P$.

    \item On a PRF query on $\gamma \in [0,\Max)$, return $\Delta_\gamma$.

    \item Output the bit $\adv$ outputs.

  \end{enumerate}

  The challenge supplies every $W_\gamma$ directly, which is exactly what an
auditor receives in the protocol. If the challenge is real, $\simu$ answers
every query with $\FT(\PTK,\ek^\star,\gamma)$. If it is random, $\simu$ answers
with independent uniform elements of $\group{T}$, which is a random function on
$[0,\Max)$. So $\simu$ runs the experiment of \Cref{exp:prf} perfectly in both
cases, which gives the following bound:
  %
  \begin{equation*}
    \Adv^{\mathsf{prf}}_{\FT,\adv}(\secparam) \leq
\Adv^{q\text{-}\mathsf{mdbdhi}}_{\simu}(\secparam).
  \end{equation*}

  The lemma covers one epoch key. Several epochs share $\{W_\gamma\}$ but have
independent epoch keys, so a hybrid over the epochs extends it, losing a factor
of the number of epochs. In each step the reduction embeds the challenge in one
epoch, and samples the keys of the other epochs itself and evaluates $\FT$ under
them from the public $\{W_\gamma\}$.

\end{proof}

\subsection{Proof of \Cref{lem:txid-rel7}: equivalence of $\rel_7$ and $\rel_7'$}\label{sec:rel7-equiv}

Recall the tag relation and its rewritten form:
%
\begin{equation*} \begin{gathered}
  \rel_7 = \{\ \com = \gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot\gen_4^{\openinfo}
\ \wedge \ \ek = \HE(\epoch)^{\utk'} \\ \wedge \ \Tag_\gamma =
\pairing\big(\ek,\ggen_D^{1/(\utk''+\gamma)}\big) \ \wedge \ 0 \leq \gamma <
\Max\ \}, \\
  \rel_7' = \{\ \com = \gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot\gen_4^{\openinfo}
\ \wedge \ U = \HE(\epoch)^s \ \wedge \ \Pi = \pairing(U,\ggen_D)^{\utk'} \\
\wedge \ X = \Tag_\gamma^s \ \wedge \ \Pi = X^{\utk''}\cdot X^{\gamma} \ \wedge
\ \com_\gamma = \gen_3^{\gamma}\cdot\gen_4^{r_\gamma} \ \wedge \ 0 \leq \gamma <
\Max\ \}.
\end{gathered} \end{equation*}
%
We prove the three properties for the interactive Sigma protocol of the tag
proof, and treat the Fiat-Shamir transform at the end.

\begin{proof}

  \paragraph{Correctness.} Let $\witness_7$ satisfy $\rel_7$, and let $s,
r_\gamma \sample \Zp$ and $U$, $\Pi$, $X$ and $\com_\gamma$ be computed as in
the tag proof. The equations for $\com$, $U$, $X$ and $\com_\gamma$, and the
range of $\gamma$, hold by construction. The equation for $\Pi$ holds as
follows:
  %
  \begin{equation*}
    \pairing(U,\ggen_D)^{\utk'} = \pairing(\HE(\epoch)^{s\utk'},\ggen_D) =
\pairing(\ek^{\,s},\ggen_D) = \Pi.
  \end{equation*}
  %
  For the tag equation, the definition of the tag gives the following:
  %
  \begin{equation*}
    \Tag_\gamma = \pairing\big(\ek, \ggen_D^{1/(\utk''+\gamma)}\big), \qquad
\Tag_\gamma^{\utk''+\gamma} = \pairing(\ek,\ggen_D).
  \end{equation*}
  %
  So the following holds:
  %
  \begin{equation*}
    X^{\utk''}\cdot X^{\gamma} = \big(\Tag_\gamma^{\utk''+\gamma}\big)^{s} =
\pairing(\ek,\ggen_D)^{s} = \pairing(\ek^{\,s},\ggen_D) = \Pi.
  \end{equation*}

  \paragraph{Special soundness.} Let two accepting transcripts of the tag proof
share a first message and have distinct challenges. The standard extractor
outputs $(\utk', \utk'', \openinfo, s, \gamma, r_\gamma)$ from the differences
of the responses. Each response is shared between the verification equations
in which its value appears: $\theta_1$ between the first and third, $\theta_2$
between the first and fifth, $\theta_s$ between the second and fourth, and
$\theta_\gamma$ between the fifth and sixth. So each extracted value is the same
in every equation of $\rel_7'$ in which it appears. In particular, the $\utk''$
of the fifth equation is the value committed in $\com$, and its $\gamma$ is the
value committed in $\com_\gamma$. Without this sharing, the fifth equation alone
would fix only the sum $\utk''+\gamma$, and a prover could shift $\utk''$ to
$\utk''+\delta$ and $\gamma$ to $\gamma-\delta$.

  The extracted values satisfy $\rel_7'$, and we derive a witness for $\rel_7$
from them. The epoch key is not extracted, and we define $\ek \leftarrow
\HE(\epoch)^{\utk'}$, which gives the second equation of $\rel_7$. The first
equation of $\rel_7$ is the first equation of $\rel_7'$. The range proof is
sound for the same $\com_\gamma$, so by binding of $\com_\gamma$ the extracted
$\gamma$ lies in $[0,\Max)$. It remains to show the tag equation. From the
second and third equations of $\rel_7'$, and from the fourth and fifth, the
following hold:
  %
  \begin{equation*}
    \Pi = \pairing(\HE(\epoch)^{s\cdot\utk'},\ggen_D) = \pairing(\ek,
\ggen_D)^{s}, \qquad \Pi = \big(\Tag_\gamma^{s}\big)^{\utk''+\gamma} =
\big(\Tag_\gamma^{\utk''+\gamma}\big)^{s}.
  \end{equation*}
  %
  The verifier rejects $U = 1_{\group{1}}$, so $s \neq 0$, as $\HE(\epoch)$
generates $\group{1}$ with overwhelming probability over the random oracle.
Cancelling $s$ gives the following:
  %
  \begin{equation}\label{eq:rel7prime-core}
    \pairing(\ek, \ggen_D) = \Tag_\gamma^{\utk''+\gamma}.
  \end{equation}
  %
  The verifier also rejects $\Pi = 1_{\group{T}}$. With $s \neq 0$, this gives
$\pairing(\ek,\ggen_D) \neq 1_{\group{T}}$, so by \Cref{eq:rel7prime-core}
$\utk'' + \gamma \neq 0 \bmod p$, and inverting the exponent gives the tag
equation of $\rel_7$:
  %
  \begin{equation*}
    \Tag_\gamma = \pairing(\ek,\ggen_D)^{1/(\utk''+\gamma)} =
\pairing\big(\ek,\, \ggen_D^{1/(\utk''+\gamma)}\big).
  \end{equation*}

  \paragraph{Honest-verifier zero knowledge.} We give a simulator $\simu$ whose
output $(U, \Pi, X,\allowbreak \com_\gamma,\allowbreak \algoproof_7')$ is computationally
indistinguishable from an honest proof, under the DDH assumption in $\group{1}$,
also for a distinguisher that holds $\ek$.

  $\simu$ samples $s, r_\gamma \sample \Zp$ and $Q \sample \group{1}$, fixes an
arbitrary $\gamma^\star \in [0,\Max)$, and computes the following:
  %
  \begin{equation*}
    U = \HE(\epoch)^{s}, \quad \Pi = \pairing(Q, \ggen_D), \quad X =
\pairing(Q, W_\gamma), \quad \com_\gamma =
\gen_3^{\gamma^\star}\cdot\gen_4^{r_\gamma}.
  \end{equation*}
  %
  In an honest proof, $\Pi$ and $X$ are the same expressions with $Q =
\ek^{\,s}$. So the only difference is that $Q$ is uniform instead of $\ek^{\,s}$,
and a distinguisher between the two gives a DDH distinguisher in $\group{1}$.
Given a challenge $(\gen, \gen^a, \gen^b, Q)$, the reduction programs the random
oracle and sets the following:
  %
  \begin{equation*}
    \HE(\epoch) = \gen, \qquad \ek = \gen^a, \qquad U = \gen^b.
  \end{equation*}
  %
  It computes $\Pi$ and $X$ from $Q$ as above. It computes $\PTK$ and the epoch
keys of other epochs, which also depend on $\utk'$, from $\gen^a$ by programming
$\gen_2$ and $\HE$ at other epochs to known powers of $\gen$. It knows $\ek =
\gen^a$, so it can also give $\ek$ to the distinguisher. If $Q = \gen^{ab}$, this
is an honest proof, and if $Q$ is uniform, it is the simulated one. For the up
to $\Max$ proofs per epoch, which share $\ek$, the reduction derives one
challenge per proof from $(\gen, \gen^a, \gen^b, Q)$ by random
self-reducibility of DDH. The simulator uses $W_\gamma$, so it is given the
index $\gamma$ as well as the instance. This suffices where the lemma is used,
since the simulator of \Cref{thm:txid-bb} assigns honest users' indices
itself.

  $\simu$ then fixes $(U, \Pi, X, \com_\gamma)$ and runs the honest-verifier
simulator of the Sigma protocol. It samples the challenge $c$ and the six
responses uniformly from $\Zp$, and solves the verification equations for the
first message:
  %
  \begin{gather*}
    A = \gen_2^{\theta_1}\cdot\gen_3^{\theta_2}\cdot\gen_4^{\theta_h}\cdot
\com^{-c}, \qquad B = \HE(\epoch)^{\theta_s}\cdot U^{-c}, \qquad M =
\pairing(U,\ggen_D)^{\theta_1}\cdot \Pi^{-c}, \\
    C = \Tag_\gamma^{\theta_s}\cdot X^{-c}, \qquad F =
X^{\theta_2+\theta_\gamma}\cdot\Pi^{-c}, \qquad A_\gamma =
\gen_3^{\theta_\gamma}\cdot\gen_4^{\theta_r}\cdot \com_\gamma^{-c}.
  \end{gather*}
  %
  The simulated proof satisfies every verification equation, and since $c$ and
the responses are uniform and independent, it is distributed identically to an
honest one with the same $(U, \Pi, X, \com_\gamma)$.

  Finally, $\simu$ runs the zero-knowledge simulator of
Bulletproofs on $\com_\gamma$~\cite{SP:BBBPWM18}. As $r_\gamma$ is uniform and
$\gen_4$ is independent of $\gen_3$, $\com_\gamma$ is a perfectly hiding
commitment, so a commitment to $\gamma^\star$ is distributed identically to a
commitment to $\gamma$.

  \paragraph{The Fiat-Shamir transform.} The non-interactive proof is sound and
zero knowledge as in \Cref{sec:prelims-sigma}, with the extractor and the
simulator above. Programming the random oracle fails only with negligible
probability, since $A$ contains a fresh uniform group element.

\end{proof}

\subsection{Proof of \Cref{lem:txid-rel6}: equivalence of $\rel_6$ and $\rel_6'$}\label{sec:rel6-equiv}

Recall that a valid BBS+ signature $(e, r, E)$ on the user's values has $E =
b^{1/(z+e)}$, for the base $b$ of the credential, and the rewritten relation:
%
\begin{equation*} \begin{gathered}
  b = \gen_0\cdot\gen_1^{\sk}\cdot\gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot
\gen_4^{r}, \\
  \rel_6' = \{\ \com = \gen_2^{\utk'}\cdot\gen_3^{\utk''}\cdot\gen_4^{\openinfo}\
\wedge \ \pairing(E', \ggen_Z) = \pairing(\bar{E}, \ggen) \\ \wedge \ \bar{E}/d
= E'^{-e}\cdot\gen_4^{r_2} \ \wedge \ (\gen_0\cdot\com)^{-1} =
\gen_1^{\sk}\cdot d^{-r_3}\cdot\gen_4^{r''}\ \}.
\end{gathered} \end{equation*}

\begin{proof}

  \paragraph{Correctness.} Let $E'$, $d$ and $\bar{E}$ be computed as in the
transaction authorisation proof. The first equation of $\rel_6'$ is the opening
of $\com$. Substituting $d$ into $\bar{E}$, and using $b = E^{z+e}$, gives the
following:
  %
  \begin{equation*}
    \bar{E} = E'^{-e}\cdot b^{r_1} = E'^{-e}\cdot E'^{z+e} = E'^{z}.
  \end{equation*}
  %
  This gives the second equation:
  %
  \begin{equation*}
    \pairing(E',\ggen_Z) = \pairing(E'^{z},\ggen) = \pairing(\bar{E},\ggen).
  \end{equation*}
  %
  The third equation is the definition of $\bar{E}$, rearranged. For the
fourth, raising $d$ to $r_3 = 1/r_1$ gives the following:
  %
  \begin{equation*}
    d^{r_3} = b\cdot\gen_4^{-r_2 r_3} = \gen_0\cdot\gen_1^{\sk}\cdot
\gen_2^{\utk'}\cdot\gen_3^{\utk''} \cdot\gen_4^{r - r_2 r_3}.
  \end{equation*}
  %
  Taking inverses, and using $-(r - r_2 r_3) + r'' = -\openinfo$, gives the
fourth equation:
  %
  \begin{equation*}
    \gen_1^{\sk}\cdot d^{-r_3}\cdot\gen_4^{r''} =
\gen_0^{-1}\cdot\gen_2^{-\utk'}\cdot\gen_3^{-\utk''}\cdot\gen_4^{-\openinfo} =
(\gen_0\cdot\com)^{-1}.
  \end{equation*}

  \paragraph{Special soundness.} The verifier checks $E' \neq 1_{\group{1}}$
and the pairing equation directly on public data, so $\bar{E} = E'^{z}$. From
two accepting transcripts of the transaction authorisation proof that share a
first message and have distinct challenges, the standard extractor outputs
$(\utk', \utk'', \openinfo, e, r_2, \sk, r_3, r'')$ satisfying the first, third
and fourth equations of $\rel_6'$. Substituting $\bar{E} = E'^{z}$ into the
third equation gives the following:
  %
  \begin{equation*}
    E'^{z+e} = d\cdot\gen_4^{r_2}.
  \end{equation*}
  %
  Raising both sides to $r_3$ and substituting $d^{r_3}$ from the fourth
equation gives the following:
  %
  \begin{equation*}
    \big(E'^{r_3}\big)^{z+e} = \gen_0\cdot\gen_1^{\sk}\cdot\gen_2^{\utk'}\cdot
\gen_3^{\utk''}\cdot\gen_4^{\openinfo + r'' + r_2 r_3}.
  \end{equation*}
  %
  So $(e, \openinfo + r'' + r_2 r_3, E'^{r_3})$ is a BBS+ signature on $\sk$
and on the values committed in $\com$. An extracted $r_3 = 0$ would turn the
fourth equation into a nontrivial discrete logarithm relation among $\gen_0,
\ldots, \gen_4$, with $\gen_0$ in it, which breaks the DL assumption since the
generators are derived by hashing. The check $E' \neq 1_{\group{1}}$
prevents a degenerate transcript from being accepting: with $E' = 1_{\group{1}}$
and $\bar{E} = 1_{\group{1}}$, the pairing equation holds for every key, and
$E'^{r_3}$ is not a signature.

  \paragraph{Honest-verifier zero knowledge.} $E'$ is uniform in $\group{1}$, as
$r_1 \sample \Zp^*$ is fresh for each transaction, and $d$ is uniform and
independent of $E'$, as $r_2 \sample \Zp$ is fresh. $\bar{E} = E'^{z}$ is
determined by $E'$ and the secret key $z$ of the registration authority, which
the simulator knows as it plays the registration authority. So $(E', \bar{E}, d)$ reveals nothing about
$\signature$. The simulator samples these three values in the same way, and
simulates the Sigma protocol of the transaction authorisation proof as for the
tag proof, by sampling $c$ and $\vec{\theta}$ and solving each verification
equation for $t_1$, $t_2$, and $t_3$. It handles the Fiat-Shamir transform as in
\Cref{sec:rel7-equiv}.

\end{proof}

\subsection{Proof of \Cref{thm:inst}: security of the algebraic instantiation}\label{sec:txid-inst-sec}

By \Cref{thm:txid-bb}, it suffices to show that the algebraic instantiation
has (P1) to (P5).

\begin{proof}

\begin{description}

  \item[(P1).] $\DS$ is the BBS+ signature scheme of~\Cref{prim:bbs}, existentially unforgeable
under the $q$-SDH assumption of \Cref{asm:qsdh-bbs}, provided the signer signs
group elements only with a proof of knowledge of their representation, which
$\algoproof_4$ in $\IDregister$ supplies.

  \item[(P2).] $\Com$ is the Pedersen commitment scheme of~\Cref{prim:pedersen},
perfectly hiding, and binding under the DL assumption in $\group{1}$, also
against the registration authority, since $\IDgen$ derives $\gen_2$, $\gen_3$
and $\gen_4$ by hashing to the group.

  \item[(P3).] $\FE$ is pseudorandom under the DDH assumption in $\group{1}$,
with $\HE$ a random oracle, by \Cref{lem:txid-fe-prf}, and $\FT$ under the
$q$-mDBDHI assumption with $q = \Max$, by \Cref{lem:txid-ft-prf}. Both hold
against a distinguisher holding $\PTK$, as Game 4 and Game 5 need.
\Cref{lem:txid-ft-prf} gives it only $\{W_\gamma\}$, but from Game 4 on $T$ is
uniform and independent of $\utk''$, so the reduction samples $T$ itself.

  \item[(P4).] The proofs for $\rel_4$, $\rel_5$, $\rel_6'$ and $\rel_7'$ are
Sigma protocols with the Fiat-Shamir transform and $\hash$ a random oracle,
together with Bulletproofs, which are sound under the DL assumption in
$\group{1}$ and simulation extractable~\cite{SP:BBBPWM18,EC:DaoGru23}. By
\Cref{lem:txid-rel7,lem:txid-rel6}, they prove $\rel_7$ and $\rel_6$. Each
Sigma protocol has special soundness, honest-verifier zero knowledge and
quasi-unique responses under the DL assumption among the hashed generators, and
hashes its whole statement, so it is zero knowledge and simulation extractable
in the random oracle model, as in \Cref{sec:prelims-sigma}~\cite{INDOCRYPT:FKMV12},
with extraction by rewinding in the standalone model. In the epoch key proof,
$\hash$ derives the $\lambda_\gamma$ from $\{W_\gamma\}$, so a malformed element
passes the batched equation with probability at most $q_{\hash}/p$ for
$q_{\hash}$ hash queries~\cite{EC:BelGarRab98}. Later grants prove the first
two equations of $\rel_5$ against the same certified $T$, which binds them to
one pair $(\utk',\utk'')$.

  \item[(P5).] Assumed of the network.

\end{description}

Combining (P1) to (P5) with~\Cref{thm:txid-bb} gives~\Cref{thm:inst}.

\end{proof}

\subsection{Proof of \Cref{thm:hash-inst}: security of the hash-based instantiation}\label{sec:txid-hash-inst-sec}

As for \Cref{thm:inst}, we show that each building block of the hash-based
instantiation has the property \Cref{thm:txid-bb} needs.

\begin{proof}

\begin{description}

  \item[(P1).] $\DS$ is the BBS+ signature scheme, existentially unforgeable
under the $q$-SDH assumption.

  \item[(P2).] $\Com$ is the Pedersen commitment scheme, perfectly hiding, and
computationally binding under the DL assumption in $\group{1}$.

  \item[(P3).] $\HE$ and $\HT$ are the MiMC block cipher, keyed by $\utk$ and
by the epoch key, so $\FE$ and $\FT$ are pseudorandom by the assumption that
MiMC is a pseudorandom permutation against a distinguisher holding
$\gen_2^{\utk}$, and the switching lemma. This is the public tracing key, which
depends on the key of $\FE$. $\FT$ is keyed by the epoch key, which is uniform
once $\FE$ is replaced, so the public tracing key gives a distinguisher of $\FT$
nothing.

  \item[(P4).] The proofs for $\rel_4$ and $\rel_6$ are Sigma protocols with
the Fiat-Shamir transform applied, as in the algebraic instantiation. For
$\rel_5$ and $\rel_7$, the zk-SNARK proof and the linking proof together prove
the relations as the construction states them. From a verifying transaction,
knowledge soundness of the zk-SNARK with commitments extracts $(\utk, \mu,
\gamma)$ for the circuit, and special soundness of the linking proof extracts
an opening $(\utk^\star, \mu^\star, \openinfo^\star)$ of $D$ and $\com$. If
$\utk \neq \utk^\star$, these are two openings of $D$, which give $\log_{K_0}
K_1$, which no party knows after an honest setup. Binding of $\com$ then ties
$\utk^\star$ to the certified key. The same argument covers grants, with the
public tracing key in place of $\com$. Hiding is unaffected, since $D$ is a
uniform element of $\group{1}$, fresh for each proof, and the linking proof is
zero knowledge.

  We need simulation extractability in the sense of \Cref{exp:simext}, which
excludes only statement and label pairs on which a proof was simulated. Proofs
of the zk-SNARK of Groth can be rerandomised, so from one proof anyone can
produce another for the same statement, and this notion allows it. The plain
zk-SNARK is simulation extractable in this sense in the algebraic group
model~\cite{FC:BKSV21}. This result does not cover the commitment extension, so
\Cref{thm:hash-inst} assumes it. The zk-SNARK has no label of its own. Its label is bound instead by the linking
proof, whose Fiat-Shamir context contains the zk-SNARK proof, and by the
transaction authorisation proof or the registration proof, which signs both.

  \item[(P5).] Assumed of the network, as in the generic construction.

\end{description}

Combining (P1) to (P5) with~\Cref{thm:txid-bb} gives~\Cref{thm:hash-inst}.

\end{proof}
