\section{Evaluation}\label{sec:tsps-evaluation}

\begin{outline}
  \item implementation on MP-SPDZ, which gives the $\Zp$ interfaces; we add
group element sharings with authentication information and $\algo{ExpGrp}$ with
mixed triples, over BLS12-381 with RELIC (cite CCS:Keller20, relictoolkit)
  \item run with ATLAS (honest majority, Shamir) and MASCOT (dishonest majority,
triples from oblivious transfer) (cite C:GLOPS21, CCS:KelOrsSch16); any protocol
with the interfaces would do, we take one per corruption setting (robustness vs
resilience to key compromise, as in the introduction)
  \item caveat: MP-SPDZ's ATLAS is semi-honest only, so ATLAS timings are for
semi-honest security (cite CCS:Keller20)
  \item caveat: neither protocol proven adaptively secure, so implemented schemes
are statically secure, where the proof has no loss
  \item baselines: centralised $\AGHO$ and $\KPW$, and the two existing threshold
SPS schemes, in Go with gnark-crypto and a trusted dealer (cite AC:CKPSS23,
PKC:MMSST24, gnark-crypto)
\end{outline}

\begin{outline}
  \item setup: $\ell = 2$ elements of $\group{1}$; ATLAS at $n = 2t+1$, MASCOT at
$t = n-1$; tables at $n = 5$
  \item one thread per party, all parties on one MacBook Air (Apple M2, 16~GB
RAM), authenticated channels on that machine
  \item each timed call starts from empty preprocessing, so offline phase and key
generation include making their triples
  \item median of 100 repetitions after 10 warm-up calls, party $p_0$; IQR within
5\% of the median for all but four measurements, within 16\% for all
  \item point to \Cref{tab:tsps-comp} (parameters) and
\Cref{tab:tsps-benchmarks,tab:tsps-baselines-time,tab:tsps-comms,tab:tsps-sizes}
(times, communication, sizes)
\end{outline}

\begin{outline}
  \item online phase sends nothing in all four settings, takes 0.36--1.8~ms;
comparable to centralised signing (0.84~ms $\AGHO$, 2.0~ms $\KPW$)
  \item all interaction in the offline phase and key generation; MASCOT far more
expensive than ATLAS there: threshold $\AGHO$ offline 31~ms vs 2.1~ms, over a
megabyte per party vs half a kilobyte
  \item batching 16 states: 8.2~ms per signature under MASCOT, 1.3~ms under ATLAS
  \item \Cref{fig:tsps-n-times,fig:tsps-n-comm}: communication linear in $n$,
online phase below 3~ms up to eleven parties
\end{outline}

\begin{outline}
  \item existing threshold SPS schemes have no offline phase: each signer sends
one partial signature (96 or 384 bytes) to the combiner; partial signing 2.1~ms
and 1.3~ms vs 0.72~ms and 1.8~ms for our online phase with MASCOT
(\Cref{fig:tsps-baselines})
  \item our schemes move the extra cost ahead of the message, off the critical
path
  \item Crites et al.\ only sign messages given in both source groups with the
same discrete logarithm, so can't sign a commitment or public key whose discrete
logarithm nobody knows (cite AC:CKPSS23)
  \item vs Mitrokotsa et al.\ (cite PKC:MMSST24): threshold $\AGHO$ has three
group elements instead of seven, verifies in 2.9~ms vs 4.2~ms, but GGM instead of
SXDH
  \item threshold $\KPW$ has no efficiency advantage, but keys, signatures and
verification are those of $\KPW$, so an existing $\KPW$ deployment can distribute
its signer without changing any verifier
\end{outline}
