\section{Structure-Preserving Signatures}\label{sec:SPS}

\paragraph{Notation.} Let $[n]$ denote the integer interval $[1,\ldots,n]$.
Let $\group{1}$, $\group{2}$, and $\group{T}$ be three cyclic groups of large
prime order $p$ that admit a non-degenerate bilinear pairing $e \colon
\group{1} \times \group{2} \rightarrow \group{T}$, with $\gen$ and $\ggen$
generators of $\group{1}$ and $\group{2}$ respectively. We denote elements in
$\group{1}$ and $\group{2}$ by upper-case letters, e.g. $G$ and $\gggen{G}$,
and elements of $\Zp$ by lower-case letters. For $\vec{\ggen} = (\ggen_1,
\ldots, \ggen_l)$, we write $e(\vec{\gen}, \vec{\ggen})$ for the
product $\prod_{i=1}^l e(\gen_i, \ggen_i)$.

Let $x \in \Zp$ be a secret value additively shared between $n$ parties such
that any $t+1$ parties can reconstruct it with the help of a pre-defined
linear combination. We denote such a sharing $\llbracket x \rrbracket$: the
vector $(x_1, \ldots, x_n)$ where $x_i$ is the share held by the
$i^{\mathrm{th}}$ party. For $\vec{x} = (x_1, \ldots, x_l) \in \Zp^l$, we
write $\llbracket \vec{x} \rrbracket$ for the vector $(\llbracket x_1
\rrbracket, \ldots, \llbracket x_l \rrbracket)$.

In this section we describe two structure-preserving signatures. The first is
optimal in terms of size, and existentially unforgeable in the generic group
model (GGM)~\cite{C:AGHO11}. The second produces signatures with more group
elements, but is existentially unforgeable under the DDH
assumption~\cite{C:KilPanWee15}. For each, we also sketch how it can be thresholdised;
Section~\ref{sec:schemes} turns these sketches into full descriptions,
building on the MPC functionalities formalised in Section~\ref{sec:MPC}.

\subsection{Optimal re-randomisable structure-preserving signatures in the
GGM}\label{sec:sps-ggm}

Abe, Groth, Haralambiev, and Ohkubo introduced the first optimal-size
structure-preserving signature scheme for asymmetric
pairings~\cite{C:AGHO11}.

\begin{primitivebox}{Optimal structure-preserving signatures (Abe, Groth,
  Haralambiev, and Ohkubo)}{sps-ggm}

  \begin{description}

    \item[$(\pk, \sk) \sample \algo{KeyGen}(\secparam, l)$ :] On input security
      parameter $\secparam$ and vector length $l$, do:

      \begin{enumerate}

        \item Sample $\vec{u} = (u_1, \ldots, u_l) \sample (\Zp^*)^l$ and $v
          \sample \Zp$.

        \item Compute $\vec{\gggen{U}} = (\gggen{U}_1, \ldots, \gggen{U}_l) = (u_1
          \ggen, \ldots, u_l \ggen) \in \group{2}^l$ and ${V} = v
          \gen \in \group{1}$.

        \item Return $\pk = (\vec{\gggen{U}}, {V})$ and $\sk = (\vec{u}, v)$.

      \end{enumerate}

    \item[$\sigma \sample \algo{Sign}(\sk, \vec{{M}})$ :] On input secret key
      $\sk = (\vec{u}, v)$ and vector $\vec{{M}} = ({M}_1, \ldots,
      {M}_l) \in \group{1}^l$, do:

      \begin{enumerate}

        \item Sample $r \sample \Zp^*$.

        \item Return $\sigma = (\gggen{R}, \gggen{S}, {T})$ such that:
          %
          \begin{equation*}
          %
            \gggen{R} = \tfrac{1}{r}\ggen, \qquad \gggen{S} = v\gggen{R}, \qquad {T} =
            r\left(\gen - \vec{u}\vec{{M}}\right).
          %
          \end{equation*}

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \algo{Verify}(\pk, \vec{{M}}, \sigma)$ :] On input
      signature $\sigma = (R, S, T) \in \group{2}^2 \times \group{1}$ and
      vector $\vec{M} \in \group{1}^l$, return 1 if the following holds, and
      0 otherwise:
      %
      \begin{equation}
      %
        e({V}, \gggen{R}) = e(\gen, \gggen{S}) \ \wedge \ e({T},
        \gggen{R})\prod_{i=1}^le({M}_i, \gggen{U}_i) = e(\gen, \ggen).
      %
      \end{equation}
      \label{eq:abe-ver}

  \end{description}

\end{primitivebox}

This signature is existentially unforgeable in the GGM~\cite{C:AGHO11}.

\paragraph{Thresholdising the signature.} The starting point for the
threshold variant of this signature is \emph{$t$-additive secret sharing},
which distributes the secret key $\sk = (u_1, \ldots, u_l, v)$ among the
signers such that any $t+1$ signers can jointly recover it by computing a
pre-defined linear function of their shares, where $t$ upper bounds the
number of corrupt signers~\cite{C:AGHO11}. To sign, the signers first come together to
additively secret-share a random value $r$. Once $r$ is shared, they use MPC
to compute additive shares of $1/r$ and of the products $u_i r$ for $i \in
[l]$. Given a vector of messages $({M}_1, \ldots, {M}_l)$, each signer
then computes its signature share as:
%
\begin{equation*}
%
  \llbracket \gggen{R} \rrbracket = \llbracket \tfrac{1}{r}\rrbracket\ggen \ ; \
  \llbracket \gggen{S} \rrbracket = {\llbracket \tfrac{v}{r}\rrbracket}\ggen \ ;
  \ \llbracket {T} \rrbracket = \llbracket r\rrbracket \gen -
  \sum_{i=1}^l \llbracket ru_i\rrbracket {{M}_i}.
%
\end{equation*}
%
A party receiving $t+1$ distinct shares combines them and checks whether the
resulting signature is valid.

In the \emph{honest majority} setting ($t < n/2$, where $n$ is the number of
signers), the signature can always be computed from the shares of honest
signers alone. In the \emph{dishonest majority} setting ($t > n/2$),
robustness is no longer guaranteed, but if the underlying MPC supports
identifiable aborts, so does the threshold signature: corrupt parties that
contribute bogus shares are eventually caught. We stress that the sharing of
$r$, the computation of $1/r$, and the products $v/r$ and $u_i r$ for $i \in
[l]$ can all be performed before the messages to be signed are known, i.e.
\emph{offline}. The remaining computation, performed once the messages are
known (\emph{online}), is purely local, and is equivalent to the computation
of the original signature.

\subsection{Structure-preserving signatures under
DDH}\label{sec:sps-kiltz}

Kiltz, Pan, and Wee introduced a structure-preserving signature scheme that
is existentially unforgeable under the DDH assumption~\cite{C:KilPanWee15}.

\begin{primitivebox}{Structure-preserving signatures under DDH (Kiltz, Pan,
  and Wee)}{sps-kiltz}

  \begin{description}

    \item[$(\pk, \sk) \sample \algo{KeyGen}(\secparam, l)$ :] On input security
      parameter $\secparam$ and vector length $l$, do:

      \begin{enumerate}

        \item Sample column vectors $\vec{a} = (1, a)^{\mathsf{T}}$ and $\vec{b} =
          (1, b)^{\mathsf{T}}$, for uniformly random $a, b \in \Zp$, together with
          uniformly random matrices $\mathbf{k} \in \Zp^{(l+1)\times 2}$,
          $\mathbf{c} \in \Zp^{2\times 2}$, and $\mathbf{d} \in \Zp^{2\times 2}$.

        \item Compute $\vec{u} = \mathbf{k}\vec{a}$, $\vec{v} = \mathbf{c}\vec{a}$,
          $\vec{w} = \mathbf{d}\vec{a}$, $\vec{x} = \vec{b}^{\mathsf{T}}\mathbf{c}$, and
          $\vec{y} = \vec{b}^{\mathsf{T}}\mathbf{d}$.

        \item Compute $\vec{{B}} = \gen(1, b)$, $\vec{{X}} =
          \gen\vec{x}$, and $\vec{{Y}} = \gen\vec{y}$.

        \item Compute $\vec{\gggen{A}} = \ggen(1, a)$, $\vec{\gggen{U}} =
          \ggen\vec{u}$, $\vec{\gggen{V}} = \ggen\vec{v}$, and $\vec{\gggen{W}} =
          \ggen\vec{w}$.

        \item Return $\sk = (\mathbf{k}, \vec{{B}}, \vec{{X}}, \vec{{Y}})$
          and $\pk = (\vec{\gggen{A}}, \vec{\gggen{U}}, \vec{\gggen{V}}, \vec{\gggen{W}})$.

      \end{enumerate}

    \item[$\sigma \sample \algo{Sign}(\sk, \vec{{M}})$ :] On input secret key
      $\sk = (\mathbf{k}, \vec{{B}}, \vec{{X}}, \vec{{Y}})$ and vector
      $\vec{{M}} = ({M}_1, \ldots, {M}_l)$, do:

      \begin{enumerate}

        \item Sample $r, s \sample \Zp^*$.

        \item Compute:
          %
          \begin{align*}
          %
            \gggen{Q} &= s\ggen, \qquad \vec{{R}} = r\vec{{B}}, \qquad
            \vec{{S}} = rs\vec{{B}}, \\ \vec{{T}} &= (\gen,
            \vec{{M}})\mathbf{k} + r (\vec{{X}}+s\vec{{Y}}).
          %
          \end{align*}

        \item Return $\sigma = (\gggen{Q}, \vec{{R}}, \vec{{S}},
          \vec{{T}})$.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \algo{Verify}(\pk, \vec{{M}}, \sigma)$ :] On input
      signature $\sigma =(\gggen{Q}, \vec{{R}}, \vec{{S}}, \vec{{T}}) \in
      \group{2}\times\group{1}^6$ and vector $\vec{M}$ of $l$ messages in
      $\group{1}$, return 1 if the following holds, and 0 otherwise:
      %
      \begin{equation}
      %
        e(\vec{{T}}, \vec{\gggen{A}}) = e((\gen, \vec{{M}}),
        \vec{\gggen{U}})\, e(\vec{{R}},\vec{\gggen{V}})\, e(\vec{{S}},
        \vec{\gggen{W}}) \ ; \qquad e({R}, \gggen{Q}) = e({S}, \ggen).
      %
      \end{equation}
      \label{eq:kiltz-ver}

  \end{description}

\end{primitivebox}

\paragraph{Thresholdising the signature.} As with the scheme of Abe, Groth,
Haralambiev, and Ohkubo, we start from a $t$-additive secret sharing of $\sk
= (\mathbf{k}, \vec{{B}}, \vec{{X}}, \vec{{Y}})$ among the
signers~\cite{C:AGHO11}. To sign a vector of messages
$\vec{M}$, the signers first come together to additively secret-share random
values $(r, s)$. Once $(r, s)$ are shared, they use MPC to compute additive
shares $\llbracket s\ggen\rrbracket = \llbracket s\rrbracket \ggen$,
$\llbracket r\vec{{B}}\rrbracket$, $\llbracket rs\vec{{B}} \rrbracket$,
$\llbracket r\vec{{X}} \rrbracket$, and $\llbracket rs\vec{{Y}}
\rrbracket$. Given a vector of messages $({M}_1, \ldots, {M}_l)$, a signer
computes the share $\llbracket (\gen, \vec{{M}})\mathbf{k}\rrbracket =
(\gen, \vec{{M}}) \llbracket \mathbf{k}\rrbracket$, and outputs its
signature share as:
%
\begin{align*}
%
  \llbracket \gggen{Q}\rrbracket &= \llbracket s\rrbracket \ggen \ ; \
  \llbracket\vec{{R}}\rrbracket = \llbracket r\vec{{B}}\rrbracket \ ; \
  \llbracket\vec{{S}}\rrbracket = \llbracket rs\vec{{B}} \rrbracket \ ;
  \\ \llbracket\vec{{T}}\rrbracket &= (\gen,
  \vec{{M}})\llbracket\mathbf{k}\rrbracket + \llbracket r \vec{{X}}
  \rrbracket+\llbracket rs\vec{{Y}}\rrbracket.
%
\end{align*}
%
As before, a party receiving $t+1$ distinct shares combines them and checks
whether the resulting signature is valid.

Most of this computation, namely $\llbracket \gggen{Q}\rrbracket$, $\llbracket
\vec{{R}}\rrbracket$, $\llbracket \vec{{S}}\rrbracket$, $\llbracket r
\vec{{X}} \rrbracket$, and $\llbracket rs\vec{{Y}}\rrbracket$, can again
be performed offline, before the messages are known. Once the messages are
known, the signers need only \emph{locally} compute $(\gen,
\vec{{M}})\llbracket\mathbf{k}\rrbracket$, so the online phase remains cheap
relative to the offline phase.
\section{Secure Multiparty Computation}\label{sec:MPC}

In this section, we describe the ideal functionalities we assume for secure
MPC over a prime order field $\Zp$ and a generic prime order group $\G$.
Section~\ref{sec:eval} then summarises concrete instantiations of
these ideal functionalities in the honest- and dishonest-majority settings,
via ATLAS and MASCOT respectively.

Our constructions of threshold structure-preserving signatures build upon
existing frameworks for secure MPC over inputs in $\Zp$. Concretely, we assume
some realisation of the ideal MPC functionality over $\Zp$ described in
Figure~\ref{fig:ideal-func}, where $\mathcal{H}$ and $\Cor$ denote the sets of honest
and corrupted parties respectively. Unless otherwise specified, we assume
security against malicious corruption of parties. Recall that $\llbracket x
\rrbracket$, for $x \in \Zp$, denotes that $x$ is secret-shared: no individual
party has access to $x$, but each party holds some share $x_i$ of $x$ (for
simplicity, we assume this notation incorporates the additional
authentication components required for malicious security).

\paragraph{Linearity-preservation.} Fundamentally, we require that the
secret-shared representation $\llbracket x \rrbracket$ is
linearity-preserving: for any $x,y,z,\alpha,\beta\in \Zp$ such that $u =
\alpha\cdot x + \beta \cdot y + z$, given secret shares $\llbracket x
\rrbracket$ and $\llbracket y \rrbracket$ and public values $z,\alpha,\beta$,
the parties can compute a secret sharing of $u$ ``for free'' as
\[\llbracket u \rrbracket = \alpha\cdot \llbracket x \rrbracket + \beta \cdot
\llbracket y \rrbracket + z.\] Since we assume malicious security, this
property must also be preserved for any additional authentication
components, which we otherwise abstract out for ease of exposition.

\paragraph{Functionalities for secure MPC in $\Zp$.} Figure~\ref{fig:ideal-func}
formally describes the ideal functionalities we assume for secure MPC in
$\Zp$. We assume a randomised functionality that generates a secret-shared
representation $\llbracket r \rrbracket$ for a randomly sampled value $r\gets
\Zp$, together with four deterministic functionalities, described below
(all arithmetic is in $\Zp$):

\begin{enumerate}

	\item A functionality that adds secret-shared inputs: given $\llbracket x
    \rrbracket$ and $\llbracket y \rrbracket$, produces $\llbracket z
    \rrbracket$ such that $z = x + y$. By linearity-preservation, this comes
    for free, as it can be performed locally by each party.

	\item A functionality that multiplies secret-shared inputs: given
    $\llbracket x \rrbracket$ and $\llbracket y \rrbracket$, produces
    $\llbracket z \rrbracket$ such that $z = x \cdot y$.

	\item A functionality that inverts a secret-shared value: given
    $\llbracket x \rrbracket$, produces $\llbracket z \rrbracket$ such that $z
    = x^{-1}$.

	\item A functionality that combines the shares of a secret-shared value
    $\llbracket x \rrbracket$: reconstructs and distributes $x$ to all, or a
    subset, of the parties.

\end{enumerate}

\subsection{Functionalities for secure multiparty computation in $\G$}

          \item Retrieve all entries $\langle \algo{share},
            \mathit{id}_{{X}}, {X}_i\rangle$ and $\langle \algo{share},

          \item Output to each honest party ${P}_i$ its share ${Z}_i$.

        \end{enumerate}

        x_i\rangle, {Y})_{{P}_i \in \mathcal{H}}$, do:

        \begin{enumerate}

          \item Retrieve all entries $\langle \algo{share}, \mathit{id}_x,
            x_i\rangle$ and entry $\langle \algo{secret}, \mathit{id}_x,
            x\rangle$, compute ${Z}_i = x_i{Y}$ and ${Z} = x{Y}$, and store

          \item Output to each honest party ${P}_i$ its share ${Z}_i$.

        \langle \mathit{id}_{{Y}},{Y}_i\rangle)_{{P}_i \in \mathcal{H}}$ and

        \mathit{id}_x, x_i \rangle, \langle \mathit{id}_{{Y}},
        {Y}_i\rangle)_{{P}_i \in \Cor}$, do:

          \item Retrieve entries $\langle \algo{share}, \mathit{id}_x,
            x_i\rangle$ and $\langle \algo{share}, \mathit{id}_{{Y}}, {Y}_i

        {$\idfu{\algo{CombineGrp}}$.} On receiving from the honest parties
        their shares $(\langle \mathit{id}_{{X}}, {X}_i\rangle)_{{P}_i \in
        \mathcal{H}}$ and from the adversary the shares $(\langle
        \mathit{id}_{{X}}, {X}_i \rangle)_{{P}_i \in \Cor}$, do:

        \begin{enumerate}

          \item Retrieve entries $\langle \algo{share}, \mathit{id}_{{X}},
            {X}_i\rangle$ using the values ${X}_i$ received in the previous
            step.

          \item If at least $t+1$ entries are retrieved successfully, fetch

We additionally assume a framework for secure MPC over inputs in a cyclic
group $(\G,+)$ of prime order $p$. In practice, this framework is
satisfied by both $\group{1}$ and $\group{2}$, but we present it here in the
abstract to avoid repetition. A group element is shared by sharing a random
exponent $x$ and raising a public generator $\gen$ to each share of $x$; each
resulting group element is then an additive share of $x\gen$, as captured by
the $\idfu{\algo{RandShareGrp}}$ interface below. Concretely, we assume some
realisation of the ideal MPC functionality over $\G$ described in
Figure~\ref{fig:ideal-func-group}, where $\mathcal{H}$ and $\Cor$ again denote the
sets of honest and corrupted parties respectively. As for MPC over $\Zp$,
unless otherwise specified, we assume security against malicious corruption
of parties.

We use the representation $\llbracket X \rrbracket$, for $X\in \G$, to
denote that $X$ is secret-shared: no individual party has access to $X$, but
each party holds some share $X_i$ of $X$ (again, we assume this notation
incorporates the authentication components required for malicious security).

\paragraph{Linearity-preservation.} We again require that the secret-shared
representation $\llbracket X \rrbracket$ is linearity-preserving: for any
$X,Y,Z\in \G$ and $\alpha,\beta\in \Zp$ such that $U = \alpha X + \beta Y
+ Z$, given secret shares $\llbracket X \rrbracket$ and $\llbracket Y
\rrbracket$, public group element $Z$, and public values $\alpha,\beta$, the
parties can compute a secret sharing of $U$ ``for free'' as
\[\llbracket U \rrbracket = \alpha\llbracket X \rrbracket + \beta \llbracket Y
\rrbracket + Z.\] Again, since we assume malicious security, this property
must also be preserved for any additional authentication components.

\paragraph{Functionalities for secure MPC in $\G$.} Figure~\ref{fig:ideal-func-group}
describes the functionalities we assume for secure MPC in $\G$, analogous
to those of Figure~\ref{fig:ideal-func} for $\Zp$. We again assume a
randomised functionality that generates a secret-shared representation
$\llbracket R \rrbracket$ for a randomly sampled group element $R\gets
\G$, together with four deterministic functionalities, described below
(all group operations below are written additively):

\begin{enumerate}

	\item A functionality that adds secret-shared group elements: given
    $\llbracket X \rrbracket$ and $\llbracket Y \rrbracket$, produces
    $\llbracket Z \rrbracket$ such that $Z = X + Y$. By linearity-preservation
    this comes for free, as it can be performed locally by each party.

	\item A functionality that multiplies a secret-shared field element with a
    public group element: given $\llbracket x \rrbracket$ and public $Y$,
    produces $\llbracket Z \rrbracket$ such that $Z = xY$. As with addition,
    this comes for free, as it can be executed locally by each party.

	\item A functionality that multiplies a secret-shared field element with a
    secret-shared group element: given $\llbracket x \rrbracket$ and
    $\llbracket Y \rrbracket$, produces $\llbracket Z \rrbracket$ such that $Z
    = xY$.

	\item A functionality that combines the shares of a secret-shared group
    element $\llbracket X \rrbracket$: reconstructs and distributes $X$ to
    all, or a subset, of the parties.

\end{enumerate}

Multiplying a secret-shared group element $\llbracket X \rrbracket$ by a
public value $y \in \Zp$, to produce $\llbracket Z \rrbracket$ such that $Z =
yX$, can also be performed locally, as this is essentially a repeated
application of the local addition functionality above.

In practice, $\G$ corresponds to either $\group{1}$ or $\group{2}$, most
often represented concretely by elliptic curve groups, whose elements are
coordinate pairs satisfying the curve equation, e.g. $(x_0, y_0)$. Sharing a
group element is \emph{not} achieved by two independent secret sharings of
the coordinates $x_0$ and $y_0$, i.e. $(\llbracket x_0 \rrbracket, \llbracket
y_0 \rrbracket)$, as this would require parties to communicate in order to
compute group operations on the shares. Instead, the group element is shared
as a single unit, $\llbracket (x_0,y_0) \rrbracket$, so that group operations
can be performed by each party locally, as desired.
