\section{Definitions}\label{sec:tsps-definitions}

Structure-preserving signatures sign vectors of messages that lie in
pairing-friendly groups, rather than arbitrary strings, and the corresponding
verification algorithm checks equations comprising products of pairings.

\subsection{Structure-preserving signatures}

A structure-preserving signature scheme is defined by the following
algorithms:

\begin{description}

  \item[$(\pk, \sk) \sample \SPSgen(\secparam, l)$ :] The key generation
    algorithm, on input security parameter $\secparam$ and vector length $l$,
    outputs key pair $(\pk, \sk)$, with $\pk$ implicitly defining message
    space $\mathcal{M} \subseteq \G^l$.

  \item[$\signature \sample \SPSsign(\sk, \vec{{M}})$ :] The signing algorithm, on
    input secret key $\sk$ and message $\vec{{M}} \in \mathcal{M}$, outputs
    signature $\signature \in \G^{poly(\secparam)}$.

  \item[$\{0,1\} \leftarrow \SPSverify(\pk, \vec{{M}}, \signature)$ :] The
    verification algorithm, on input public key $\pk$, message $\vec{{M}}$,
    and signature $\signature$, returns 0 or 1. Verification consists only of
    pairing product equations.

\end{description}

A structure-preserving signature scheme satisfies correctness if for all
security parameters $\secparam$, all $(\pk, \sk) \sample \SPSgen(\secparam,
l)$, and all $\vec{{M}} \in \mathcal{M}$, we have $\SPSverify(\pk, \vec{{M}},
\SPSsign(\sk, \vec{{M}})) = 1$.

\paragraph{Unforgeability.} For a PPT adversary $\adv$, define advantage as
follows:
%
\begin{equation*}
%
  \Adv_{\mathrm{SPS}, \adv}^{\text{UF-CMA}}(\secparam) =
  \Pr\left[\mathbf{G}_{\mathrm{SPS}, \adv}^{\text{UF-CMA}}(\secparam) =
  1\right].
%
\end{equation*}
%
Here, game $\mathbf{G}_{\mathrm{SPS},\adv}^{\text{UF-CMA}}$ and signing oracle
$\signo$ are given in Experiment~\ref{exp:sps-uf-cma}. A structure-preserving
signature scheme achieves UF-CMA security if, for every PPT adversary $\adv$,
the following holds:
%
\begin{equation*}
%
  \Adv_{\mathrm{SPS}, \adv}^{\text{UF-CMA}}(\secparam) \leq
  \operatorname{negl}(\secparam).
%
\end{equation*}
%
Excluding the message $\vec{{M}^*}$ itself from the set $S$ of previously
queried messages, as shown in Experiment~\ref{exp:sps-uf-cma}, gives
\emph{weak} unforgeability (wUF-CMA), the notion we rely on throughout this
chapter. Excluding instead the pair $(\vec{{M}^*}, \signature^*)$ gives the
stronger notion of \emph{strong} unforgeability (sUF-CMA), which additionally
rules out an adversary producing a fresh signature on an already-signed
message.

\begin{experimentbox}{Unforgeability under chosen message attack for
  structure-preserving signatures}{sps-uf-cma}

  \begin{enumerate}

    \item The challenger generates $(\pk, \sk) \gets \SPSgen(\secparam,
      l)$ and sends $\pk$ to $\adv$.

    \item The adversary is given oracle access to $\signo$, which on input
      $\vec{{M}}$, computes $\signature \gets \SPSsign(\sk, \vec{{M}})$, and if
      $\signature \neq \perp$, adds $\vec{{M}}$ to $S$, before returning $\signature$.

    \item The adversary outputs $(\vec{{M}^*}, \signature^*)$.

  \end{enumerate}

  $\adv$ wins the experiment if $\SPSverify(\pk, \vec{{M}^*}, \signature^*) =
  1$ and $\vec{{M}^*} \notin S$.

\end{experimentbox}

\subsection{Threshold structure-preserving signatures}

A threshold structure-preserving signature scheme is a structure-preserving
signature scheme whose signing key is distributed across multiple parties. It
is defined by algorithms $\algo{Setup}$, $\algo{KeyGen}$, $\algo{ThreshSign}$, $\algo{Combine}$, and
$\SPSverify$, as follows.

\begin{description}

  \item[$\algo{pp} \sample \algo{Setup}(1^\secparam)$ :] The setup algorithm generates
    public parameters $\algo{pp}$ describing three cyclic groups $(\group{1},
    \group{2}, \group{T})$ of prime order $p$ that admit a non-degenerate
    bilinear pairing $e \colon \group{1} \times \group{2} \rightarrow
    \group{T}$. Hereafter we take $\algo{pp} := (p, e, \group{1}, \group{2},
    \group{T})$ as an implicit input to every subsequent algorithm.

  \item[$(\pk, \llbracket \sk \rrbracket) \sample \algo{KeyGen}(l, t, n)$ :] The key
    generation algorithm takes a triple of integers $(l, t, n > t)$, where
    $l$ is the length of the vectors to be signed, $t$ is an upper bound on
    the number of corrupted parties, and $n$ is the total number of
    threshold signers. It returns a public key $\pk$ and $n$ shares
    $\llbracket \sk \rrbracket$ such that any $t+1$ shares reconstruct the
    secret key underlying $\pk$; $\pk$ consists of group elements, and $\sk$
    of elements of $\Zp$ and/or group elements. This algorithm may be
    interactive.

  \item[$\llbracket \signature \rrbracket \sample \algo{ThreshSign}(\llbracket \sk
    \rrbracket, \vec{{M}})$ :] The threshold signing algorithm takes a
    secret key share $\llbracket \sk \rrbracket$ and a vector of messages
    $\vec{{M}}$ with elements in $\group{1}$ and/or $\group{2}$, and
    outputs a signature share $\llbracket \signature \rrbracket$ with elements in
    $\group{1}$ and $\group{2}$. This algorithm may be interactive.

  \item[$\signature \leftarrow \algo{Combine}(\llbracket \signature \rrbracket)$ :] The
    combining algorithm is non-interactive, and takes signature shares
    $\llbracket \signature \rrbracket$ to output signature $\signature$.

  \item[$\{0,1\} \leftarrow \SPSverify(\pk, \vec{{M}}, \signature)$ :] The
    verification algorithm takes public key $\pk$, vector of messages
    $\vec{{M}}$, and signature $\signature$, and returns 1 if $\signature$ is valid
    on $\vec{{M}}$, and 0 otherwise. As in the non-threshold case,
    verification checks membership of the signature's elements in $\group{1}$
    and $\group{2}$, and evaluates equations involving pairing products.

\end{description}

Both threshold structure-preserving signature schemes we construct in
Section~\ref{sec:schemes} are \emph{partially non-interactive}: $\algo{ThreshSign}$
requires no interaction between signers, while the message-independent
pre-processing that precedes it, captured by $\algo{OffSign}$ in
Section~\ref{sec:schemes}, may be interactive. We formalise security for
threshold structure-preserving signatures, together with the corresponding
game, in Section~\ref{sec:tsps-security}, once the MPC functionalities of
Section~\ref{sec:MPC} that our constructions build upon are available to draw
on.
