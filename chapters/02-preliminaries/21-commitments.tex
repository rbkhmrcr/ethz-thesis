\section{Commitments}\label{sec:prelims-commitments}

Commitment schemes enable a party to commit to a message while keeping it
hidden until it is later revealed.

\paragraph{Interfaces.} A commitment scheme consists of algorithms defined as
follows:
%
\begin{itemize}

  \item $\ck \sample \COMgen(\secparam)$ : the key generation outputs key
    $\ck$.

  \item $\com \leftarrow \COMcommit(\ck, \msg, \openinfo)$ : the commitment
    algorithm takes as input key $\ck$, a message $\msg$, and opening
    information $\openinfo$, and outputs commitment $\com$.

  \item $\msg \leftarrow \COMopen(\ck, \openinfo, \com)$ : the opening
    algorithm takes as input a commitment key $\ck$, opening information
    $\openinfo$, and commitment $\com$, and outputs message $\msg$.

\end{itemize}
%
Commitment schemes satisfy correctness, hiding, and binding, which we define
below. We use the standard syntax and security notions for commitment
schemes~\cite{KatLin14}.

\paragraph{Correctness.} A commitment scheme must satisfy the following
correctness requirement: for every key $\ck$ generated by
$\COMgen(\secparam)$, every message $\msg$, and every opening information
$\openinfo$, it holds that
$\COMopen(\ck, \COMcommit(\ck,\msg,\openinfo),\openinfo) = \msg$.

\paragraph{Hiding.} We require commitment schemes to satisfy hiding as defined
by the following security experiment between a challenger and an adversary
$\adv$:
%
\begin{enumerate}

  \item The challenger generates $\ck \sample \COMgen(\secparam)$ and sends
    $\ck$ to $\adv$.

  \item The adversary outputs two messages $(\msg_0, \msg_1)$.

  \item The challenger samples $b \sample \{0,1\}$, generates $\openinfo$ and
    computes $ \com^\star \leftarrow \COMcommit(\ck,\msg_b,\openinfo)$. They
    send $\com^\star$ to $\adv$.

  \item Eventually, $\adv$ outputs a bit $b'$.

\end{enumerate}
%
The adversary wins if $b' = b$. Their hiding advantage is then defined as
follows: 
\begin{equation*}
\Adv^{\mathsf{hiding}}_{\COM, \ \adv}(\secparam) = \left| \ \Pr[b'=b]-\frac{1}{2} \ \right|.
\end{equation*}
A commitment scheme is said to be hiding if this advantage is small.

\paragraph{Binding.} We also require commitment schemes to satisfy the binding
property.  It is defined by the following security experiment:
%
\begin{enumerate}

  \item The challenger generates $\ck \sample \COMgen(\secparam)$ and sends
    $\ck$ to $\adv$.

  \item Eventually, the adversary outputs
    $(\com, \msg, \msg', \openinfo, \openinfo')$, where $\msg \neq \msg'$.

\end{enumerate}
%
The adversary wins if $\COMopen(\ck,\openinfo,\com)=\msg$ and
$\COMopen(\ck,\openinfo',\com) = \msg'$.
Its binding advantage is defined as follows:
\begin{equation*}
\Adv^{\mathsf{binding}}_{\COM, \ \adv}(\secparam) = \Pr[ \ \adv\text{ wins} \ ]. 
\end{equation*}
A commitment scheme is said to be binding if this advantage is small.
