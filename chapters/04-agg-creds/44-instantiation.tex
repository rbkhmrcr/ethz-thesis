\section{Instantiation}\label{sec:agg-creds-instantiation}

\paragraph{Notation.} We use bilinear groups and the conventions of
\Cref{sec:prelims-groups}. As a reminder, elements of $\group{2}$ are written with a tilde.

We use hash functions $\hashone \colon \{0,1\}^* \rightarrow \group{1}$ and
$\hashtwo \colon \{0,1\}^* \rightarrow \group{1}$, and a hash function $\hash
\colon \{0,1\}^* \rightarrow \Zp$ for the challenges of the proofs below.
Each hash function prefixes its input with a domain separation tag, so that they
behave as independent random oracles, and $\hash$ uses one tag for the proofs of
knowledge of secret keys and another for presentations.

\subsection{Instantiating $\ATS$}\label{sec:agg-creds-tag-scheme}

Our tag-based aggregate signature scheme builds on the BLS signature scheme and
its aggregate form~\cite{JC:BonLynSha04,EC:BGLS03}. Each of our signatures adds
the hash of a tag raised to a fresh exponent, so that only signatures under the
same tag aggregate, and signatures can be rerandomised. Signatures aggregate by
multiplication and verify with one pairing equation, so an aggregate is as short
as one signature. Our scheme, given in \Cref{prot:ats}, consists of the following algorithms:

\begin{protocolbox}{The tag-based aggregate signature scheme}{ats}

  \begin{description}

    \item[$(\sk, \pk) \sample \ATSgen(\secparam)$ :] On input the security
parameter, do the following:

      \begin{enumerate}

	\item Sample $\sk \sample \Zp$.

	\item Return $(\sk, \pk = \ggen^\sk)$.

      \end{enumerate}

    \item[$\signature \sample \ATSsign(\sk, \Tag, \msg)$ :] On input secret key
$\sk$ and pair of tag and message $(\Tag, \msg)\in \{0,1\}^*\times\{0,1\}^*$,
do:

      \begin{enumerate}

	\item Sample $\upsilon \sample \Zp$.

	\item Return $\signature = (\ggen^\upsilon, \hashone(\msg)^\sk \cdot
\hashtwo(\Tag)^\upsilon)$.

      \end{enumerate}

    \item[$\signature' \sample \ATSrandomise(\Tag, \signature) $ :] On input tag
$\Tag$, signature $\signature$, do:

      \begin{enumerate}

	\item Parse $\signature = (\signatureone, \signaturetwo)$.

	\item Sample $\upsilon' \sample \Zp$.

	\item Return $\signature' = (\signatureone \cdot  \ggen^{\upsilon'},
\signaturetwo \cdot \hashtwo(\Tag)^{\upsilon'})$.

      \end{enumerate}

    \item[$ \{0,1\} \leftarrow \ATSverify(\pk, \Tag, \msg, \signature) $ :] On
input public key $\pk$, tag $\Tag \in \{0,1\}^*$, message $\msg \in \{0,1\}^*$,
and signature $\signature$, do:

      \begin{enumerate}

	\item Parse $\signature = (\signatureone, \signaturetwo)$.

	\item Return $1$ if and only if the following holds:
	  %
	  \begin{equation*}
	    \pairing(\signaturetwo,\ggen) = \pairing(\hashtwo(\Tag), \signatureone)
\cdot \pairing(\hashone(\msg), \pk).
	  \end{equation*}

      \end{enumerate}

    \item[$\signature \leftarrow \ATSaggregate((\signature_i)_{i \in
\ISSUERS})$:] On input signatures $(\signature_i)_{i \in \ISSUERS}$, for set
$\ISSUERS \subseteq [1, n]$, do:

      \begin{enumerate}

	\item Parse $\signature_i = (\signatureone_i, \signaturetwo_i)$ for each
$i \in \ISSUERS$.

	\item Return $\signature = (\prod_{i\in\ISSUERS} \signatureone_i, \
\prod_{i\in\ISSUERS} \signaturetwo_i)$.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \ATSverifyagg((\pk_i)_{i\in \ISSUERS},
\Tag,(\msg_i)_{i\in \ISSUERS},\signature) $ :] On input public keys
$(\pk_i)_{i\in \ISSUERS}$, tag $\Tag$, messages $(\msg_i)_{i\in \ISSUERS}$, and
aggregate signature $\signature$, do:

      \begin{enumerate}

	\item Parse $\signature = (\signatureone, \signaturetwo)$.

	\item Return $1$ if and only if the following holds:
	  %
	  \begin{equation*}
	    \pairing(\signaturetwo, \ggen) = \pairing(\hashtwo(\Tag),
\signatureone) \cdot \prod_{i\in\ISSUERS} \pairing(\hashone(\msg_i), \pk_i).
	  \end{equation*}

      \end{enumerate}

  \end{description} \end{protocolbox}

Issuer keys are certified, as in \Cref{exp:ats-euf}. Without this, an adversary
could choose its key as the inverse of an honest one, and the signature $(1, 1)$
would then verify under both keys for any tag and message. Unrestricted
aggregate signatures prevent this by hashing the index of the signer together
with each message~\cite{ICALP:BelNamNev07}.

  \begin{assumptionbox}{The Bilinear Computational Diffie-Hellman (BCDH) assumption~\cite{C:BonFra01}.}{bcdh}

    The BCDH assumption holds if, given $(\gen, \gen^\gamma, \gen^\omega,
\gen^\chi, \ggen, \ggen^\gamma, \ggen^\omega, \ggen^\chi)$ for uniformly
random $\gamma, \omega, \chi \sample \Zp$, no PPT adversary can output
$\pairing(\gen, \ggen)^{\gamma\omega\chi}$ with non-negligible probability.

  \end{assumptionbox}

  \begin{theorem}\label{thm:agg-creds-thm-1} If the BCDH assumption of \Cref{asm:bcdh} holds, then
our tag-based aggregate signature scheme is existentially unforgeable
under tag-based aggregation in the random oracle model.  \end{theorem}

We prove \Cref{thm:agg-creds-thm-1} in \Cref{sec:agg-creds-proof-2}.

\subsection{Instantiating $\AAC$ with $\AGHO$ and $\ATS$}\label{sec:agg-creds-aac-inst}

\paragraph{Overview.} In this instantiation, each user has a pair of secret and
public keys $(\sk, \pk = \gen^\sk)$, so the one-way function of the construction
is exponentiation. The digital signature $\DS$ is instantiated using the $\AGHO$
structure-preserving signature scheme of \Cref{prim:agho}~\cite{C:AGHO11}, and
the tag-based aggregate signature $\ATS$ with our construction. Every user is
assigned a unique tag $\Tag \in \Zp$, and the registration authority signs the
pair $(\pk, \tid)$, with $\tid = \hashtwo(\Tag)$. \Cref{prot:paac} gives the
protocol instantiation in full.

The registration authority's key pair is for the structure-preserving signature
scheme, since messages and signatures consist of elements of the same group as
everything else in the protocol. This lets users prove knowledge of a valid
registration signature with an efficient Sigma protocol over discrete
logarithms, without a general-purpose zero-knowledge proof.

The tag and its hash each have a role. Issuers sign under $\Tag$, and
$\ATSsign$ hashes it to $\tid$, so that the security proof of $\ATS$ can program
$\hashtwo$ at the tag of the forgery. A tag chosen directly as a group element
could not be programmed. The registration authority computes $\tid$ from $\Tag$
itself and signs $\tid$, which a structure-preserving signature scheme allows,
since it signs group elements. The registration signature and the aggregate
signature then share $\tid$, and the presentation only proves that they share
it, without showing $\tid$. A signature scheme on field elements could only sign
$\Tag$, and the presentation would then have to prove that the hidden $\tid$ is
the hash of the hidden signed tag. Proving a hash to the group in zero knowledge
needs a general-purpose proof system.

We write the registration authority's public key, the issuer public keys, the
tag identifier and the two signatures as follows:
%
\begin{gather*}
%
  \rapk = (\widetilde{u}_1, \widetilde{u}_2, v), \quad \ipk{i} =
\ggen^{\isk{i}}, \quad \tid = \hashtwo(\Tag), \\ \signature = (\signatureone,
\signaturetwo), \quad \SPSsig = (\widetilde{r}, \widetilde{s}, z).
%
\end{gather*}
%
The presentation relation $\rel_1$ of \eqref{eq:agg-creds-proof-abstract},
with $\DS$ set to $\AGHO$ and $\ATS$ to our tag-based scheme, has instance,
witness and relation defined as follows:
%
\begin{equation}\label{eq:agg-creds-proof-original}\begin{gathered}
%
  \inst_2 = (\rapk, \ISSUERS, \{\ipk{i}, \atv{i}\}_{i \in \ISSUERS}), \qquad \witness_2
= (\sk, \pk, \tid, \signature, \SPSsig), \\
%
  \rel_2 = \{\ \pairing(v, \widetilde{r}) = \pairing(\gen, \widetilde{s}) \
\wedge\ \pairing(z, \widetilde{r}) \cdot \pairing(\gen^\sk,
\widetilde{u}_1)\cdot \pairing(\tid, \widetilde{u}_2) = \pairing(\gen, \ggen) \\
  \wedge\ \pk = \gen^\sk \ \wedge\ \pairing(\signaturetwo, \ggen) =
\pairing(\tid,
\signatureone)\cdot\prod_{i\in\ISSUERS}\pairing(\hashone(\atv{i}), \ipk{i})\ \}.
%
\end{gathered}\end{equation}
%
The witness contains $\tid = \hashtwo(\Tag)$ in place of the $\Tag$ of
$\witness_1$, since the equations of $\rel_2$ use only $\tid$, and the proof of
\Cref{lem:agg-creds-sigma} recovers $\Tag$ from $\tid$ by programming
$\hashtwo$.

To avoid a general-purpose zero-knowledge proof over the pairing equations of
$\rel_2$, $\AACpresent$ in \Cref{prot:paac} randomises both signatures, and
raises every element that would identify them to a fresh $\delta$. The
consistency checks of $\rel_2$ then become the following relation, which the
Sigma protocol of $\AACpresent$ proves:
%
\begin{equation}\label{eq:agg-creds-proof-rel}\begin{gathered}
%
  \inst_3 = (\bar{\gen}, \bar{v}, \pk', \{i, \atv{i}, H_i\}_{i\in\ISSUERS},
\widetilde{r}', \widetilde{s}', \bar{z}, \signatureone', \bar{\signaturetwo},
\bar{\tid}), \qquad \witness_3 = (\delta, \sk), \\
%
  \rel_3 = \{\ \bar{\gen} = \gen^\delta \ \wedge\ \bar{v} = v^\delta \ \wedge\
H_i = \hashone(\atv{i})^\delta\ \ \forall i \in \ISSUERS \ \wedge\ \pk' =
\bar{\gen}^\sk\ \}.
%
\end{gathered}\end{equation}
%
$\rel_3$ does not include the signature verification equations of $\rel_2$. The
randomised signatures reveal nothing about the original ones, so the user sends
them in the clear and the verifier checks their verification equations directly. This gives an
efficient proof, with no zero-knowledge proof over pairing equations
or elements of $\group{T}$. The cost is that a presentation grows with the number of
disclosed attributes. Each disclosed attribute adds its blinded hash $H_i$ and
one Sigma protocol commitment, two elements of $\group{1}$. Proving that every
$H_i$ uses the same $\delta$ in $\group{T}$ instead would make the proof
constant-size, apart from the disclosed values, at the cost of one pairing per
disclosed attribute for the user.

\begin{lemma}\label{lem:agg-creds-sigma}

  In the random oracle model, if the registration authority signs only pairs
$(\pk, \hashtwo(\Tag))$, a witness $(\Tag, \sk, \pk, \SPSsig, \signature)$ for
$\rel_1$, with $\DS$ set to $\AGHO$ on $(\pk, \hashtwo(\Tag))$, can be extracted
by rewinding from any adversary that outputs a verifying presentation for a
statement and label on which it saw no simulated presentation, except with the
probability of forging an $\AGHO$ signature or computing a discrete logarithm
in $\group{1}$. If the DDH assumption holds in $\group{1}$, presentations can
be simulated without a witness, with $\rask$ and by programming $\hash$.

\end{lemma}

We prove \Cref{lem:agg-creds-sigma} in \Cref{sec:agg-creds-proof-lemma}.

At registration and issuance, users prove knowledge of $\sk$ with a Sigma
protocol on a nonce chosen by the registration authority or the issuer, so proofs
cannot be replayed.

%%%% anon creds protocol

\begin{protocolbox}{The aggregate anonymous credentials protocol}{paac}

  \begin{description}

    \item[$\crs \sample \AACgen(\secparam, n)$ :] On input security parameter
$\secparam$ and number of issuers $n$, do the following:

      \begin{enumerate}

	\item Sample $(\rask,\rapk) \sample \SPSgen(\secparam,2)$ for the
$\AGHO$ SPS scheme, with $\rapk = (\widetilde{u}_1, \widetilde{u}_2, v)$.

	\item Each issuer $i \in [1,n]$ samples $(\isk{i},\ipk{i}) \sample
\ATSgen(\secparam)$, so $\ipk{i} = \ggen^{\isk{i}}$, samples $\varrho_i \sample
\Zp$, and computes a proof of knowledge of $\isk{i}$ as follows:
          %
	  \begin{equation*}
          %
	    \widetilde{a}_i = \ggen^{\varrho_i}, \quad c_i = \hash(\ggen, \ipk{i},
\widetilde{a}_i, i), \quad \zeta_i = \varrho_i + c_i \cdot \isk{i}.
          %
	  \end{equation*}

	\item Return $\crs \leftarrow
(\gen,\ggen,\hashone,\hashtwo,\hash,\rapk,\{\ipk{i}, \widetilde{a}_i,
\zeta_i\}_i)$. Verifiers recompute each $c_i$ and accept $\ipk{i}$ only if
$\ipk{i} \neq 1$ and $\ggen^{\zeta_i} = \widetilde{a}_i \cdot \ipk{i}^{c_i}$.

      \end{enumerate}

    \item[$(\sk,\regcred) \sample \AACregister(\crs,\rask)$ :] Between the user
and the registration authority, on input $\rask$ to the registration authority, do:

      \begin{enumerate}

	\item The user samples $\sk \sample \Zp$ and sets $\pk \leftarrow
\gen^\sk$.

	\item The registration authority samples a fresh nonce $\rand \sample \Zp$ and sends it to
the user.

	\item The user samples $\varrho \sample \Zp$ and computes the following:
          %
	  \begin{equation*}
          %
	    a = \gen^\varrho, \quad c = \hash(\gen, \pk, a, \rand), \quad \zeta =
\varrho + c \cdot \sk.
          %
	  \end{equation*}

	\item The user sends $(\pk, a, \zeta)$.

	\item The registration authority recomputes $c$ and exits unless $\pk \neq 1$, $\pk$ has not
been registered before, and $\gen^\zeta = a \cdot \pk^c$.

	\item Otherwise, the registration authority samples a fresh $\Tag \sample \Zp$ it has not
assigned before, sets $\tid \leftarrow \hashtwo(\Tag)$, and computes $\SPSsig
\sample \SPSsign(\rask,(\pk,\tid))$.

	\item Return $\sk$ and $\regcred \leftarrow (\Tag,\pk,\SPSsig)$ to the
user.

      \end{enumerate}

    \item[$\cred \sample \AACissue(\crs,\isk{i},\sk,\regcred,\atv{i})$ :] Between
the user, on input $(\sk, \regcred)$, and issuer $i$, on input $\isk{i}$, for
the user's value $\atv{i}$ of attribute $\att{i}$, do:

      \begin{enumerate}

	\item The user sends $\regcred = (\Tag,\pk,\SPSsig)$. The issuer
computes $\tid \leftarrow \hashtwo(\Tag)$ and exits if
$\SPSverify(\rapk,(\pk,\tid),\SPSsig) \neq 1$.

	\item The issuer sends a fresh nonce $\rand$, and the user proves
knowledge of $\sk$ as in $\AACregister$. If the proof fails, the issuer exits.

	\item Otherwise, the issuer computes $\signature_i \sample
\ATSsign(\isk{i},\Tag,\atv{i})$, and the user stores $\cred_i \leftarrow
(\atv{i},\signature_i)$.

      \end{enumerate}

    \item[$\aggcred \leftarrow \AACaggregate(\crs,(\cred_i)_{i \in \ISSUERS})$ :]
On input the credentials $(\cred_i)_{i \in \ISSUERS}$ to be disclosed, for
$\ISSUERS \subseteq [1,n]$, all issued under the same tag $\Tag$, do:

      \begin{enumerate}

	\item Parse each $\cred_i = (\atv{i},\signature_i)$ for $i \in \ISSUERS$.

	\item Compute $\signature \leftarrow
\ATSaggregate((\signature_i)_{i\in\ISSUERS})$.

	\item Return $\aggcred \leftarrow
(\Tag,\{(i, \atv{i})\}_{i\in\ISSUERS},\signature)$.

      \end{enumerate}

    \item[$\algoproof \sample \AACpresent(\crs,\sk,\regcred,\aggcred,\msg)$ :]
On input the user's $\sk$ and $\regcred$, $\aggcred$, and message $\msg$
from the verifier, do:

      \begin{enumerate}

	\item Parse $\regcred = (\Tag,\pk,\SPSsig)$ and $\aggcred =
(\Tag,\{(i, \atv{i})\}_{i \in \ISSUERS},\signature)$, and set $\tid =
\hashtwo(\Tag)$.

	\item Randomise the signatures as follows:
          %
	  \begin{gather*}
          %
	    (\signatureone', \signaturetwo') \sample
\ATSrandomise(\Tag,\signature), \\ (\widetilde{r}', \widetilde{s}', z')
\sample \SPSrandomise(\SPSsig).
          %
	  \end{gather*}

	\item Sample $\delta \sample \Zp^*$ and compute the following:
          %
	  \begin{gather*}
          %
	    \bar{\gen} = \gen^\delta, \quad \bar{v} = v^\delta, \quad \bar{z} =
{z'}^\delta, \quad \bar{\signaturetwo} = {\signaturetwo'}^\delta, \\
\bar{\tid} = \tid^\delta, \quad \pk' = \pk^\delta, \quad H_i =
\hashone(\atv{i})^\delta \ \ \forall i \in \ISSUERS.
          %
	  \end{gather*}

	\item Set the statement and witness as follows:
          %
	  \begin{equation*}\begin{gathered}
          %
	    \inst_3 = (\bar{\gen}, \bar{v}, \pk', \{i, \atv{i}, H_i\}_{i\in\ISSUERS},
\widetilde{r}', \widetilde{s}', \bar{z}, \signatureone', \bar{\signaturetwo},
\bar{\tid}), \qquad \witness_3 = (\delta, \sk), \\
          %
	    \rel_3 = \{\ \bar{\gen} = \gen^\delta \ \wedge\ \bar{v} = v^\delta \
\wedge\ H_i = \hashone(\atv{i})^\delta\ \ \forall i \in \ISSUERS \ \wedge\ \pk'
= \bar{\gen}^\sk\ \}.
          %
	\end{gathered}\end{equation*}

      \item To prove $\rel_3$, sample $\alpha, \beta \sample \Zp$ and compute
the commitments, the challenge and the responses as follows:
          %
	  \begin{gather*}
          %
	    (f, h, \{y_i\}_{i \in \ISSUERS}, w) = (\gen^\alpha, v^\alpha,
\{\hashone(\atv{i})^\alpha\}_{i \in \ISSUERS}, \bar{\gen}^\beta), \\
	    c \leftarrow \hash(\gen, v, \inst_3, f, h, \{y_i\}_{i \in
\ISSUERS}, w, \msg), \\
	    \pi_1 = \alpha + c\delta, \quad \pi_2 = \beta + c\sk.
          %
	  \end{gather*}

      \item Set $\eta = (f, h, \{y_i\}_{i \in \ISSUERS}, w, \pi_1, \pi_2)$.

      \item Return $\algoproof = (\eta, \inst_3)$.

    \end{enumerate}

  \item[$\{0,1\} \leftarrow \AACverify(\crs,\{\atv{i}\}_{i \in
\ISSUERS},\msg,\algoproof)$ :] On input $(\{\atv{i}\}_{i \in
\ISSUERS},\msg,\algoproof)$ from a verifier, parse $\algoproof = (\eta,
\inst_3)$ with $\inst_3 = (\bar{\gen}, \bar{v}, \pk', \{i, \atv{i},
H_i\}_{i\in\ISSUERS}, \widetilde{r}', \widetilde{s}', \bar{z},
\signatureone', \bar{\signaturetwo}, \bar{\tid})$ for the input values, and $\eta = (f, h, \{y_i\}_{i \in \ISSUERS}, w, \pi_1, \pi_2)$, and do:

    \begin{enumerate}

      \item Compute $c \leftarrow \hash(\gen, v, \inst_3, f, h, \{y_i\}_{i \in
\ISSUERS}, w, \msg)$.

      \item Return $1$ if and only if the indices $i$ in $\inst_3$ are distinct
elements of $[1,n]$ and the following hold:
       %
	\begin{gather*}
		%
	  \bar{\gen} \neq 1, \quad \bar{v} \neq 1, \quad \pk' \neq 1, \quad
\widetilde{r}' \neq 1, \\
	   \gen^{\pi_1} = f\cdot\bar{\gen}^c, \quad v^{\pi_1}
= h\cdot\bar{v}^c, \quad \bar{\gen}^{\pi_2} = w\cdot\pk'^c, \\
	  \hashone(\atv{i})^{\pi_1} = y_i\cdot H_i^c \ \ \forall i \in \ISSUERS,
\\
		%
	  \pairing(\bar{v}, \widetilde{r}')= \pairing(\bar{\gen},
\widetilde{s}'), \\
		%
	  \pairing(\bar{\signaturetwo}, \ggen) = \pairing(\bar{\tid},
\signatureone') \cdot \prod_{i\in \ISSUERS}\pairing(H_i, \ipk{i}), \\
          	%
	  \pairing(\bar{\gen}, \ggen) = \pairing(\bar{z},
\widetilde{r}')\cdot \pairing(\pk', \widetilde{u}_1)\cdot \pairing(\bar{\tid},
\widetilde{u}_2).
	%
	\end{gather*}
        %
    \end{enumerate}

\end{description}

\end{protocolbox}

\begin{theorem}\label{thm:agg-creds-thm-2}

    In the random oracle model, if the BCDH assumption holds, the DDH assumption
holds in $\group{1}$, and $\AGHO$ is existentially unforgeable, then the
aggregate anonymous credentials protocol $\AAC$ of \Cref{prot:paac} securely
realises ideal functionality $\idfu{\AAC}$.

\end{theorem}

$\AGHO$ is existentially unforgeable in the GGM~\cite{C:AGHO11}. So the
protocol is secure in the random oracle model and the GGM. We prove \Cref{thm:agg-creds-thm-2} in \Cref{sec:agg-creds-proof-3}.
