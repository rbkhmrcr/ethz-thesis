\section{Instantiation}

\subsection{Our tag based aggregate signature scheme ($\ATS$)}
\label{sec:tag-scheme}

Our tag based aggregate signature scheme is an enhanced aggregate BLS signature
scheme that signs pairs of messages and tags~\cite{JC:BonLynSha04,EC:BGLS03}.
The key differences are tag restricted aggregation and ability to randomise
signatures.  Our scheme is comprised of the following algorithms:

\begin{protocolbox}{Tag based aggregate signature protocol ($\ATS$)} {fig:ats}

  \begin{description}

    \item[$(\sk, \pk) \sample \ATSgen(\secparam)$ :] On input the security
      parameter, do the following:

      \begin{enumerate}

        \item Sample $\sk \sample \Zp$.

        \item Return $(\sk, \pk = \ggen^x)$.

      \end{enumerate}

    \item[$\signature \sample \ATSsign(\sk, \Tag, \msg)$ :] On input secret key
      $\sk$ and pair of tag and message $(\Tag, \msg)\in
      \{0,1\}^*\times\{0,1\}^*$, do:

      \begin{enumerate}

        \item Sample $s \sample \Zp$.

        \item Return $\signature = (\ggen^{s}, \hashone(m)^{\sk} \cdot
          \hashtwo(\Tag)^s)$.

      \end{enumerate}

    \item[$\signature' \sample \ATSrandomise(\Tag, \signature) $ :] On input
      tag $\Tag$, signature $\signature$, do:

      \begin{enumerate}

        \item Parse $\signature = (\signatureone, \signaturetwo)$.

        \item Sample $s' \sample \Zp$.

        \item Return $\signature' = (\signatureone \cdot  \ggen^{s'},
          \signaturetwo \cdot \hashtwo(\Tag)^{s'})$.

      \end{enumerate}

    \item[$ \{0,1\} \leftarrow \ATSverify(\pk, \Tag, \msg, \signature) $ :] On
      input public key $\pk$, tag $\Tag \in \{0,1\}^*$, message $\msg \in
      \{0,1\}^*$, and signature $\signature$, do:

      \begin{enumerate}

        \item Parse $\signature = (\signatureone, \signaturetwo)$.

        \item Return $e(\signaturetwo,\ggen) \checkcheck e(\hashone(\msg), \pk)
          \cdot e(\hashtwo(\Tag), \signatureone)$.

      \end{enumerate}

    \item[$\signature \leftarrow \ATSaggregate(\{ \signature_i \}_{i \in [1,
      n]})$:] On input signatures $\signature_i$, do:

      \begin{enumerate}

        \item Parse $\signature_i = (\signatureone_i, \signaturetwo_i)$.

        \item Return $\signature = (\prod_{i=1}^n {\signatureone}_i, \
          \prod_{i=1}^n {\signaturetwo}_i)$.

      \end{enumerate}

    \item[$\{0,1\} \leftarrow \ATSverifyagg(\{\pk_i\}_{i\in [1, n]},
      \Tag,\{\msg_i\}_{i\in [1, n]},\signature) $ :] On input public keys
      $\{\pk_i\}_{i\in [1, n]}$, tag $\Tag$, messages $\{\msg_i\}_{i\in [1,
      n]}$, and aggregate signature $\signature$, the aggregate verification
      algorithm outputs the result of the following check:

      \begin{enumerate}

        \item Parse $\signature = (\signatureone, \signaturetwo)$.

        \item Return $e(\signaturetwo, \ggen) \checkcheck e (\hashtwo(\Tag),
          \signatureone) \cdot \prod_{i=1}^n e(\hashone(\msg_i), \pk_i)$.

      \end{enumerate}

  \end{description} \end{protocolbox}

  This signature is existentially unforgeable under tag-based aggregation in
  the random oracle model under the Bilinear Computational Diffie-Hellman
  (BCDH) assumption and a modified variant of the same assumption. To the best
  of our knowledge, the modified BCDH assumption has not been explicitly
  introduced in prior work. However, it fits within the Uber assumption
  framework and can be shown to hold in the generic bilinear group
  model~\cite{EC:BonBoyGoh05,PAIRING:Boyen08}.  This is shown
  in~\Fref{sec:agg-creds-security}.

  \subsection{Our aggregate anonymous credentials scheme ($\AAC$)}

  \paragraph{Overview.} In this instantiation, each user has a pair of secret
  and public keys $(\sk, \pk = \gen^\sk)$.  The digital signature $\DS$ uses
  AGHO structure preserving signatures~\cite{C:AGHO11}. The message that we
  sign is the pair $(\pk, \hashtwo(\Tag)) \in \group{1}\times\group{1}$, where
  $\pk$ is the user's public key and $\Tag$ their unique tag.  The aggregate
  tag-based signature $\ATS$ is instantiated with our construction.

  \paragraph{The AGHO structure preserving signature scheme.} The AGHO scheme
  supports signing vectors of elements in $\group{1}$, $\group{2}$, or both.
  In the following, we only describe signing elements of $\group{1}$.

  \begin{primitivebox} {AGHO structure-preserving signatures} {fig:agho}

    \begin{description}

      \item[$ (\sk, \pk) \sample \SPSgen(\secparam, \ell) $ :] On input a
        security parameter $\secparam$ and vector length $\ell$, the generation
        algorithm outputs the following key pair:
         %
        \begin{gather*}
     %
          (u_1, \dots, u_\ell,  v) \sample \Zp^{\ell+1}; \quad \sk = (u_1,
          \dots, u_\ell, v); \\
      %
          \pk = (\widehat{U}_1, \dots, \widehat{U}_\ell, V)
          \quad\text{with}\quad \widehat{U}_i = \ggen^{u_i} \in \group{2}, V =
          \gen^v \in \group{1}.
        %
        \end{gather*}
     %

      \item[$\SPSsig \sample \SPSsign(\sk, \vec{M})$ :] On input the secret key
        $\sk = (u_1, \dots, u_\ell, v)$ and message $\vec{M} = (M_1, \dots,
        M_\ell) \in \group{1}^\ell$, the signing algorithm randomly samples $r
        \sample \Zp$ and outputs the signature constructed as follows:
    %
        \begin{equation*}
     %
          \signature =  (\widehat{R}, \widehat{S}, T) = (\ggen^r,
          \widehat{R}^v, (\gen \cdot \prod_{i=1}^\ell M_i^{-u_i})^{1/r}).
    %
        \end{equation*}
     %

      \item[$\SPSsig' \sample \SPSrandomise(\SPSsig)$ :] On input signature
        $\SPSsig = (\widehat{R}, \widehat{S}, T)$, the randomisation algorithm
        randomly samples $r' \sample \Zp$ and outputs the signature formed as
        follows:
    %
        \begin{equation*}
        %
          \SPSsig' = (\widehat{R}', \widehat{S}', T') = ( \widehat{R}^{r'},
          \widehat{S}^{r'}, T^{\frac{1}{r'}}).
    %
        \end{equation*}
     %

      \item[$ \{0,1\} \leftarrow \SPSverify(\pk, \vec{M}, \SPSsig)$ :] On input
        a public key $\pk$, message $\vec{M} = (M_1, \dots, M_\ell) \in
        \group{1}^\ell$, and signature $\SPSsig = (\widehat{R}, \widehat{S},
        T)$, the verification algorithm outputs $1$ if both of the following
        pairing equations hold:
    %
        \begin{equation*}
    %
          e(V, \widehat{R}) = e(\gen, \widehat{S}) \quad \wedge \quad e(T,
          \widehat{R}) \cdot \prod_{i=1}^\ell e(M_i, \widehat{U}_i) = e(\gen,
          \ggen).
  %
        \end{equation*}
  %
        And otherwise outputs $0$.

    \end{description}

  \end{primitivebox}

  \begin{protocolbox} {Aggregate anonymous credentials protocol} {fig:paac}

    \begin{description}

      \item[$(\crs,\state) \sample \AACgen(\secparam)$ :] On input security
        parameter $\secparam$, do the following:

        \begin{enumerate}

          \item Sample $(\rask,\rapk) \sample \SPSgen(\secparam,2)$.

          \item For each issuer $i$, sample $(\isk{i},\ipk{i}) \sample
            \ATSgen(\secparam)$.

          \item Set $\crs \leftarrow
            (\gen,\ggen,\hashone,\hashtwo,\rapk,\{\ipk{i}\}_i)$ and $\state
            \leftarrow \varnothing$.

          \item Return $(\crs,\state)$.

        \end{enumerate}

      \item[$(\sk,\regcred) \sample \AACregister(\crs,\state)$ :] On input
        $(\crs,\state)$ from the user, do:

        \begin{enumerate}

          \item The user samples $\sk \sample \Zp$ and sets $\pk \leftarrow
            \gen^\sk$.

          \item The user sends $\pk$ to the RA and proves knowledge of $\sk$ on
            a fresh nonce from the RA.

          \item If the proof does not verify, the RA aborts.

          \item Else, the RA samples a fresh tag $\tau \sample \Zp \setminus
            \state$, sets $\Gamma \leftarrow \hashtwo(\tau)$, and computes
            $\psi \sample \SPSsign(\rask,(\pk,\Gamma))$. (This instantiates the
            generic $\DSsign$.)

          \item Set $\state \leftarrow \state \cup \{\tau\}$, and return $\sk$
            to the user, and $\regcred \leftarrow (\tau,\pk,\psi)$ to the user.

        \end{enumerate}

      \item[$\cred \sample \AACissue(\crs,\isk{},\regcred,\att{})$ :] On input
        $(\crs,\isk{i},\regcred,\att{i})$ from the user, with $\atv{i}$ the
        value of attribute $\att{i}$ held by the user, do:

        \begin{enumerate}

          \item Parse $\regcred = (\tau,\pk,\psi)$.

          \item If $\SPSverify(\rapk,(\pk,\hashtwo(\tau)),\psi) \neq 1$, abort.
            (This instantiates the generic $\DSverify$.)

          \item Else, the user proves knowledge of $\sk$ underlying $\pk$ to
            issuer $i$; if this fails, abort.

          \item Else, compute $\sigma \sample \ATSsign(\isk{i},\tau,\atv{i})$.

          \item Return $\cred \leftarrow (\atv{i},\sigma)$ to the user.

        \end{enumerate}

      \item[$\aggcred \leftarrow \AACaggregate(\crs,\cred,\ldots,\cred)$ :] On
        input credentials $\cred_1,\ldots,\cred_n$ from the user, all issued
        under the same tag $\tau$, do:

        \begin{enumerate}

          \item Parse each $\cred_j = (\atv{j},\sigma_j)$ for $j \in [1,n]$.

          \item Compute $\signature \leftarrow
            \ATSaggregate(\{\sigma_j\}_{j\in[1,n]})$.

          \item Return $\aggcred \leftarrow
            (\tau,\{\atv{j}\}_{j\in[1,n]},\signature)$.

        \end{enumerate}

    \end{description}

  \end{protocolbox}

  \begin{protocolbox} {Aggregate anonymous credentials protocol continued}
    {fig:paac-2}

    \begin{description}

      \item[$\proof \sample \AACpresent(\crs,\aggcred,\msg)$ :] On input
        $\aggcred$ and message $\msg$ from the verifier, do:

        \begin{enumerate}

          \item Parse $\aggcred = (\tau,\{\atv{j}\}_j,\signature)$, and
            retrieve the user's stored $(\sk,\pk,\psi)$.

          \item Randomise $\signature' \sample \ATSrandomise(\tau,\signature)$
            and $\psi' \sample \SPSrandomise(\psi)$.

          \item Sample $\delta \sample \Zp^*$ and compute the $\delta$-blinded
            values $\bar{\gen}, \bar{V}, \bar{T}, \bar{\signaturetwo},
            \bar{\Gamma}, \pk', \{H_i\}_{i\in\mathbb{I}}$.

          \item Compute $\eta$ on input $\msg$, following the $\eta$
            computation of~\Fref{sec:agg-creds-eta}.

          \item Return $\proof \leftarrow \phi$ as defined
            in~\eqref{eq:proof-phi}.

        \end{enumerate}

      \item[$\{0,1\} \leftarrow \AACverify(\crs,\msg,\proof)$ :] On input
        $(\msg,\proof)$ from a verifier, do:

        \begin{enumerate}

          \item Parse $\proof = \phi$.

          \item If $\bar{\gen} = 1$, return $0$.

          \item Else if $\eta$ is not a valid proof for
            relation~\eqref{eq:proof-rel}, return $0$.

          \item Else if any of the three pairing equations of \emph{Proving
            knowledge} does not hold, return $0$.

          \item Else return $1$.

        \end{enumerate}

    \end{description}

  \end{protocolbox}

  The AGHO signature scheme is existentially unforgeable under chosen message
  attacks under the $q$-Strong Diffie-Hellman ($q$-SDH) assumption~\cite{}.

  The protocol instantiation is described in full in~Fref{fig:paac}. The
  protocol instantiation works as follows:

  \begin{description}

    \item[$(\crs,\state) \sample \AACgen(\secparam)$ :] The registration
      authority sets up an AGHO key pair, which it will later use to certify
      each user's public key and tag. We use a structure-preserving scheme here
      because then the messages and resulting signature both live in the same
      group as everything else in the protocol. This means that when a user
      later wants to prove they hold a valid registration signature, they can
      do so with a sigma protocol over discrete logarithms, rather than a
      general purpose zero knowledge proof, which would be considerably more
      expensive.

      Each issuer sets up a key pair for the tag based aggregate signature
      scheme of~\Fref{sec:tag-scheme}, so credentials issued by different
      issuers under the same tag can later be compressed into one single short
      credential.

    \item[$(\sk,\regcred) \sample \AACregister(\crs,\state)$ :] The user
      generates a key pair and then proves knowledge of the secret key to the
      registration authority.  The proof is used to prevent users' from
      presenting others' public keys and pooling credentials across users. If
      the proof is verified, the registration authority assigns the user a
      fresh tag and signs the user's public key and the hash of the tag.

    \item[$\cred \sample \AACissue(\crs,\isk{},\regcred,\att{})$ :] To request
      a credential, the user first shows the issuer their registration
      signature and proves knowledge of the secret key corresponding to the
      signed public key. If both checks pass, and the issuer is satisfied that
      the user is entitled to the credential, the issuer signs the tag and
      attribute value.

    \item[$\aggcred \leftarrow \AACaggregate(\crs,\cred_1,\ldots,\cred_n)$ :]
      The user simply aggregates all of the individual signatures they hold
      under the same tag into a single aggregate signature. This step is
      entirely local.

    \item[$\proof \sample \AACpresent(\crs,\aggcred,\msg)$ :] To present a set
      of attributes, the user first rerandomises their aggregate signature and
      registration signature, so that the values are unlinkable even if the
      same underlying credential has been presented many times.  The user
      computes the proof as shown in~\eqref{eq:proof-phi}.

    \item[$\{0,1\} \leftarrow \AACverify(\crs,\msg,\proof)$ :] Verification of
      the credential presentation corresponds to verification of the zero
      knowledge proofs presented.

  \end{description}

  The registration authority assigns each user a scalar identifier $\tid \in
  \Zp$ and certifies the group element $\Tag = \hashtwo(\tid)$ rather than
  $\tid$ itself.  Two things motivate this. The AGHO scheme signs vectors of
  group elements, so a scalar cannot be signed directly. More importantly,
  $\Tag$ is the value shared between the two verification equations checked at
  presentation: it appears both in the AGHO equation certifying the user's
  registration and in the aggregate verification equation certifying their
  credentials. It is $\Tag$, not $\tid$, that binds the user registration to
  the credentials issuance, and $\Tag$ that is blinded and used during
  presentation.  Hashing to get $\Tag$ rather than sampling it from $\group{1}$
  directly is required by the security arguments: $\hashtwo$ is programmed to
  embed challenges, and in extraction, $\tid$ is recovered from $\Tag$ using
  the map of the random oracle.  $\tid$ exists so that the registration
  authority can enforce uniqueness without expensive operations.  All other
  computations in the protocol use $\Tag$.

  \subsubsection*{Proving knowledge.} The user proves that they possess a valid
  registration signature, an aggregate credential under a single tag, and the
  secret key corresponding to the registered public key corresponding to the
  given tag, without revealing either the tag or the public key.

  Let $\crs =(\gen, \ggen) \ ; \ \inst = (\pk, \{\atv{i}, \ipk{i}\}_{i \in
  \mathbb{I}})$ with $\pk = (\widehat{U}_1, \widehat{U}_2, V)$ and $\ipk{i} =
  {\gen^x}_i$.  Let $\witness = (\sk, \pk, \Gamma = \hashtwo(\Tag), \signature,
  \SPSsig)$ with $\signature = (\signatureone, \signaturetwo)$ and $\SPSsig =
  (\widehat{R}, \widehat{S}, T)$.

  To present set of attribute values $\{\atv{i}\}_{i \in\mathbb{I}}$ after
  receiving $\msg$ from the verifier, the user aggregates the corresponding
  tag-based signatures and produces a proof for $\msg$ with respect to relation
  $\rel$ defined as $\rel( \inst, \witness) = 1$, if and only if, the following
  equalities hold: \begin{equation} \label{eq:proof-original} \begin{aligned}
    e(V, \widehat{R}) = e(\gen, \widehat{S}) & \quad ;  \quad e(T, \widehat{R})
    \cdot e(\gen^{\sk}, \widehat{U}_1)\cdot e(\Gamma,  \widehat{U}_2) = e(\gen,
  \ggen) \ ; \\ \quad \pk = \gen^{\sk} & \quad ;  \quad e(\signaturetwo, \ggen)
= e(\Gamma, \signatureone)\cdot\prod_{i\in\mathbb{I}}e(\hashone(\atv{i}),
{\gen^x}_{i}).  \end{aligned} \end{equation} Since we assume that the
registration authority only issues signatures on well-formed messages, pairs
$(\pk, \hashtwo(\Tag))$ for $\Tag \in \Zp$, we do not require the user to prove
knowledge of the pre image such that $\Gamma = \hashtwo(\Tag)$. This results in
a more efficient proof.

To reduce the computational cost incurred by this proof, we randomise the
signatures and equations in a way that removes the need for producing zero
knowledge proofs over pairing equations in $\group{T}$, and relies on zero
knowledge proofs of knowledge and equality of discrete logarithms of group
elements in $\group{1}$.

The user first randomises signatures $\signature' \leftarrow
\ATSrandomise(\signature)$ and $\SPSsig' \leftarrow \SPSrandomise(\SPSsig)$.
Let $\signature' = (\signatureone', \signaturetwo')$ and $\SPSsig' =
(\widehat{R}', \widehat{S}', T')$.  The user then samples a random $\delta \in
\Zp^*$ and computes the following:
%
\begin{gather*}
%
  \forall i \in \mathbb{I}: \quad H_i = \hashone(\atv{i})^{\delta} \quad ;
  \quad \bar{\gen} = \gen^{\delta} \quad ;  \quad \bar{T} = {T'}^{\delta} \quad
  ;  \quad \bar{\signaturetwo} = {\signaturetwo'}^{\delta} \ ; \\
%
  \bar{\Gamma} = \Gamma^{\delta} \quad ; \quad \bar{V} = V^{\delta} \quad ;
  \quad \pk' = \pk^{\delta}.
%
\end{gather*}

Let $\crs = \gen \ ; \ \inst = (\pk', \{\atv{i}, H_i\}_{i\in \mathbb{I}},
\bar{\gen}) \ ; \ \witness = (\delta, \sk)$, and let $\rel$ be the relation
defined as $\rel(\inst, \witness) = 1$, if and only if,  the following holds:
%
\begin{equation} \label{eq:proof-rel}
%
  \bar{\gen} = \gen^{\delta} \quad ; \quad \bar{V} = V^{\delta} \quad ;  \quad
  H_i = \hashone(\atv{i})^{\delta} \quad ; \quad \pk' = \bar{\gen}^{\sk}.
%
\end{equation}
 %
Next, the user produces $\eta$, a proof for $\rel$, and defines presentation
$\proof$ as:
%
\begin{equation} \label{eq:proof-phi}
%
  \phi = (\eta, \bar{\gen}, \bar{V}, \widehat{R}', \widehat{S}', \bar{T},
  \signatureone', \bar{\signaturetwo}, \bar{\Gamma}, \pk', \{\atv{i},
  H_i\}_{i\in \mathbb{I}}).
%
\end{equation}
 %
The verifier accepts $\proof$ if and only if, $\bar{\gen} \neq 1$, $\eta$ is a
valid proof for the relation depicted in equation~\ref{eq:proof-rel}, and the
following equalities hold:
%
\begin{gather*}
 %
  e(\bar{\signaturetwo}, \ggen)  = \prod_{i\in \mathbb{I}}e(H_{i},
  {\gen^x}_{i})\cdot e(\bar{\Gamma}, \signatureone') \ ; \ \\
  %
  e(\bar{\gen}, \ggen) = e(\bar{T}, \widehat{R}')\cdot e(\pk',
  \widehat{U}_1)\cdot e(\bar{\Gamma}, \widehat{U}_2) \ ; \\
  %
  e(\bar{V}, \widehat{R}')= e(\bar{\gen}, \widehat{S}').
%
\end{gather*}
%

Next we describe how $\eta$ is computed.  This is followed by showing that if
the user is able to produce a valid $\eta$, then we can extract a valid witness
for the relation defined in~\fref{eq:proof-original}.  We prove that under the
DDH assumption in $\group{1}$, $\proof$ is simulatable, it does not leak any
information whatsoever about the witness.

\paragraph{$\eta$ Computation.}\label{sec:agg-creds-eta} We first describe the
interactive zero-knowledge proof  underlying the computation of $\eta$, and
then show how to apply the Fiat-Shamir heuristics to the proof to finally
obtain $\eta$.

User the user proves knowledge of a valid witness $\witness = (\delta, \sk)$
for the relation depicted in equation~\ref{eq:proof-rel}, by executing the
following:

\begin{itemize}

  \item Select two random numbers $\alpha$ and $\beta$ in $\Zp$;

  \item Compute and send the following tuple to the verifier:
  %
    \begin{equation*}
  %
      (A, B, \{C_i\}_{i \in \mathbb{I}}, D) = (\gen^{\alpha}, V^{\alpha},
      \{\hashone(\atv{i})^{\alpha}\}_{i \in \mathbb{I}}, \bar{\gen}^{\beta});
    %
    \end{equation*}
    %

  \item On receiving challenge $c$ from the verifier, compute and send $\pi_1 =
    \alpha + c\cdot\delta$ and $\pi_2 = \beta + c\cdot\sk$.

\end{itemize}

The verifier accepts $\pi_1$ and $\pi_2$ if the following equalities hold;
$\gen^{\pi_1} = A\cdot\bar{\gen}^c \ ; \ V^{\pi_1} = B\cdot\bar{V}^c \ ; \
\hashone(\atv{i})^{\pi_1} = C_i\cdot H_i^c \ ; \ \bar{\gen}^{\pi_2} =
D\cdot\pk'^c$.

To produce $\eta$ on input of a message $\msg$, we apply the Fiat-Shamir
heuristics to generate the challenge $c$.  Let $\hash: \{0,1\}^* \rightarrow
\Zp$ be a cryptographic hash function. the user computes $\eta$ by first
computing tuple $(A, B, \{C_i\}_{i \in \mathbb{I}}, D)$, followed by $c =
\hash(A, B, \{C_i\}_{i \in \mathbb{I}}, D, \msg)$, and outputting $\eta = (A,
B, \{C_i\}_{i \in \mathbb{I}}, D, \pi_1, \pi_2)$.

\subsubsection*{Extensions.} The construction supports also several
straightforward extensions.

New issuers can join the system without impacting the construction.  In fact,
the aggregation of credentials and their presentation is agnostic to the number
of issuers.

The current construction assumes that each issuer produces a credential for a
single attribute type.  The current construction captures settings where
issuers generate credentials for multiple attribute types by having each issuer
hold different public key for each attribute type.  Alternatively, if it is
desirable to have the issuer hold a single public key regardless of the number
of attribute types it is responsible for, then we modify the way the issuer
signs. Instead of signing pair $(\Tag, \atv{})$, the issuer signs $(\Tag,
\att{} \| \atv{})$, with $\att{}$ the attribute type and $\atv{}$ the attribute
value.

The construction can be extended to support epoch-based revocation, in the
following way.  Instead of signing pair $(\pk, \hashtwo(\Tag))$, registration
authority the registration authority signs triple $(\pk, \hashtwo(\Tag),
\gen^{\epoch})$, where $\epoch$ identifies the current epoch.  Issuers, on
their end, sign pair $(\Tag, \epoch \| \att{} \| \atv{})$, instead of pair
$(\Tag, \att{} \| \atv{})$; this ties the attribute credential to epoch
$\epoch$.  During credential presentation, users prove that they hold a valid
signature from the registration authority and valid aggregate tag-based
signatures from the relevant issuers, for the current epoch.

We leave the study of accumulator-based revocation and the revocation of
individual attribute credentials to future work.
