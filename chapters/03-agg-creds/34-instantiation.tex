\paragraph{Our Tag-Based Aggregate Signature ($\ATS$)} \label{sec:tag-scheme}

Our tag-based aggregate signature scheme is an enhanced aggregate BLS signature
scheme~\cite{boneh2001short,boneh2003aggregate} that signs pairs of messages
and tags.  The key differences are tag-restricted aggregation and ability to
randomise signatures.  Our scheme is comprised of the following algorithms:

\begin{itemize}

  \item $(\sk, \pk) \leftarrow \ATSkeygen(\secparam)$: Randomly select $x \in
    \Zp$, compute $\gen^x = \pk \in \group{2}$, and output key pair $(\sk, \pk)
    = (x, \gen^x)$.

  \item $\signature \leftarrow \ATSsign(\sk, \Tag, \msg)$: On input secret key
    $\sk$ and pair of tag and message $(\Tag, \msg)\in
    \{0,1\}^*\times\{0,1\}^*$, randomly select $s \in \Zp$, and output
    signature $\signature = (\signatureone,\signaturetwo) \in
    \group{2}\times\group{1}$ constructed as follows: $$\signature = ....$$

  \item $\signature' \leftarrow \ATSrandomise(\Tag, \signature) $: On input tag
    $\Tag$, signature $\signature = (\signatureone, \signaturetwo)$, randomly
    select $s' \in \Zp$ and output randomised signature formed as follows: $$
    \signature' = (\signatureone', \signaturetwo') = ( \signatureone \cdot
    \ggen^{s'}, \signaturetwo \cdot \hashtwo(\Tag)^{s'}).$$

  \item $ \{0,1\} \leftarrow \ATSverify(\pk, \Tag, \msg, \signature) $: On
    input public key $\pk$, tag $\Tag \in \{0,1\}^*$, message $\msg \in
    \{0,1\}^*$, and signature $\signature = (\signatureone, \signaturetwo)$,
    output $1$ if the following equation is satisfied: ... Otherwise, output
    $0$.

  \item $\signature \leftarrow \ATSaggregate(\{ \signature_i \}_{i \in [1,
    n]})$: On input signatures $\signature_i = ({\signatureone}_i,
    {\signaturetwo}_i)$, output $$\signature = (\signatureone, \signaturetwo) =
    (\prod_{i=1}^n {\signatureone}_i, \ \prod_{i=1}^n {\signaturetwo}_i).$$

  \item $\{0,1\} \leftarrow \ATSverifyagg(\{\pk_i\}_{i\in [1, n]},
    \Tag,\{\msg_i\}_{i\in [1, n]},\signature) $: On input public keys
    $\{\pk_i\}_{i\in [1, n]}$, tag $\Tag$, messages $\{\msg_i\}_{i\in [1, n]}$,
    and aggregate signature $\signature$, parse $ \signature = (\signatureone,
    \signaturetwo)$ and output $1$ if the following holds: $$e(\signaturetwo,
    \ggen) = e (\hashtwo(\Tag), \signatureone) \cdot \prod_{i=1}^n
    e(\hashone(\msg_i), \pk_i). $$ Otherwise, output $0$.

\end{itemize}

This signature is existentially unforgeable under tag-based aggregation in the
random oracle model under the Bilinear Computational Diffie-Hellman (BCDH)
assumption and a modified variant of the same assumption. To the best of our
knowledge, the modified BCDH assumption has not been explicitly introduced in
prior work. However, it fits within the Uber assumption framework and can be
shown to hold in the generic bilinear group model~\cite{BonehBG05,Boyen08}.

\paragraph{Overview.} In this instantiation, each user has a pair of secret and
public keys $(\sk, \pk = \gen^\sk)$.  The digital signature $\DS$ uses AGHO
structure preserving signatures \cite{abe2011optimal}, to sign a pair $(\pk,
\hashtwo(\Tag)) \in \group{1}\times\group{1}$, where $\pk$ is the user's public
key and $\Tag$ their unique tag.  The aggregate tag-based signature $\ATS$ is
instantiated with our construction.

\paragraph{AGHO Structure-Preserving Signature Scheme}

The AGHO scheme supports signing vectors of elements in $\group{1}$,
$\group{2}$, or both.  In the following, we only describe signing elements of
$\group{1}$.

\begin{itemize}

  \item $ (\sk, \pk) \leftarrow \SPSgen(\secparam, \ell) $: On input a security
    parameter $\secparam$ and vector length $l$, sample $(u_1, \dots, u_\ell,
    v) \sample \Zp^{\ell+1}$ uniformly at random.  Set the secret key $\sk =
    (u_1, \dots, u_l, v)$ and the public key $\pk = (\widehat{U}_1, \dots,
    \widehat{U}_\ell, V)$ with $\widehat{U}_i = \ggen^{u_i} \in \group{2}$ and
    $V = \gen^v \in \group{1}$.  Finally, output $(\sk, \pk)$.

  \item $\SPSsig \leftarrow \SPSsign(\sk, \vec{M})$: On input the secret key
    $\sk = (u_1, \dots, u_\ell, v)$ and a message vector $\vec{M} = (M_1,
    \dots, M_l) \in \group{1}^\ell$, sample $r \sample \Zp$ uniformly at random
    and compute the signature as follows: \begin{equation*} \signature =
      (\widehat{R}, \widehat{S}, T) = (\ggen^r, \widehat{R}^v, (\gen \cdot
    \prod_{i=1}^\ell M_i^{-u_i})^{1/r}).  \end{equation*}

  \item $\SPSsig' \leftarrow \SPSrandomise(\SPSsig)$: On input signature
    $\SPSsig = (\widehat{R}, \widehat{S}, T)$, randomly pick $r' \leftarrow
    \Zp$ and output randomised signature formed as follows: \begin{equation*}
      \SPSsig' = (\widehat{R}', \widehat{S}', T') = ( \widehat{R}^{r'},
    \widehat{S}^{r'}, T^{\frac{1}{r'}}).  \end{equation*}

  \item $ \{0,1\} \leftarrow \SPSverify(\pk, \vec{M}, \SPSsig)$: On input a
    public key $\pk$, a message vector $\vec{M} = (M_1, \dots, M_\ell) \in
    \group{1}^\ell$, and a signature $\SPSsig = (\widehat{R}, \widehat{S}, T)$,
    output $1$ if both of the following pairing equations hold:
    \begin{equation*} e(V, \widehat{R}) = e(\gen, \widehat{S}) \quad \text{and}
    \quad e(T, \widehat{R}) \cdot \prod_{i=1}^\ell e(M_i, \widehat{U}_i) =
  e(\gen, \ggen).  \end{equation*} Otherwise output $0$.

\end{itemize}

AGHO is existentially unforgeable under chosen-message attacks  under the
$q$-Strong Diffie-Hellman ($q$-SDH) assumption.

Now we show how registration authority the registration authority uses AGHO
signatures to implement digital signature $\DS$.

\begin{itemize}

  \item $(\sk, \pk) \leftarrow \DSgen(\secparam)$: It calls
    $\SPSgen(\secparam, 2)$ to produce a key pair for signing two elements.

  \item $\signature \leftarrow \DSsign(\sk, \msg)$: It first parse $\msg$ as
    $\pk \| \Tag$,  computes $\Gamma = \hashtwo(\Tag)$, and outputs signature:
    \begin{equation*} \SPSsig \leftarrow \SPSsign(\sk, (\pk, \Gamma)).
    \end{equation*}

  \item $\{0,1\} \leftarrow \DSverify(\pk, \msg, \SPSsig)$: It first parses
    $\msg$ as $\pk \| \Tag$, computes $\Gamma = \hashtwo(\Tag)$, and returns
    bit $b$ defined as: \begin{equation*} b \leftarrow \SPSverify(\pk, (\pk,
    \Gamma), \SPSsig).  \end{equation*}

\end{itemize}

\paragraph{Signatures of Knowledge}

The user proves that they possess (i) a valid registration signature, (ii) an
aggregate credential under a single tag, and (iii) the secret key corresponding
to the registered public key corresponding to the given tag, without revealing
either the tag or the public key.

Let $\crs =(\gen, \ggen) \ ; \ \inst = (\pk, \{\atv{i}, \ipk{i}\}_{i \in
\mathbb{I}})$ with $\pk = (\widehat{U}_1, \widehat{U}_2, V)$ and $\ipk{i} =
{\gen^x}_i$.  Let $\witness = (\sk, \pk, \Gamma = \hashtwo(\Tag), \signature,
\SPSsig)$ with $\signature = (\signatureone, \signaturetwo)$ and $\SPSsig =
(\widehat{R}, \widehat{S}, T)$.

To present set of attribute values $\{\atv{i}\}_{i \in\mathbb{I}}$ after
receiving $\msg$ from the verifier, the user aggregates the corresponding
tag-based signatures and produces a SoK for $\msg$ with respect to relation
$\rel$ defined as $\rel( \inst, \witness) = 1$, if and only if, the following
equalities hold: \begin{equation} \label{eq:sok-original} \begin{aligned} e(V,
  \widehat{R}) = e(\gen, \widehat{S}) & \quad ;  \quad e(T, \widehat{R}) \cdot
  e(\gen^{\sk}, \widehat{U}_1)\cdot e(\Gamma,  \widehat{U}_2) = e(\gen, \ggen)
\ ; \\ \quad \pk = \gen^{\sk} & \quad ;  \quad e(\signaturetwo, \ggen) =
e(\Gamma, \signatureone)\cdot\prod_{i\in\mathbb{I}}e(\hashone(\atv{i}),
{\gen^x}_{i}).  \end{aligned} \end{equation} Since we assume that the
registration authority only issues signatures on well-formed messages, pairs
$(\pk, \hashtwo(\Tag))$ for $\Tag \in \Zp$, we do not require the user to prove
knowledge of the pre image such that $\Gamma = \hashtwo(\Tag)$. This results in
a more efficient SoK.

To reduce the computational cost incurred by this SoK, we randomise the
signatures and equations in a way that removes the need for producing zero
knowledge proofs over pairing equations in $\group{T}$, and relies on zero
knowledge proofs of knowledge and equality of discrete logarithms of group
elements in $\group{1}$.

The user first randomises signatures $\signature' \leftarrow
\ATSrandomise(\signature)$ and $\SPSsig' \leftarrow \SPSrandomise(\SPSsig)$.
Let $\signature' = (\signatureone', \signaturetwo')$ and $\SPSsig' =
(\widehat{R}', \widehat{S}', T')$.  The user then samples a random $\delta \in
\Zp^*$ and computes the following: \begin{gather*} \forall i \in \mathbb{I}:
  \quad H_i = \hashone(\atv{i})^{\delta} \quad ; \quad \bar{\gen} =
  \gen^{\delta} \quad ;  \quad \bar{T} = {T'}^{\delta} \quad ;  \quad
\bar{\signaturetwo} = {\signaturetwo'}^{\delta} \ ; \\ \bar{\Gamma} =
\Gamma^{\delta} \quad ; \quad \bar{V} = V^{\delta} \quad ;  \quad \pk' =
\pk^{\delta}.  \end{gather*}

Let $\crs = \gen \ ; \ \inst = (\pk', \{\atv{i}, H_i\}_{i\in \mathbb{I}},
\bar{\gen}) \ ; \ \witness = (\delta, \sk)$, and let $\rel$ be the relation
defined as $\rel(\inst, \witness) = 1$, if and only if,  the following holds:
\begin{equation} \label{eq:sok-rel} \bar{\gen} = \gen^{\delta} \quad ; \quad
\bar{V} = V^{\delta} \quad ;  \quad  H_i = \hashone(\atv{i})^{\delta} \quad ;
\quad \pk' = \bar{\gen}^{\sk}.  \end{equation} Next, the user produces $\eta$,
a SoK for $\rel$, and defines presentation $\proof$ as $$\phi = (\eta,
\bar{\gen}, \bar{V}, \widehat{R}', \widehat{S}', \bar{T}, \allowbreak
\signatureone', \bar{\signaturetwo}, \bar{\Gamma}, \pk', \{\atv{i}, H_i\}_{i\in
\mathbb{I}}).$$ The verifier accepts $\proof$ if and only if, $\bar{\gen} \neq
1$, $\eta$ is a valid SoK for the relation depicted in
equation~\ref{eq:sok-rel}, and the following equalities hold: \begin{gather*}
  e(\bar{\signaturetwo}, \ggen)  = \prod_{i\in \mathbb{I}}e(H_{i},
  {\gen^x}_{i})\cdot e(\bar{\Gamma}, \signatureone') \ ; \ \\ e(\bar{\gen},
\ggen) = e(\bar{T}, \widehat{R}')\cdot e(\pk', \widehat{U}_1)\cdot
e(\bar{\Gamma}, \widehat{U}_2) \ ; \\ e(\bar{V}, \widehat{R}')= e(\bar{\gen},
\widehat{S}').  \end{gather*}

\paragraph{Extensions} The construction supports also several straightforward
extensions.

New issuers can join the system without impacting the construction.  In fact,
the aggregation of credentials and their presentation is agnostic to the number
of issuers.

The current construction assumes that each issuer produces a credential for a
single attribute type.  The current construction captures settings where
issuers generate credentials for multiple attribute types by having each issuer
hold different public key for each attribute type.  Alternatively, if it is
desirable to have the issuer hold a single public key regardless of the number
of attribute types it is responsible for, then we modify the way the issuer
signs. Instead of signing pair $(\Tag, \atv{})$, the issuer signs $(\Tag,
\att{} \| \atv{})$, with $\att{}$ the attribute type and $\atv{}$ the attribute
value.

The construction can be extended to support epoch-based revocation, in the
following way.  Instead of signing pair $(\pk, \hashtwo(\Tag))$, registration
authority the registration authority signs triple $(\pk, \hashtwo(\Tag),
\gen^{\epoch})$, where $\epoch$ identifies the current epoch.  Issuers, on
their end, sign pair $(\Tag, \epoch \| \att{} \| \atv{})$, instead of pair
$(\Tag, \att{} \| \atv{})$; this ties the attribute credential to epoch
$\epoch$.  During credential presentation, users prove that they hold a valid
signature from the registration authority and valid aggregate tag-based
signatures from the relevant issuers, for the current epoch.

We leave the study of accumulator-based revocation and the revocation of
individual attribute credentials to future work.

\section{Instantiation of the SoK} The user is equipped with a key pair $(\sk,
\pk) = (\sk, \gen^{\sk})$ , an AGHO signature  $\SPSsig = (\widehat{R},
\widehat{S}, T)$ on pair $(\pk, \Gamma = \hashtwo(\Tag))$ from the registration
authority, and a tag-based aggregate signature $\signature = (\signatureone,
\signaturetwo)$ on attributes $\{\atv{i}\}_{i \in \mathbb{I}}$ that verifies
against the public keys of issuers with $i \in \mathbb{I}$.  Upon receiving
$\msg$ from a verifier, the user presents their attribute values
$\{\atv{i}\}_{i \in \mathbb{I}}$ by executing the following steps.

The user randomises signatures $\signature' \leftarrow
\ATSrandomise(\signature)$ and $\SPSsig' \leftarrow \SPSrandomise(\SPSsig)$.
We parse $\signature'$ as  $(\signatureone', \signaturetwo')$ and $\SPSsig'$ as
$(\widehat{R}', \widehat{S}', T')$.  Next, the user samples $\delta \in \Zp^*$
and computes the following: \begin{align*} \forall i \in \mathbb{I}: \ H_i =
  \hashone(\atv{i})^{\delta} & \ ; \quad \bar{\gen} = \gen^{\delta};  \quad
  \bar{T} = {T'}^{\delta}; \quad \bar{\signaturetwo} =
{\signaturetwo'}^{\delta}; \quad \bar{\Gamma}= \Gamma^{\delta}; \\ & \quad
\bar{V} = V^{\delta} ; \quad \pk' = \pk^{\delta}.  \end{align*} Let $\crs =
\gen \ ; \ \inst = (\pk', \{\atv{i}, H_i\}_{i\in \mathbb{I}}, \bar{\gen}) \ ; \
\witness = (\delta, \sk)$, and let $\rel$ be the relation defined as
$\rel(\inst, \witness) = 1$, if and only if,  the following holds:
\begin{equation} \label{eq:app-sok-rel} \bar{\gen} = \gen^{\delta} \  ; \
\bar{V} = V^{\delta} \ ; \ H_i = \hashone(\atv{i})^{\delta}\  ; \ \pk' =
\bar{\gen}^{\sk} \end{equation} the user now computes $\eta$,  a SoK for
$\rel$, and outputs presentation $$\proof = (\eta, \bar{\gen}, \bar{V},
\widehat{R}', \widehat{S}', \bar{T}, \signatureone', \bar{\signaturetwo},
\bar{\Gamma}, \pk', \{\atv{i}, H_i\}_{i\in \mathbb{I}}).$$

The verifier accepts $\proof$ if $\bar{\gen} \neq 1$, $\eta$ is a valid SoK for
the relation depicted in equation~\ref{eq:sok-rel} and the following equalities
hold: \begin{align} \label{eq:app-sok-rel-2} e(\bar{\gen}, \ggen) &= e(\bar{T},
  \widehat{R}')\cdot e(\pk', \widehat{U}_1)\cdot e(\bar{\Gamma}, \widehat{U}_2)
\ ; \ e(\bar{V}, \widehat{R}') = e(\bar{\gen}, \widehat{S}') \ ; \ \\ &
e(\bar{\signaturetwo}, \ggen) = \prod_{i\in \mathbb{I}}e(H_{i},
{\gen^x}_{i})\cdot e(\bar{\Gamma}, \signatureone').  \end{align}

Next, we describe first how $\eta$ is computed.  This is followed by showing
that if the user is able to produce a valid $\eta$, then we can extract a valid
witness for the relation defined in Equation \ref{eq:sok-original}.  Finally,
we prove that under the DDH assumption in $\group{1}$, $\proof$ is simulatable,
i.e., it does not leak any information whatsoever about the witness.

\paragraph{$\eta$ Computation.} We first describe the interactive
zero-knowledge proof  underlying the computation of $\eta$, and then show how
to apply the Fiat-Shamir heuristics to the proof to finally obtain $\eta$.

User the user proves knowledge of a valid witness $\witness = (\delta, \sk)$
for the relation depicted in equation~\ref{eq:app-sok-rel}, by executing the
following:

\begin{itemize}

  \item Select two random numbers $\alpha$ and $\beta$ in $\Zp$;

  \item Compute and send tuple $(A, B, \{C_i\}_{i \in \mathbb{I}}, D) =
    (\gen^{\alpha}, V^{\alpha}, \{\hashone(\atv{i})^{\alpha}\}_{i \in
    \mathbb{I}}, \bar{\gen}^{\beta})$ to the verifier;

  \item On receiving challenge $c$ from the verifier, compute and send $\pi_1 =
    \alpha + c\cdot\delta$ and $\pi_2 = \beta + c\cdot\sk$.

\end{itemize}

The verifier accepts $\pi_1$ and $\pi_2$ if the following equalities hold;
$\gen^{\pi_1} = A\cdot\bar{\gen}^c \ ; \ V^{\pi_1} = B\cdot\bar{V}^c \ ; \
\hashone(\atv{i})^{\pi_1} = C_i\cdot H_i^c \ ; \ \bar{\gen}^{\pi_2} =
D\cdot\pk'^c$.

To produce $\eta$ on input of a message $\msg$, we apply the Fiat-Shamir
heuristics to generate the challenge $c$.  Let $\hash: \{0,1\}^* \rightarrow
\Zp$ be a cryptographic hash function. the user computes $\eta$ by first
computing tuple $(A, B, \{C_i\}_{i \in \mathbb{I}}, D)$, followed by $c =
\hash(A, B, \{C_i\}_{i \in \mathbb{I}}, D, \msg)$, and outputting $\eta = (A,
B, \{C_i\}_{i \in \mathbb{I}}, D, \pi_1, \pi_2)$.

\paragraph{Extractability.} Recall that $\proof = (\eta, \bar{\gen}, \bar{V},
\widehat{R}', \widehat{S}', \bar{T}, \signatureone', \bar{\signaturetwo},
\bar{\Gamma}, \pk', \{\atv{i}, H_i\}_{i\in \mathbb{I}})$.

Note that given the extractability property of signatures of knowledge, if a
user is able to produce a valid signature $\eta$ for relation $\rel$, then it
is possible to extract the corresponding witness $(\delta, \sk)$ that verifies
$\bar{\gen} = \gen^{\delta} \  ; \ \bar{V} = V^{\delta} \ ; \ H_i =
\hashone(\atv{i})^{\delta}\  ; \ \pk' = \bar{\gen}^{\sk}$.  Now given that
$\bar{\gen} \neq 1$, then $\delta \neq 0$ and we can write $\gen =
\bar{\gen}^{1/\delta}$, $V = \bar{V}^{1/\delta}$ and $\pk'^{1/\delta} =
\bar{\gen}^{\sk/\delta} = \gen^{\sk}$.  Furthermore, given the equalities in
equation~\ref{eq:app-sok-rel-2}, we can deduce that: \begin{gather*}
  e(\bar{V}^{1/\delta}, \widehat{R}) = e(V, \widehat{R}) =
  e(\bar{\gen}^{1/\delta}, \widehat{S}) = e(\gen, \widehat{S}) \ ; \\
  e(\bar{T}^{1/\delta}, \widehat{R}) \cdot e( \pk'^{1/\delta}, \widehat{U}_1)
  \cdot e(\bar{\Gamma}^{1/\delta},  \widehat{U}_2) = e(\bar{\gen}^{1/\delta},
  \ggen)= e(\gen, \ggen) \ ; \\ e(\bar{\signaturetwo}^{1/\delta}, \ggen) =
e(\bar{\Gamma}^{1/\delta},
\signatureone)\cdot\prod_{i\in\mathbb{I}}e(H_i^{1/\delta}, {\gen^x}_i).
\end{gather*} That is, $(\signatureone, \bar{\signaturetwo}^{1/\delta})$ is a
valid tag-based aggregate signature on the pre-image of
$\bar{\Gamma}^{1/\delta}$ and attributes $\atv{i}$, and that $(\widehat{R},
\widehat{S}, \bar{T}^{1/\delta})$ is a valid AGHO signature on pair
$\pk'^{1/\delta}, \bar{\Gamma}^{1/\delta}$.

To extract the pre image of $\bar{\Gamma}^{1/\delta}$, we use the following:

\begin{enumerate}

  \item Random oracle $\hashtwo$, which is initialised with two maps $L_1$ and
    $L_2$, and which for each query $\Tag$, checks if $L_1[\Tag]$ is empty. If
    so, it  selects a random group element $\Gamma \in \group{1}$, and sets
    $L_1[\Tag] \leftarrow \Gamma$ and $L_2[\Gamma] \leftarrow \Tag$.  Finally,
    returns $L_1[\Tag]$.

  \item The fact that the registration authority only signs well-formed pairs
    defined as $(\pk, \hashtwo(\Tag))$.

\end{enumerate}

Notice that if $(\widehat{R}, \widehat{S}, \bar{T}^{1/\delta})$ is a valid AGHO
signature on pair $(\pk'^{1/\delta}, \bar{\Gamma}^{1/\delta})$, then under the
existential unforgeability of AGHO signatures, this signature corresponDS to
either a signature or a randomisation of a signature computed by the
registration authority on the same pair.  Since the registration authority is
trusted to sign only well-formed pairs, then this entails that
$\bar{\Gamma}^{1/\delta}$ was computed by calling $\hashtwo$ on some input
$\Tag \in \{0,1\}^*$, and that $\Tag$ corresponDS to
$L_2[\bar{\Gamma}^{1/\delta}]$.

Hence the extractability property of signatures of knowledge guarantees that if
user the user is able to produce a valid SoK $\eta$, then we can extract a
valid witness  $(\delta, \sk)$, and that $(\signatureone,
\bar{\signaturetwo}^{1/\delta})$ is a valid tag-based aggregate signature on
the pre-image of $\bar{\Gamma}^{1/\delta}$ and attributes $\atv{i}$, and that
$(\widehat{R}, \widehat{S}, \bar{T}^{1/\delta})$ is a valid AGHO signature on
pair $\pk'^{1/\delta}, \bar{\Gamma}^{1/\delta}$.

\paragraph{Simulatability}

We now show that if DDH holds in $\group{1}$, we can simulate a valid
presentation $\proof$ without access to a valid witness.

\begin{itemize}

  \item Randomly select $\alpha, \beta, \gamma, \delta, \nu, \{\eta_i\}_{i\in
    \mathbb{I}},  \theta \in \Zp^*$;

  \item Compute $\bar{\gen} = \gen^{\alpha}$, $\bar{V} = \gen^{\beta}$,
    $\bar{T} = \gen^{\gamma}$, $\bar{\signaturetwo} = \gen^{\delta}$,
    $\bar{\Gamma} = \gen^{\nu}$, $H_i = \gen^{\eta_i}$, and $\pk' =
    \gen^{\theta}$ (note that if the DDH assumption holds in $\group{1}$, then
    it is computationally infeasible to tell whether tuple $(\bar{\gen},
    \bar{V}, \bar{T}, \bar{\signaturetwo}, \bar{\Gamma})$ was generated
    following the description in Section~\ref{sec:sok-inst} or as random group
    elements);

  \item Compute $\widehat{R}' =
    (\ggen^{\alpha}\widehat{U}_1^{-\theta}\widehat{U}_2^{-\nu})^{1/\gamma}$,
    $\widehat{S}' = \widehat{R}'^{\beta/\alpha}$, and $\signatureone' =
    (\ggen\prod_{i \in \mathbb{I}}\ipk{i}^{-\eta_i})^{\delta/\nu}$ (by
    construction, tuple $(\bar{\gen}, \bar{V}, \widehat{R}', \widehat{S}',
    \bar{T}, \signatureone', \bar{\signaturetwo}, \bar{\Gamma}, \pk',
    \{\atv{i}, H_i\}_{i\in \mathbb{I}})$ verifies equations
    \ref{eq:app-sok-rel-2});

  \item Pick $\pi_1$, $\pi_2$ and $c$ randomly in $\Zp$;

  \item Compute $A = \gen^{\pi_1}\cdot\bar{\gen}^{-c} \ ; \ B =
    V^{\pi_1}\cdot\bar{V}^{-c} \ ; \ C_i = \hashone(\atv{i})^{\pi_1}\cdot
    H_i^{-c} \ ; \ D = \bar{\gen}^{\pi_2}\cdot\pk'^{-c}$;

  \item Using random oracle $\hash$, define the hash $\hash(A, B, \{C_i\}_{i
    \in \mathbb{I}}, D, \msg)$ as value $c$;

  \item Finally, set $\eta$ to tuple $(A, B, \{C_i\}_{i \in \mathbb{I}}, D,
    \pi_1, \pi_2)$.

\end{itemize}
