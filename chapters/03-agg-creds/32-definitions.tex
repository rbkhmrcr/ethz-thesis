\section{Definitions}

\subsection{Aggregate anonymous credentials}

An aggregate anonymous credentials scheme involves four types of participants.
The registration authority is responsible for registering users. Issuers
certifies attributes. For simplicity we assume that each issuer is responsible
for a single attribute type, and is the only issuer for that attribute. Users
each register with the registration authority, obtain credentials from the
relevant i issuers for the attribute values they hold, and then use these
credentials to make presentations. A presentation is a user provably disclosing
the values of a subset of their attributes. Verifiers check users' claims.

We assume the registration authority is honest but curious. It follows the
protocol, but may collude with other participants to try to identify users or
correlate credential presentations. Issuers, users, and verifiers may be
arbitrarily malicious, and may collude to try to undermine the privacy of
honest users, to cause honest verifiers to accept invalid presentations, or to
forge credentials.  We consider static corruption throughout: the adversary
fixes the set of corrupt participants before any protocol interaction takes
place.

\begin{description}

  \item[$(\crs,\state) \sample \AACgen(\secparam)$ :] The setup algorithm, on
    input security parameter $\secparam$, generates the system public
    parameters $\crs$ together with the initial state $\state$.

  \item[$(\sk,\regcred) \sample \AACregister(\crs,\state)$ :] The registration
    algorithm, on input public parameters $\crs$ and state $\state$, outputs
    user secret key $\sk$ and registration credential $\regcred$.

  \item[$\cred \sample \AACissue(\crs,\isk{},\regcred,\att{})$ :] The issuance
    algorithm, on input public parameters $\crs$, issuer secret key $\isk{}$,
    registration credential $\regcred$, and attribute $\att{}$, outputs
    attribute credential $\cred$.

  \item[$\aggcred \leftarrow \AACaggregate(\crs,\cred,\ldots,\cred)$ :] The
    aggregation algorithm, on input public parameters $\crs$ and credentials
    $\cred,\ldots,\cred$, outputs aggregate credential $\aggcred$.

  \item[$\proof \sample \AACpresent(\crs,\aggcred,\msg)$ :] The presentation
    algorithm, on input public parameters $\crs$, aggregate credential
    $\aggcred$, and message $\msg$, outputs presentation $\proof$.

  \item[$\{0,1\} \leftarrow \AACverify(\crs,\msg,\proof)$ :] The verification
    algorithm, on input public parameters $\crs$, message $\msg$, and
    presentation proof $\proof$, returns 0 or 1.

\end{description}

We define security of aggregate anonymous credentials through an ideal
functionality that represents a trusted third party which executes the
operations of the credential system on behalf of system participants in a way
that perfectly meets the system requirements.

The ideal functionality captures the properties of aggregate anonymous
credentials: unforgeability, unlinkability, and aggregatability.
Unforgeability is enforced by ensuring that only validly issued attributes can
be successfully presented or verified. Unlinkability is achieved as randomness
is returned in each query to present, which prevents presentations from being
correlated.

\subsection{Aggregate tag based signatures}

We define an aggregate tag based signature scheme as one that allows signatures
computed over the same tag to be aggregated into a compact signature. An
aggregate tag-based signature scheme is defined by the following algorithms:

\begin{description}

  \item[$(\sk, \pk) \sample \ATSgen(\secparam)$ :] The generation algorithm, on
    input security parameter $\secparam$, outputs key pair $(\sk,\pk)$.

  \item[$\signature \sample \ATSsign(\sk, \Tag, \msg)$ :] The signing
    algorithm, on input secret key $\sk$, tag $\Tag \in \{0,1\}^*$, and message
    $\msg \in \{0,1\}^*$, outputs signature $\signature$.

  \item[$ \signature' \sample \ATSrandomise(\Tag, \signature)$ :] The
    randomisation algorithm, on input tag $\Tag$ and signature $\signature$,
    outputs randomised signature $\signature'$.

  \item[$ \{0,1\} \leftarrow \ATSverify(\pk, \Tag, \msg, \signature)$ :] The
    verification algorithm, on input public key $\pk$, tag $\Tag$, message
    $\msg$, and signature $\signature$, returns 0 or 1.

  \item[$\signature \leftarrow \ATSaggregate(\signature_1, \ldots,
    \signature_n)$ :] The aggregation algorithm, for general $n$, on input
    signatures $\signature_1,\ldots,\signature_n$, all under the same tag
    $\Tag$, outputs aggregate signature $\signature$.

  \item[$\{0,1\} \leftarrow \ATSverifyagg((\pk_i)_{i\in [1 , n]}, \Tag,
    (\msg_i)_{i\in [1 , n]}, \signature)$ :] The aggregate verification
    algorithm, on input public keys $(\pk_i)_{i\in [1 , n]}$, tag $\Tag$,
    messages $(\msg_i)_{i\in [1 , n]}$, and aggregate signature $\signature$,
    returns 0 or 1.

\end{description}

An aggregate tag based signature scheme should satisfy correctness and
existentially unforgeability, as defined below.

\paragraph{Correctness.} We say that an ATS scheme satisfies correctness if for
all security parameters $\secparam$, all $n \geq 1$, all tags $\Tag \in
\{0,1\}^*$, and all messages $\msg_i \in \{0,1\}^*$, the following holds.

The scheme satisfies the usual correctness definition for digital signatures.
That is, for every key pair $(\pk,\sk)$ generated by $\ATSgen(\secparam)$ and
every tag and message $\Tag, \msg$, the following holds:
%
\begin{equation*}
%
  \ATSverify(\pk, \Tag, \msg, \ATSsign(\sk, \Tag, \msg)) = 1.
%
\end{equation*}
%

We additionally have correctness of aggregated signatures.  For set $\ISSUERS
\subseteq [1, n]$, for $i \in \ISSUERS$, an aggregate signature is generated as
follows:
%
\begin{gather*}
%
  (\sk_i, \pk_i) \gets \ATSgen(\secparam) \ ; \  \signature_i \gets
  \ATSsign(\sk_i, \Tag, \msg_i) ; \\ \signature \gets
  \ATSaggregate((\signature_i)_{i \in \ISSUERS}).
    %
\end{gather*}
%
Then aggregate correctness holds if we have the following:
  %
\begin{gather*}
%
  \text{If } \ \forall i \in \ISSUERS \ : \ \ATSverify(\pk_i, \Tag, \msg_i,
  \signature_i) = 1 \\ \text{then } \ \ATSverifyagg((\pk_i)_{i \in \ISSUERS},
  \Tag, (\msg_i)_{i \in \ISSUERS}, \signature) = 1.
    %
\end{gather*}
%
Randomisation also preserves validity, meaning that the following holds:
  %
\begin{gather*}
%
  \text{If } \ \ATSverify(\pk, \Tag, \msg, \signature) = 1, \\ \text{then }
  \forall \ \signature' \ : \  \signature' \leftarrow \ATSrandomise(\Tag,
  \signature), \\ \ATSverify(\pk, \Tag, \msg, \signature') = 1.
    %
\end{gather*}
%

\paragraph{Existential unforgeability under tag based aggregation.} We say an
ATS scheme is existentially unforgeable under tag based aggregation if for any
probabilistic polynomial time adversary $\adv$, with access to corruption
oracle $\corrupto$ and signing oracle $\signo$, the probability that $\adv$
wins the experiment depicted in~\Fref{fig:exp-ats-euf} is negligible in security
parameter $\secparam$.

\begin{experimentbox}{Existential unforgeability under tag based
  aggregation}{fig:exp-ats-euf}

  \begin{minipage}[t]{0.36\linewidth}

    \underline{$\corrupto(\pk_i)$}

    If $\pk_i \in \pk$, then:

    \begin{itemize}

      \item $\Cor \gets \Cor \cup \{\pk_i\}$;

      \item return $\sk_i$.

    \end{itemize}

  \end{minipage}
  \hfill
  \begin{minipage}[t]{0.60\linewidth}

    \underline{$\signo(\pk_i, \Tag, \msg)$}

    If $\pk_i \in \pk$, then:

    \begin{itemize}

      \item $\Query \gets \Query \cup \{(\pk_i, \Tag, \msg)\}$;

      \item return $\signature \gets \ATSsign(\sk_i, \Tag, \msg)$.

    \end{itemize}

  \end{minipage}

  \medbreak

  \underline{Experiment}

  \begin{itemize}

    \item $(\ISSUERS \subseteq [1, n], (\pk_i)_{i \in \ISSUERS}, \Tag,
      (\msg_i)_{i \in \ISSUERS}, \signature) \gets
      \adv^{\signo,\corrupto}(\pk)$;

    \item $b \gets \ATSverifyagg\bigl((\pk_i)_{i \in \ISSUERS}, \Tag,
      (\msg_i)_{i \in \ISSUERS}, \signature\bigr)$.

  \end{itemize}

  $\adv$ wins the experiment if $b = 1$ and $\exists \ i \in \ISSUERS : \pk_i
  \notin \Cor \wedge (\pk_i, \Tag, \msg_i) \notin \Query$.

\end{experimentbox}
