\section{Security}\label{sec:agg-creds-security}

%%%% proof 1 - the generic construction is secure (Theorem 1)

\subsection{Proof of \Cref{thm:agg-creds-construction-security}}\label{sec:agg-creds-proof-1}

In the following, we show that the view of a real-world adversary $\adv$ during
an execution of the construction $\Pi$ is indistinguishable from the view of an ideal-world
simulator $\simu$ that interacts with system participants through ideal
functionality $\idfu{\AAC}$.  We define a sequence of indistinguishable games
that start with Game 0 representing the real world, and end with Game 8
representing the ideal world.

The games use the three hypotheses of \Cref{thm:agg-creds-construction-security},
which we label as follows so that the games can refer to them.

\begin{enumerate}

  \item[(P1)] The digital signature scheme $\DS$ used by the registration
authority is existentially unforgeable (EUF-CMA): no PPT adversary can produce a
valid signature $\psi$ on a pair $(\pk, \Tag)$ that the registration authority
never signed.

  \item[(P2)] The tag-based aggregate signature scheme $\ATS$ is existentially
unforgeable under tag-based aggregation, as shown in~\Cref{thm:agg-creds-thm-1}.

  \item[(P3)] The non-interactive zero-knowledge proof system used to compute
$\algoproof$ is simulation extractable: a valid witness can be extracted from
any accepted proof, and simulated proofs are indistinguishable from real ones.

\end{enumerate}

\begin{proof}

  \paragraph{Game 0.} This is the execution of protocol $\Pi$.

  \paragraph{Game 1.} As Game 0, except $\simu$ executes protocol $\Pi$ on
behalf of the honest parties: $\simu$ is provided with the inputs (including
secrets) of the honest parties, and interacts with corrupt parties, through the
adversary, in the real world, following $\Pi$'s specifications, and returns the
corresponding output. This change is purely syntactic, so Game 1 is
indistinguishable from Game 0 by construction.

  \paragraph{Game 2.} As Game 1, except we introduce dummy functionality
$\idfu{\AAC}'$ that forwards the inputs from the honest parties to $\simu$ and
returns the outputs. This modification is syntactic, so Game 2 is
indistinguishable from Game 1.

  \paragraph{Game 3.} As Game 2, except $\idfu{\AAC}'$ handles register calls
from honest users following the description of ideal functionality
$\idfu{\AAC}$. $\simu$ first assigns each honest user a key pair $(\sk, \pk)$.
Now, when an honest user $\user$ calls $\idfu{\AAC}'$ to register, $\simu$
learns the user's identity. Given this information, $\simu$ retrieves the
corresponding key pair $(\sk,\pk)$ and contacts the registration authority to
register $\user$. $\simu$ receives a unique tag $\Tag$ and a signature $\psi
\leftarrow \DSsign(\rask, (\pk, \Tag))$ and stores entry $\langle \user, \Tag,
\pk, \psi\rangle $.

  Since the registration authority and $\idfu{\AAC}'$ both register each user
exactly once and reject duplicates, they accept or reject the same requests, so
this game is indistinguishable from Game 2.

  \paragraph{Game 4.} As Game 3, except $\idfu{\AAC}'$ also handles credential
issuance calls from honest users following the description of ideal
functionality $\idfu{\AAC}$.  When  $\idfu{\AAC}'$ receives issuance request
$(\AACissue, \att{i}, \atv{i})$ from honest user $\user$, $\simu$ learns the
triple $(\user, \att{i}, \atv{i})$.  To simulate the corresponding credential
issuance for $\user$ in the real world, $\simu$ retrieves $(\sk, \pk)$ and
$(\Tag, \psi)$.  If the pair $(\Tag, \psi)$ for $\user$ does not exist, meaning
$\user$ did not call register before, then $\simu$ aborts. Otherwise, it
honestly executes $\Pi$ with issuer $\issuer{i}$.  There are two cases to
consider.

  \begin{description}

    \item[$\issuer{i}$ is honest.] If this is the first time $\simu$ simulates
$\user$ for $\issuer{i}$, then as per $\Pi$'s specification,  $\simu$ will
receive signature $\signature_i \leftarrow \ATSsign(\isk{i}, \Tag, \atv{i})$,
and record entry $\langle \user, \Tag, \atv{i}, \signature_i \rangle$.
Otherwise, $\issuer{i}$ will reject the credential issuance request.

    \item[$\issuer{i}$ is corrupt.] If the execution of $\Pi$ terminates with
$\simu$ receiving a signature $\signature_i$ with $\ATSverify(\ipk{i}, \Tag,$
$\atv{i}, \signature_i) = 1$, then $\simu$ records entry $\langle \user, \Tag, \atv{i},
\signature_i \rangle$, and sends accept.

  \end{description}

  In both cases, $\idfu{\AAC}'$ follows $\simu$: an honest issuer accepts every
request from a registered user, matching the first branch, and for a dishonest
issuer, $\idfu{\AAC}'$ accepts only when $\simu$ does, when the issuer produced
a genuinely valid aggregate signature.  So $\idfu{\AAC}'$'s output matches
$\Pi$'s in both cases, and this game is indistinguishable from Game 3 as long as
$\simu$ does not abort.  Since $\user$ is honest, they always register
before requesting credentials, so the abort event never occurs.

  \paragraph{Game 5.} As Game 4, except $\idfu{\AAC}'$ executes aggregate
requests from honest users following the description of $\idfu{\AAC}$. Since
credential aggregation is a local operation where adversary $\adv$ observes
nothing, $\simu$ need not do anything, so Game 5 is indistinguishable from Game
4.

  \paragraph{Game 6.} As Game 5, except $\idfu{\AAC}'$ takes charge of presentation
requests from honest users, following the specifications of $\idfu{\AAC}$.
Given the message $(\AACpresentend, \vec{\atv{}}, \msg,$ $\algoproof)$ from
$\idfu{\AAC}'$ for $\vec{\atv{}} = (\atv{1}, \ldots, \atv{n})$, $\simu$ defines
the statement $\inst_1 = (\pk,$ $(\ipk{i}, \atv{i})_{i \in \ISSUERS})$ such that $\forall i \in
\ISSUERS: \atv{i} \neq \varnothing$, and, using its ability to program the
random oracle as the simulation trapdoor $\td$, outputs $\algoproof^\star
\leftarrow \NIZKsimprove(\crs, \td, \inst_1, \msg)$, which gives
$\NIZKverify(\crs, \inst_1, \algoproof^\star, \msg) = 1$. By (P3), this
simulated proof is indistinguishable from a real one, so Game 6 is
indistinguishable from Game 5.

  \paragraph{Game 7.} As Game 6, except $\idfu{\AAC}'$ processes verification
requests from honest verifiers following the description of $\idfu{\AAC}$, and
$\simu$ simulates the honest verifiers in the real world.  On receiving a
presentation in the real world, $\simu$ translates the presentation into calls to
$\idfu{\AAC}'$, and instead of returning the output of $\NIZKverify$, it returns
the verification result received from $\idfu{\AAC}'$.  In the following, we
describe $\simu$'s simulation.

  \begin{description}

    \item[Register.] For each registration request $\pk$ that a corrupt user
sends, in the real world, to the honest registration authority, $\simu$ (acting
as the registration authority) first checks if the user knows the secret key
$\sk$ underlying $\pk$.  If not, then $\simu$ stops.  Otherwise, it executes the
rest of the registration protocol, records entry $\langle\user, \Tag, \pk, \psi
\rangle$, and then (acting as a user) transmits the corresponding registration
request $register$ to $\idfu{\AAC}'$ which processes it in a similar fashion to
$\idfu{\AAC}$.

      The simulated registration authority and $\idfu{\AAC}'$ accept or reject
the same requests by construction, so their outputs are indistinguishable.

    \item[Issue.] For each issuance request $(\Tag, \pk, \psi, \atv{i})$ that a
corrupt user $\user$ sends, in the real world, to an honest issuer $\issuer{i}$
(simulated by $\simu$), $\simu$ (acting as $\user$) sends $(\AACissue, \att{i},
\atv{i})$ to $\idfu{\AAC}'$, and stores entry $\langle \user, \Tag, \att{i},
\atv{i}, \signature_i\rangle$ on success.  $\idfu{\AAC}'$ issues the credential
exactly when $\user$ is registered and this is their first request for
$\att{i}$,
and the simulated $\issuer{i}$ returns $\signature_i \leftarrow
\ATSsign(\isk{i}, \Tag, \atv{i})$ under the same conditions, so their outputs
are indistinguishable.

    \item[Verify.] For each presentation $(\vec{\atv{}}, \msg, \algoproof)$, with $\vec{\atv{}} =$
$(\atv{1}, \ldots, \atv{n})$, that a user $\user$ presents, in the real world, to an honest
verifier $V$, $\simu$ (simulating $V$) calls $b \leftarrow \NIZKverify(\crs,
\inst_1, \algoproof, \msg)$.  We recall that $\atv{i} = \varnothing$ if the
attribute value is not disclosed.

      If $b  = 0$,  $\simu$ sends $(\msg, \vec{\atv{}} = (\atv{1}, ...,
\atv{n}), \algoproof)$ to $\idfu{\AAC}'$, which returns $(\AACverifyend,
b^\star)$.  Two scenarios present themselves. Either there exists a dishonest
user with attribute values $\vec{\atv'{}} = (\atv'{1}, ..., \atv'{n})$, $\forall
\atv{i} \neq \varnothing$, we either have $\atv{i} = \atv'{i}$, or have $\atv{i}
\neq \atv'{i}$ but issuer $\issuer{i}$ is dishonest.  Or $\forall i: \atv{i} \neq
\varnothing$, issuers $\issuer{i}$ and users holding attribute values $\atv{i}$
are honest.

      In case of scenario one, the output of $\idfu{\AAC}'$ is defined by
$\simu$, which instructs $\idfu{\AAC}'$ to return $\AACverifyend$ with $0$.  In case
of scenario two, $\idfu{\AAC}'$ returns $\AACverifyend$ with $1$.  However, thanks
to the correctness of protocol $\Pi$ this scenario never occurs.  Given a proof
that was computed honestly,  $\NIZKverify$ will never output $0$, so the output
of $\idfu{\AAC}'$ matches that of $\Pi$.

      If $b = 1$, then by (P3), $\simu$ can extract the witness $\witness_1 =
(\Tag, \sk, \pk, \psi, \signature)$. They then execute the following steps:

      \begin{description}

	\item[No key entry.] If there is no recorded entry $\langle \star, \Tag,
\pk, \star\rangle$, where $\star$ matches any value, then $\simu$ aborts, and we call this event $a_1$.

	\item[No attribute entry.] Otherwise, if there exists $1 \leq i \leq n$
such that $\atv{i} \neq \varnothing$ and $\issuer{i}$ is honest, and there is no
recorded entry $\langle \star, \Tag, \atv{i}, \star \rangle$, then $\simu$
aborts, and we call this event $a_2$.

	\item[Otherwise.] $\simu$ sends to $\idfu{\AAC}'$ the presentation request
$(\AACpresent, \vec{\atv{}}, \signature, \msg)$.

	  Either $\idfu{\AAC}'$ aborts, and $\simu$ sends request $(\AACverify,$ $V,\vec{\atv{}}, \algoproof)$ to $\idfu{\AAC}'$, or $\idfu{\AAC}'$ returns
$(\AACpresentend,$ $\algoproof^\star)$, and $\simu$ sends request $(\AACverify,$ $V,$
$\vec{\atv{}}, \algoproof^\star)$ to $\idfu{\AAC}'$.

      \end{description}

      $\simu$ receives $(\AACverifyend, b)$ and outputs $b$.

  \end{description}

  In what follows, we show that if $\simu$ does not abort, then $b = 1$.

  If $a_1$ does not occur, then the registration request for $\user$ was
successfully processed by $\simu$, and $\user$ was successfully registered by
$\idfu{\AAC}$.  If $a_2$ does not occur then this implies one of two things:

  \begin{description}

    \item[Case one :] $\forall i : \atv{i} \neq \varnothing$, there exists an
entry $\langle \star, \Tag, \atv{i}, \star \rangle$.

    \item[Case two :]  $\exists j: \atv{j} \neq \varnothing$ such that there is
no recorded entry $\langle \star, \Tag, \atv{j}, \star \rangle$ but issuer
$\issuer{j}$ is dishonest.

  \end{description}

  Case one implies that $\simu$ issued credentials for $\user$ for the relevant
attributes, and so did $\idfu{\AAC}'$.  During the $\AACpresent$ call,
$\idfu{\AAC}'$ will not abort and will return $(\AACpresentend,
\algoproof^\star)$, and the subsequent call $(\AACverify, V, \vec{\atv{}},
\algoproof^\star)$ will result in $\idfu{\AAC}'$ returning $(\AACverifyend, 1)$.
This matches the output of the verification in the real world.

  Case two implies that $\user$ is in possession of a credential that was issued
by a dishonest issuer and never recorded by either $\simu$ or $\idfu{\AAC}'$.
In this case,  $\idfu{\AAC}'$ aborts during $\AACpresent$, and when $\simu$
calls $\idfu{\AAC}'$ with  $(\AACverify, V, \vec{\atv{}}, \algoproof)$, the
output of $\idfu{\AAC}'$ is dictated by $\simu$.  $\simu$ sets this output to
$1$ to match the output of the verification in the real world.

  This game is indistinguishable from Game 6 as long as $a_1$ and $a_2$ do not
occur. We now show that the probability of these events occurring is negligible.

  \begin{description}

    \item[$a_1$.] Occurs if there is no recorded entry $\langle \star, \Tag,
\pk, \star \rangle$ in the system.  By (P3), we can extract witness $\witness_1
= (\Tag, \sk, \pk, \psi, \signature)$.  This means that $\user$ has knowledge of
a valid $\psi$ such that $1 \leftarrow \DSverify(\rapk, (\pk, \Tag), \psi)$ with
no corresponding entry, contradicting (P1).

    \item[$a_2$.] Occurs if $\exists j \in [1, n]$ such that $\atv{j} \neq
\varnothing$ and $\issuer{j}$ is honest, and there is no recorded entry $\langle
\star, \Tag, \atv{j}, \star \rangle$.  By (P3), we can again extract a valid
witness $\witness_1 = (\Tag, \sk, \pk, \psi, \signature)$.  This means that
$\signature$ satisfies the following:
    %
      \begin{equation*}
    %
	\ATSverifyagg((\ipk{i})_{i\in \ISSUERS},\Tag,(\atv{i})_{i\in\ISSUERS},
\signature).
    %
      \end{equation*}
    %
      $\ISSUERS$ here identifies the indices with $\atv{i} \neq \varnothing$ and
$j \in \ISSUERS$.  Given that there is no recorded entry $\langle \star, \Tag,
\atv{j}, \star \rangle$, this implies that the honest issuer $\issuer{j}$ never
issued a signature $\signature_j$ for pair $(\Tag, \atv{j})$, contradicting
(P2).

  \end{description}

  \paragraph{Game 8.} This is the ideal world. As Game 7, except $\idfu{\AAC}'$
is now identical to ideal functionality $\idfu{\AAC}$, so Game 8 is
indistinguishable from Game 7. This concludes the proof
of~\Cref{thm:agg-creds-construction-security}.

\end{proof}

%%%% proof 2 - tag-based agg sigs are secure (Theorem 2)

\subsection{Proof of \Cref{thm:agg-creds-thm-1}}\label{sec:agg-creds-proof-2}

Let $\pk_1, \ldots, \pk_n$ be the challenge public keys of
Experiment~\ref{exp:ats-euf}, and suppose an adversary $\adv$ wins by outputting
an aggregate signature $\signature^* = (\signatureone^*, \signaturetwo^*)$ on
messages $(\msg_i^*)_{i \in \ISSUERS}$ under a tag $\Tag^*$, so that
%
\begin{equation*}
  \pairing(\signaturetwo^*,\ggen) = \pairing(\hashtwo(\Tag^*), \signatureone^*)\cdot
\prod_{i \in \ISSUERS} \pairing(\hashone(\msg_i^*), \pk_i).
\end{equation*}
%
Some $j \in \ISSUERS$ has an uncorrupted key $\pk_j$, and the signing oracle
never signed $(\pk_j, \Tag^*, \msg_j^*)$. The forgery is of Type 1 if $\adv$ never
asked for a signature on $\msg_j^*$ under $\pk_j$ with any tag, and of Type 2 if
it did, but only under tags other than $\Tag^*$.

\begin{proof}

  We build a reduction $\advB$ for each type. Both embed a challenge in one of
the two random oracles, answer signing queries under $\pk_j$ from the other, and
extract the challenge answer from the forgery. A Type 1 forgery uses a message
never signed under $\pk_j$, so its reduction embeds in $\hashone$ and breaks
BCDH. A Type 2 forgery reuses a signed message under a new tag, so its reduction
embeds in $\hashtwo$ and breaks m-BCDH. We first give what the two reductions
share, then what each does differently.

  \paragraph{Shared part.} Without loss of generality, $\adv$ corrupts every key
but one. $\advB$ guesses $j \sample [1,n]$ and sets $\pk_j = \widetilde{x}$, the
element $\ggen^\gamma$ of its challenge. For every $k \neq j$ it samples $\xi_k
\sample \Zp^*$ and sets $\sk_k = \xi_k$ and $\pk_k = \ggen^{\xi_k}$. It answers a
corruption of $\pk_k$ with $\xi_k$, and stops if $\adv$ corrupts $\pk_j$.

  $\advB$ keeps lists $L_1$ and $L_2$ for $\hashone$ and $\hashtwo$. On each new
query it samples a fresh exponent from $\Zp^*$, computes the output from it, and
stores the input, the exponent and the output. One of the two oracles has an
embedded branch: with probability $p$, its output is a challenge element raised
to the exponent, and otherwise, on the honest branch, it is $\gen$ raised to the
exponent. The other oracle always takes the honest branch. We write $\rho$ for the
exponent of a $\hashone$ query and $\eta$ for that of a $\hashtwo$ query.

  $\advB$ answers a signing query $(\pk_i, \Tag, \msg)$ with $i \neq j$ by running
$\ATSsign(\xi_i, \Tag, \msg)$. Queries with $i = j$ are answered as each
reduction describes below. On receiving the forgery, $\advB$ removes the
contributions of the corrupted keys,
%
\begin{equation*}
  d = \signaturetwo^* / \prod_{i \in \ISSUERS, i \neq j}\hashone(\msg^*_i)^{\xi_i},
\end{equation*}
%
so that the verification equation becomes
%
\begin{equation*}
  \pairing(d, \ggen) = \pairing(\hashtwo(\Tag^*), \signatureone^*) \cdot
\pairing(\hashone(\msg^*_j), \widetilde{x}).
\end{equation*}

  \paragraph{Type 1 forgeries.} $\advB$ receives a BCDH challenge $(\gen, x, y, z,
\ggen, \widetilde{x}, \widetilde{y}, \widetilde{z}) = (\gen, \gen^\gamma,
\gen^\omega, \gen^\chi, \ggen, \ggen^\gamma, \ggen^\omega, \ggen^\chi)$ and must
output $\pairing(\gen, \ggen)^{\gamma\omega\chi}$. The embedded branch is in
$\hashone$, with $\hashone(\msg) = y^\rho$, and $\hashtwo(\Tag) = \gen^\eta$ always.
For a signing query $(\pk_j, \Tag, \msg)$, $\advB$ stops if $\hashone(\msg)$ is
embedded. Otherwise $\hashone(\msg) = \gen^\rho$, so $\advB$ samples $\phi \sample
\Zp$ and returns
%
\begin{equation*}
  (\signatureone, \signaturetwo) = (\ggen^\phi, x^\rho\,\hashtwo(\Tag)^\phi),
\end{equation*}
%
which is $\ATSsign(\gamma, \Tag, \msg)$ with randomness $\phi$, since $x^\rho =
\hashone(\msg)^\gamma$. On the forgery, $\advB$ stops unless $\hashone(\msg^*_j) =
y^{\rho^*}$ is embedded. Then $\hashtwo(\Tag^*) = \gen^{\eta^*}$, and pairing both
sides of the verification equation above with $\widetilde{z}$ instead of $\ggen$
gives
%
\begin{equation*}
  X = \left(\pairing(d, \widetilde{z}) / \pairing(z^{\eta^*},
\signatureone^*)\right)^{1/\rho^*} = \pairing(y, \widetilde{x})^{\chi} =
\pairing(\gen, \ggen)^{\gamma\omega\chi}.
\end{equation*}

  \paragraph{Type 2 forgeries.} $\advB$ receives an m-BCDH challenge $(\gen, y,
\ggen, \widetilde{x}, \widetilde{y}) = (\gen, \gen^{1/\omega}, \ggen,
\ggen^\gamma, \ggen^\omega)$ and must output $\pairing(\gen,
\ggen)^{\gamma\omega}$. The embedded branch is now in $\hashtwo$, with
$\hashtwo(\Tag) = y^\eta$, and $\hashone(\msg) = \gen^\rho$ always. $\advB$ no longer
knows $\gen^\gamma$, so for a signing query $(\pk_j, \Tag, \msg)$ it stops if
$\hashtwo(\Tag)$ is embedded, and otherwise samples $\upsilon \sample \Zp$ and
solves the verification equation for the first component:
%
\begin{equation*}
  (\signatureone, \signaturetwo) = \left(\left(\ggen^\upsilon /
\widetilde{x}^\rho\right)^{1/\eta}, \ \gen^\upsilon\right).
\end{equation*}
%
Then $\pairing(\hashone(\msg), \widetilde{x}) \cdot \pairing(\hashtwo(\Tag),
\signatureone) = \pairing(\gen, \ggen)^{\rho\gamma + \upsilon - \rho\gamma} =
\pairing(\signaturetwo, \ggen)$, so the signature verifies, and it is distributed
as a real one since $\upsilon$ is uniform. On the forgery, $\advB$ stops unless
$\hashtwo(\Tag^*) = y^{\eta^*}$ is embedded. Then $\hashone(\msg^*_j) =
\gen^{\rho^*}$, and pairing with $\widetilde{y}$ instead of $\ggen$, using
$y^\omega = \gen$, gives
%
\begin{equation*}
  X = \left(\pairing(d, \widetilde{y}) / \pairing(\gen^{\eta^*},
\signatureone^*)\right)^{1/\rho^*} = \pairing(\gen, \widetilde{x})^{\omega} =
\pairing(\gen, \ggen)^{\gamma\omega}.
\end{equation*}

  \paragraph{Success probability.} In both reductions the simulation is perfect,
and $\advB$ extracts, when three independent events hold. The guess of $j$ is
right, with probability $1/n$. The oracle query behind the forgery, $\msg^*_j$ for
Type 1 and $\Tag^*$ for Type 2, takes the embedded branch, with probability $p$.
And each of the at most $q$ signing queries under $\pk_j$ takes the honest branch,
with probability $(1-p)^q$ together; a Type 1 forgery's message and a Type 2
forgery's tag are, by definition, never among them. Whenever one of these fails,
$\advB$ stops and outputs a random guess. So $\advB$ succeeds with probability at
least $\frac{1}{n} \cdot p(1-p)^q$ times that of $\adv$, and with $p = 1/(q+1)$
this is at least $1/(e\,n(q+1))$, a polynomial loss. A forgery of either type
therefore breaks BCDH or m-BCDH, and $\ATS$ is existentially unforgeable under
tag-based aggregation.

  \rebekah{Type 2 does not cover a forgery on $\Tag^*$ when $\adv$ also asked
for a signature under $\pk_j$ on $\Tag^*$ with another message: answering that
query needs $\hashtwo(\Tag^*)$ on the honest branch, while extraction needs it
on the embedded one, and neither embedding in $\hashone$ nor in $\hashtwo$ covers
both. The case needs its own reduction, or a direct proof in the GGM.}

\end{proof}

%%%% proof of Theorem 3 - the concrete instantiation, corollary of Theorem 1

\subsection{Proof of \Cref{lem:agg-creds-sigma}}\label{sec:agg-creds-proof-lemma}

\begin{proof}

    The presentation relation of the construction, with $\DS$ set to the
$\AGHO$ SPS scheme and $\ATS$ to our tag-based scheme, has instance, witness and
relation
%
    \begin{equation*}\begin{gathered}
%
      \inst_2 = (\rapk, \{\atv{i}, \ipk{i}\}_{i \in \ISSUERS}), \quad \witness_2
= (\sk, \pk, \tid, \signature, \SPSsig), \\
%
      \rel_2 = \{\ \pairing(v, \widetilde{r}) = \pairing(\gen, \widetilde{s}) \
\wedge\ \pairing(z, \widetilde{r}) \cdot \pairing(\gen^\sk,
\widetilde{u}_1)\cdot \pairing(\tid, \widetilde{u}_2) = \pairing(\gen, \ggen) \\
      \wedge\ \pk = \gen^\sk \ \wedge\ \pairing(\signaturetwo, \ggen) =
\pairing(\tid,
\signatureone)\cdot\prod_{i\in\ISSUERS}\pairing(\hashone(\atv{i}), \ipk{i})\ \},
%
    \end{gathered}\end{equation*}
%
with $\rapk = (\widetilde{u}_1, \widetilde{u}_2, v)$, $\ipk{i} = \ggen^{\isk{i}}$,
$\signature = (\signatureone, \signaturetwo)$ and $\SPSsig = (\widetilde{r},
\widetilde{s}, z)$. Recall that $\algoproof = (\eta, \inst_3)$, with $\inst_3 = (\bar{\gen},
\bar{v}, \pk', \{i, \atv{i}, H_i\}_{i\in\ISSUERS}, \widetilde{r}',
\widetilde{s}', \bar{z}, \signatureone', \bar{\signaturetwo}, \bar{\tid})$.

  We first show extractability. By special soundness of the Sigma protocol, which
Fiat-Shamir preserves in the random oracle model, if a user is able to produce
a valid proof $\eta$ for relation $\rel_3$, then it
is possible to extract the corresponding witness $\witness_3 = (\delta, \sk)$
satisfying the following:
%
  \begin{equation*}
%
    \bar{\gen} = \gen^\delta, \quad \bar{v} = v^\delta, \quad H_i =
\hashone(\atv{i})^\delta, \quad \pk' = \bar{\gen}^\sk.
%
  \end{equation*}
%
  Since $\bar{\gen} \neq 1$, we have $\delta \neq 0$, and can write $\gen =
\bar{\gen}^{1/\delta}$, $v = \bar{v}^{1/\delta}$, and $\pk'^{1/\delta} =
\bar{\gen}^{\sk/\delta} = \gen^\sk$.  A valid presentation satisfies the blinded
$\ATSverifyagg$ and $\SPSverify$ equations:
%
  \begin{gather*}
%
    \pairing(\bar{\signaturetwo}, \ggen) =
\prod_{i\in\ISSUERS}\pairing(H_i,\ipk{i}) \cdot
\pairing(\bar{\tid},\signatureone') \ \wedge \\ \pairing(\bar{\gen},\ggen) =
\pairing(\bar{z},\widetilde{r}')\cdot \pairing(\pk',\widetilde{u}_1) \cdot
\pairing(\bar{\tid},\widetilde{u}_2) \ \wedge \\
\pairing(\bar{v},\widetilde{r}') = \pairing(\bar{\gen},\widetilde{s}').
%
  \end{gather*}
%
  Substituting $\bar{\gen}^{1/\delta} = \gen$, $\bar{v}^{1/\delta} = v$, and
raising the first two equalities to the power $1/\delta$, we can deduce that:
%
  \begin{gather*}
%
    \pairing(\bar{v}^{1/\delta}, \widetilde{r}) = \pairing(v, \widetilde{r}) =
\pairing(\bar{\gen}^{1/\delta}, \widetilde{s}) = \pairing(\gen, \widetilde{s}) \
\wedge \\
  %
    \pairing(\bar{z}^{1/\delta}, \widetilde{r}) \cdot \pairing( \pk'^{1/\delta},
\widetilde{u}_1) \cdot \pairing(\bar{\tid}^{1/\delta}, \widetilde{u}_2) =
\pairing(\bar{\gen}^{1/\delta}, \ggen)= \pairing(\gen, \ggen) \ \wedge \\
  %
    \pairing(\bar{\signaturetwo}^{1/\delta}, \ggen) =
\pairing(\bar{\tid}^{1/\delta},
\signatureone)\cdot\prod_{i\in\ISSUERS}\pairing(H_i^{1/\delta}, \ipk{i}).
  %
  \end{gather*}
%
  So $(\signatureone, \bar{\signaturetwo}^{1/\delta})$ is a valid tag-based
aggregate signature on the preimage of $\bar{\tid}^{1/\delta}$ and attributes
$\atv{i}$, and that $(\widetilde{r}, \widetilde{s}, \bar{z}^{1/\delta})$ is a
valid signature on pair $\pk'^{1/\delta}, \bar{\tid}^{1/\delta}$.

  To extract the preimage of $\bar{\tid}^{1/\delta}$, we use the following:

  \begin{enumerate}

    \item Random oracle $\hashtwo$, which is initialised with two maps $L_1$ and
$L_2$, and which for each query $\Tag$, checks if $L_1[\Tag]$ is empty. If so,
it  selects a random group element $\tid \in \group{1}$, and sets $L_1[\Tag]
\leftarrow \tid$ and $L_2[\tid] \leftarrow \Tag$.  Finally, returns $L_1[\Tag]$.

    \item The fact that the registration authority only signs well-formed pairs
defined as $(\pk, \hashtwo(\Tag))$.

  \end{enumerate}

  Notice that if $(\widetilde{r}, \widetilde{s}, \bar{z}^{1/\delta})$ is a valid
signature on pair $(\pk'^{1/\delta}, \bar{\tid}^{1/\delta})$, then under the
existential unforgeability of the $\AGHO$ SPS scheme, this signature
corresponds to either a signature or a randomisation of a signature computed by
the registration authority on the same pair.  Since the registration authority
is trusted to sign only well-formed pairs, then this entails that
$\bar{\tid}^{1/\delta}$ was computed by calling $\hashtwo$ on some input $\Tag
\in \{0,1\}^*$, and that $\Tag$ corresponds to $L_2[\bar{\tid}^{1/\delta}]$.

  Putting the pieces together: extracting $(\delta, \sk)$ from $\eta$ gives us
$\Tag$ (so $\tid = \bar{\tid}^{1/\delta}$), $\sk$ (so $\pk = \gen^\sk$), the
  $\AGHO$ signature $\SPSsig = (\widetilde{r}, \widetilde{s}, \bar{z}^{1/\delta})$ on
$(\pk, \tid)$, and the tag-based aggregate signature $\signature =
(\signatureone, \bar{\signaturetwo}^{1/\delta})$ on $\tid$ and the attributes
$\atv{i}$: exactly a witness $\witness_2 = (\sk, \pk, \tid, \signature,
\SPSsig)$ for $\rel_2$.

  We now show simulatability: if DDH holds in $\group{1}$, we
can simulate a valid presentation $\algoproof$ without access to a valid
witness.

  \begin{enumerate}

    \item Randomly select $\alpha, \beta, \kappa, \delta, \nu, \{\eta_i\}_{i\in
\ISSUERS},  \iota \in \Zp^*$, and set the following:
%
      \begin{equation*}
%
	\bar{\gen} = \gen^\alpha, \quad \bar{v} = \gen^\beta, \quad \bar{z} =
\gen^\kappa, \quad \bar{\signaturetwo} = \gen^\delta, \quad \bar{\tid} =
\gen^\nu, \quad H_i = \gen^{\eta_i}, \quad \pk' = \gen^\iota.
%
      \end{equation*}
%
      If the DDH assumption holds in $\group{1}$, it is computationally
infeasible to distinguish between $(\bar{\gen}, \bar{v}, \bar{z},
\bar{\signaturetwo}, \bar{\tid})$ as above and those generated following the
protocol description.

    \item We define the randomised signature elements as follows:
%
      \begin{equation*}
%
	\widetilde{r}' =
(\ggen^\alpha\widetilde{u}_1^{-\iota}\widetilde{u}_2^{-\nu})^{1/\kappa}, \quad
\widetilde{s}' = \widetilde{r}'^{\beta/\alpha}, \quad \signatureone' =
(\ggen^{\delta}\textstyle\prod_{i \in \ISSUERS}\ipk{i}^{-\eta_i})^{1/\nu}.
%
      \end{equation*}
%
      Now we have by construction that $(\bar{\gen}, \bar{v}, \widetilde{r}',
\widetilde{s}', \bar{z}, \signatureone', \bar{\signaturetwo}, \bar{\tid}, \pk',
\{\atv{i}, H_i\}_{i\in \ISSUERS})$ satisfies the following:
    %
      \begin{gather*}
    %
	\pairing(\bar{\signaturetwo}, \ggen) =
\prod_{i\in\ISSUERS}\pairing(H_i,\ipk{i}) \cdot
\pairing(\bar{\tid},\signatureone'), \\
      %
	\pairing(\bar{\gen},\ggen) = \pairing(\bar{z},\widetilde{r}')\cdot
\pairing(\pk',\widetilde{u}_1) \cdot \pairing(\bar{\tid},\widetilde{u}_2), \\
      %
	\pairing(\bar{v},\widetilde{r}') = \pairing(\bar{\gen},\widetilde{s}').
    %
      \end{gather*}
    %

    \item Pick $\pi_1$, $\pi_2$ and $c$ randomly in $\Zp$, and set the
following:
%
      \begin{equation*}
%
	f = \gen^{\pi_1}\cdot\bar{\gen}^{-c}, \quad h =
v^{\pi_1}\cdot\bar{v}^{-c}, \quad k_i = \hashone(\atv{i})^{\pi_1}\cdot H_i^{-c},
\quad w = \bar{\gen}^{\pi_2}\cdot\pk'^{-c}.
%
      \end{equation*}

        \item Program random oracle $\hash$ so that $\hash(\gen, v, \inst_3, f, h,
\{k_i\}_{i \in \ISSUERS}, w, \msg) = c$, where $\inst_3$ is the simulated
statement above.

    \item Finally, set $\eta$ to tuple $(f, h, \{k_i\}_{i \in \ISSUERS}, w,
\pi_1, \pi_2)$.

  \end{enumerate}

  So under the DDH assumption in $\group{1}$, the simulated and honestly
generated presentations are computationally indistinguishable. This proves
\Cref{lem:agg-creds-sigma}.

\end{proof}

\subsection{Proof of \Cref{thm:agg-creds-thm-2}}\label{sec:agg-creds-proof-3}

The instantiation is an instance of the construction that sets $\DS$ to the
$\AGHO$ SPS scheme, $\ATS$ to our tag-based aggregate signature scheme, and the
proof system to the presentation proof of $\AACpresent$ and $\AACverify$.

\begin{proof}

  \begin{description}

        \item[$\DS$ is existentially unforgeable.] The $\AGHO$ SPS scheme is existentially
unforgeable under chosen message attack in the GGM~\cite{C:AGHO11}.

    \item[$\ATS$ is existentially unforgeable under tag-based aggregation.] This
is \Cref{thm:agg-creds-thm-1}, under the BCDH and m-BCDH assumptions. Both hold
in the GGM. A generic adversary obtains elements of $\group{T}$ only as
$\pairing(\gen, \ggen)^{f}$, where $f$ is a linear combination of products of
one exponent it holds in $\group{1}$ with one it holds in $\group{2}$. For BCDH
these exponents are $1, \gamma, \varepsilon, \chi$ in both groups, so every $f$
has degree at most two, and none equals $\gamma\varepsilon\chi$. For m-BCDH the
exponents are $1$ and $1/\varepsilon$ in $\group{1}$, and $1$, $\gamma$ and
$\varepsilon$ in $\group{2}$, so every $f$ is a combination of $1$, $\gamma$,
$\varepsilon$, $1/\varepsilon$ and $\gamma/\varepsilon$. Multiplying by
$\varepsilon$, the target $\gamma\varepsilon$ becomes $\gamma\varepsilon^2$,
which is not a combination of $\varepsilon$, $\gamma\varepsilon$,
$\varepsilon^2$, $1$ and $\gamma$. In both cases an adversary making $q$ group
operations succeeds only if two of the polynomials it computes collide, or one
hits the target, at a random point, which by the Schwartz-Zippel lemma happens
with probability $O(q^2/p)$.

    \item[The proof system is simulation extractable.] \Cref{lem:agg-creds-sigma},
under the DDH assumption in $\group{1}$, which holds in the GGM, gives special
soundness and honest-verifier zero knowledge of the Sigma protocol for $\rel_3$.
Its responses are unique, and so quasi-unique, since each response is fixed by
one verification equation, for example $\pi_1$ by $\gen^{\pi_1} = f \cdot
\bar{\gen}^c$. The challenge hashes the whole statement together with $\msg$, so
the Fiat-Shamir transform makes the presentation proof simulation extractable
with $\msg$ as its label in the random oracle model~\cite{INDOCRYPT:FKMV12}. The
simulator programs the random oracle to simulate honest users' presentations,
and rewinds the adversary to extract from its own, as the simulator
of the construction's proof requires.

  \end{description}

  The instantiated protocol therefore securely realises ideal functionality
$\idfu{\AAC}$ in the GGM and the random oracle model.

\end{proof}
