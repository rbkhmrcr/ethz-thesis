\section{Evaluation}\label{sec:agg-creds-evaluation}

\begin{outline}
  \item setup: $\AAC$ and $\ATS$ in Go, gnark-crypto v0.21.0, BLS12-381 (cite gnark-crypto); only bilinearity is used, so other pairing groups work too
  \item baseline: Idemix, built on BBS+, same library (cite CCS:CamVan02); Idemix issues one credential on all $n$ attributes from one issuer and presents it with $k$ disclosed
  \item machine: MacBook Air, Apple M2, 16GB RAM, all eight cores; median of 100 repetitions after ten warm-up calls
  \item spread: interquartile range typically 2\% of the median, never above 6\%, so medians only
\end{outline}

\begin{outline}
  \item \Cref{tab:agg-creds-times,tab:agg-creds-sizes}: every algorithm and object at $n = 128$, $k = 64$
  \item registration and issuance are cheap and depend on neither $n$ nor $k$
  \item communication of registration, in words: the user sends 128 bytes, the RA 352 bytes, three messages in total
  \item communication of issuance: the user sends 440 bytes, the issuer 224 bytes, four messages in total
\end{outline}

\begin{outline}
  \item \Cref{fig:agg-creds-idemix}: Idemix proves knowledge of a signature on all $n$ attributes, so its cost grows with attributes held; ours with attributes disclosed
  \item numbers at $n = 128$, $k = 1$: present 1.82ms vs 31.9ms for Idemix, verify 4.05ms vs 11.8ms
  \item Idemix verifies faster once more than about 20 attributes are disclosed, but it has one issuer for all attributes, the setting this chapter avoids
  \item close: costs are low enough for client devices
\end{outline}
